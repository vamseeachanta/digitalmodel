### Blocking defects

**1. The claimed source/input/CDB/log hash binding does not exist in code.** The only `hashlib` uses in the whole feature are `padeye_pressure.py:46` (`input_sha256` of the `.inp` into its own manifest) and `test_padeye_pressure_preparation.py:106-109`, which freezes `generate_padeye_apdl` — the **old equal-force deck**, not the new preparation deck. Repo-wide grep for `parse_pressure_cdb` / `assess_shape_output` / `verify_frozen_pressure_domain` outside the five padeye-pressure test files returns only the plan HTML. Nothing binds a CDB or a log to a source. This is a missing implementation, not a missing report.

**2. `generate_pressure_preparation` output bytes are unfrozen while `padeye_pressure_cdb.py:9-10` cites a replayed-source SHA256 (`f1b53a67…`).** No test can evaluate that claim. A one-byte change to the generator silently invalidates the cited replay with zero signal. Add the same LF/CRLF freeze the old deck already has, for all three levels.

**3. `verify_pressure_mesh` is never applied to production output.** `test_padeye_pressure_domain.py:12` correctly feeds `build_pressure_mesh(...)` into the domain gate, but the pressure gate is exercised only against `synthetic_ring`. The sole check on the generated pressure intent is `test_padeye_pressure_preparation.py:43-47`, which re-derives expected pressure from `mesh['pressure_slope_mpa_per_mm']` and integrates with the identical trapezoid rule that produced `alpha` — self-referential. A symmetric mis-assignment of `row['element']` in `_pressure_intent` would renormalize to `fy=50000`, `fx≈0` and pass. `verify_pressure_mesh(m, m['pressures'])` on all three levels is a one-line addition and is the only independent check of the generator's face binding.

**4. `read_pressures` accepts exactly 4 values but SFEBLOCK declares `6(pg20.9)`** (`padeye_pressure_cdb.py:126`, format asserted at line 206). `fields()` raises "Unexpected trailing fields" on any non-blank 5th/6th column. The synthetic fixture (`test_padeye_pressure_cdb.py:50`) emits only 4, so the real export's column count is never exercised. `extra_pressure_value` mutates VAL3, not VAL5/6. If the observed v261 export writes six populated fields, the parser refuses the genuine CDB. Resolve against the actual artifact or widen to 6 with zero-checks on 5/6.

**5. `assess_shape_output` requires `text.count('SHAPE TESTING SUMMARY') == 1`** (`padeye_pressure_quality.py:9`), but the deck issues both `CHECK` and `SHPP,SUMMARY` (`padeye_pressure.py:29`). If `CHECK` also emits a summary block, a clean native run is rejected. Fail-closed, so not a false pass — but it makes the gate unrunnable against the real log and is untested in that direction.

**Root issue behind 1/2/4/5:** every "native" parser here is tested only against fixtures authored to match the parser, and no CDB or log artifact is committed. The docstring SHA256s at `padeye_pressure_cdb.py:6-10` are prose. Until the binding in #1 lands, "native parser reads CDB actual stored loads" is a design intent, not a verified property.

### Minor

- `test_padeye_pressure_domain.py:23` (`left_in`, `x: 0→10`) passes for the wrong reason: `x=10` is already an `_axis_points` grid value, so `_nodes` raises "duplicate node coordinates" before any plate-boundary logic runs. Use a non-grid offset.
- `assess_shape_output` raises `AttributeError`/`TypeError` on non-`str` `text`, inconsistent with the `ValueError` refusal contract of the other three gates; no type guard on `text` (only on `expected_elements`).
- `prepare_pressure_study` (`padeye_pressure.py:42-53`) leaves earlier mesh-level directories on disk if a later level fails readback; the next invocation then hits `FileExistsError` with a partial bundle present. Consider writing to a temp root and renaming.
- `read_pressures` header field `header[4]` is only checked `> 0`; SFEBLOCK row truncation is detected solely via the caller-supplied `upper_edges`. Acceptable given the docstring's allocation-profile finding, but it means the block carries no self-describing completeness check — worth stating explicitly in the evidence record rather than leaving it to the docstring.
