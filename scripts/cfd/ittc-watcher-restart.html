1. Executive summary

Draft for maintainer review

The convergence watcher is a file-based stopping monitor. Analysis is performed to determine whether coefficient history is eligible for convergence assessment; key results are summarized below.

  • Restart protection
    • History modified at or before arming is withheld from assessment.
    • Empty current history produces a waiting result.
  • Operational decision
    • Convergence assessment requires a subsequent coefficient write.

2. System

The monitor reads coefficient history and creates a stop-trigger file after consecutive passing checks. The solver responds only when its abort function is configured.

Coefficient writer → versioned history → freshness gate → convergence criterion
                                                              ↓
                                                    consecutive passes → trigger

Figure: logical monitoring boundary. Physical geometry and mesh are outside this software check.

3. Basis

Eligibility is evaluated using a strict timestamp comparison. The opened history must have modification time m greater than arming time a; equality is rejected because a later write is not established.

Both timestamps use nanoseconds on the system clock. Existing convergence limits remain operator inputs; no engineering limit is established by this freshness check.

4. Inputs

Synthetic inputs are used to demonstrate the comparison. Arming time is 10 ns; candidate modification times are 9, 10 and 11 ns. These values are test inputs, not measured timestamps.

5. Method

The arming time is captured once before polling. Modification time is read from the opened file descriptor, and stale output is rejected before coefficient rows are parsed.

The latest selected history is assessed without falling back to an older complete history. Consecutive passes are reset when the selected path changes or a waiting result is returned.

6. Worked example

The comparison is repeated by subtracting a from m. Differences of −1 and 0 ns fail the strict positive condition; a difference of 1 ns permits row assessment.

For the fresh case, four synthetic rows have iteration labels 1 through 4 and unit coefficient values. Two windows of two iterations give means of 1 and 1. Their spread and end-to-end difference are zero, so both percentage checks are zero. A header-only history instead returns a waiting result before these calculations.

7. Validation and pre-flight

Offline tests pass all 80 cases: seven in-memory freshness cases, eight file-backed restart cases and 65 supervision guards. Four restart cases execute the shipped Bash watcher with real coefficient directories, one fixed arming time, and stubbed polling and solver liveness. Stale converged history and fresh empty or header-only history coexist without creating a trigger. Fresh convergence creates a trigger only after the required consecutive passes; both a waiting result and a newly selected history reset the count.

Negative controls detect oldest-file discovery, removal of the waiting-result reset, removal of the selected-history reset and repeated arming-time capture. Each control is rejected for both empty and header-only inputs, giving eight detections in eight probes. The shipped watcher is unchanged by these disposable probes.

8. Limitations and operation

Modification after arming establishes file freshness, not writer identity. A copied or manually touched history can satisfy this timestamp condition. A shared clock and normal coefficient-writer ownership are required.

For a stale result, continue waiting for current output as required by the freshness criterion. Do not touch an old history to make it eligible. A watcher armed after output has stopped waits for another write.

9. Appendix

9.1 Data register

The timestamps, iteration labels and constant coefficient values are synthetic. No measured or licensed engineering data is used. File-backed integration and Bash execution are verified with stubbed polling and solver liveness; behavior with a running solver and browser comment export remain unverified.

9.2 Sources and reproduction

Requirement: repository issue 2027, suggested fix and regression case. Method: scripts/cfd/ittc_watch.sh, embedded criterion. Reproduction: tests/scripts/test_ittc_watch_freshness.py and tests/scripts/test_ittc_watch_restart.py. The former executes the shipped criterion with synthetic file metadata; the latter uses actual files.

The restart suite also executes the shipped watcher loop to assess coefficient discovery and trigger creation.

Spread is 100(maximum window mean − minimum window mean) / overall mean. Drift is 100|last window mean − first window mean| / overall mean. Both expressions are retained from the watcher; this report establishes no new standards-derived constants.
