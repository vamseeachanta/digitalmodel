## 1. Purpose and scope

The main path loads two JSON catalogs, sweeps selected combinations, evaluates five installation phases, and writes case CSV and summary JSON through `router`. [src/digitalmodel/installation/jumper_installation/workflow.py:L24-L49]

`run_single_case` combines lift-off, in-air bending, splash-zone loading, lowering and tie-in deflection; its verdict uses the maximum of the rounded phase utilisations. [src/digitalmodel/installation/jumper_installation/calculations.py:L294-L335]

The engine dispatches `basename: jumper_installation` to this package, separately from the `installation` branch; the routing registry calls the enclosing installation domain beta. [src/digitalmodel/engine.py:L289-L298] [docs/registry/module-routing.yaml:L557-L562]

The lowering model uses a scalar peak heave amplitude and one derived wave period; it does not resolve a time history, sling geometry or a directional wave phase in that calculation. [src/digitalmodel/installation/jumper_installation/calculations.py:L223-L245]

UNVERIFIED: physical applicability outside a checked design basis, independent benchmark accuracy, and engineering suitability of the supplied screening factors remain unestablished; see item O1 in section 10.

## 3. Method and governing standards

These equations describe the implementation, not independently validated design criteria. [src/digitalmodel/installation/jumper_installation/calculations.py:L94-L291]

| Method | Implementation and reference boundary | Source |
| --- | --- | --- |
| Period | `hs_to_tp`: coefficient × √Hs; the demo explicitly calls this a screening simplification | [src/digitalmodel/installation/jumper_installation/calculations.py:L72-L74] [examples/demos/gtm/demo_05_deepwater_rigid_jumper_installation.py:L208-L215] |
| Lift-off | `calc_phase_1_liftoff`: (air mass per length × length + rigging mass) × lift factor / 1000, divided by maximum crane SWL; radius-dependent crane curves are not read in this function | [src/digitalmodel/installation/jumper_installation/calculations.py:L100-L118] |
| Bending | `calc_phase_2_inair_bending`: effective distributed air load × span² / moment coefficient; stress = moment × OD / (2I); utilisation = stress / (allowable fraction × SMYS) | [src/digitalmodel/installation/jumper_installation/calculations.py:L126-L159] |
| Splash | `calc_phase_3_splash`: projected area = OD × capped submerged length; wave speed = πHs/Tp; relative speed adds lowering speed; quadratic slam and drag add to air weight before amplification | [src/digitalmodel/installation/jumper_installation/calculations.py:L170-L204] |
| Lowering | `calc_phase_4_lowering`: submerged jumper weight + cable weight × depth; added mass from cylindrical displacement; inertial load from scalar heave amplitude × angular frequency²; total divided by wire factor × MBL | [src/digitalmodel/installation/jumper_installation/calculations.py:L216-L245] |
| Tie-in / additional current-force implementation | `calc_phase_5_tiein`: distributed current load proportional to density × drag coefficient × OD × current speed²; optional vertical weight enters `hypot`; deflection proportional to resultant load × span⁴ / (deflection coefficient × EI) | [src/digitalmodel/installation/jumper_installation/calculations.py:L254-L290] |
| Aggregation | `status_from_utils`: `NO_GO` above configured upper threshold, `MARGINAL` at or above lower threshold, otherwise `GO`; empty mapping behaves as zero utilisation; `governing_phase` returns `N/A` for empty mapping | [src/digitalmodel/installation/jumper_installation/calculations.py:L77-L91] |

The demo's report reference list names DNV-RP-H103, *Modelling and Analysis of Marine Operations*, 2011; DNV-ST-N001, *Marine Operations and Marine Warranty*, 2021; DNV-OS-F101, *Submarine Pipeline Systems*, 2021 (pipe stress limits); API 17R, *Subsea Production System Connectors*, 2015 (tie-in tolerance basis); and API 5L, *Line Pipe*, 2018 (X65 material properties), without clause titles in that list; clause text not checked against the licensed copy. [examples/demos/gtm/demo_05_deepwater_rigid_jumper_installation.py:L1270-L1276]

## 5. QA gates

Local QA proposal, revision 1 (this section): G0-G5 are proposed evidence categories, not a sourced policy or solver clearance. The earlier attribution to "AQG r0" supplied no retrievable title, revision or supporting sections and is withdrawn. Code citations establish implementation behaviour only. The former 2.0% load/balance tolerance, 1 s dynamics duration and 25.0% tension limit have no established derivation here and are withdrawn; no replacement engineering limits are inferred from regression tests.

Local derivation: zero-count criteria require completeness, consistent records and no unresolved violations; they are proposed evidence checks, not standards-derived safety limits. C04 and C07 use one rounding quantum as a deliberately loose arithmetic comparison bound: two independently rounded representations of the same exact quantity can each differ by half a quantum, giving a combined bound of one quantum. C04 uses 0.0001 dimensionless for four-decimal utilisation. C07 uses 0.01 te for two-decimal hook/tension outputs, 0.01 MPa for two-decimal stress and 0.0001 mm for four-decimal deflection. Inputs and intermediate calculations will remain unrounded; these output bounds do not cover physical-model error or permit a contradictory status. The implementation precision is recorded in the C04/C07 citations and section 2 output contract.

C08 balance tolerance and C09 run duration/tension bounds are not established. O6 will supply a versioned, retrievable design basis with exact supporting sections or an independently reviewed derivation: force uncertainty and solver convergence for C08; wave and natural periods, transient settling, sampling and stage load envelopes for C09. G2/G3 remain NOT_RUN and uncleared until that basis and the corresponding case evidence are reviewed. A short execution alone cannot demonstrate dynamic adequacy.
