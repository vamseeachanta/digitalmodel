Towing analysis: worked static scenario

The implementation follows the five-step approved plan for issue 487 and its owner audit comment: the package is digitalmodel.marine_ops.towing. It evaluates a synthetic 80 m × 24 m barge, an 80 tonnes-force tug and a 600 m wire. The fixture's historical name contains “500t”; its actual tug capacity is 80 tonnes-force. The fixture is regression input, with no measured vessel data or certified rope properties.

Run and inspect

With the project dependencies installed, execute from the repository root:

PYTHONPATH=src python examples/marine_ops/towing/towing_scenario.py
PYTHONPATH=src python -m pytest tests/marine_ops/towing/ -m "not solver"

Set MPLCONFIGDIR to a writable temporary directory. Configure LLM_WIKI_PATH to the existing maintained wiki. The established citation resolver validates metadata at calculation time; missing or mismatched references raise CitationResolutionError. Tests provide explicitly synthetic metadata to exercise that behavior without distributing licensed standards text.

run_scenario(environment="storm") evaluates the storm input; run_scenario(diameter_scale=0.8) reduces diameter by 20% and scales weight and breaking load by 0.8², under the same-construction assumption. The fixed scenario verdict is retained independently of the optimizer's result.

Interfaces and mechanics

  • solve_catenary(span_m, length_m, weight_n_m, elevation_m) uses keyword arguments for a freely suspended, inextensible line. The output contains horizontal and maximum support tension, maximum sag below the support chord, scope (arc length / horizontal span), and coordinates.
  • catenary_from_pull(...) uses prescribed horizontal load and line length at level supports. Span is an output, since fixed span, length and pull would overconstrain equilibrium. H = w a, span = 2 a asinh(L / 2 a), and support tension = sqrt(H² + (w L / 2)²).
  • compute_drift_force(vessel, current_profile, wind_profile) accepts a signed uniform speed or a callable of height above bed. A callable requires water depth exceeding draft; midpoint quadrature integrates signed u|u| over occupied draft. The river-current package's power-law functions can be passed directly through a callable. No RiverCurrentProfile class exists.
  • The existing OCIMFLoading approximate wind/current formulas are reused. Wind coefficient triples (Cx, Cy, Cmz) can be supplied explicitly with reference areas, using their tabulated signs. The existing approximation's cardinal-angle current artefacts are removed. The code does not retrieve or interpolate a licensed coefficient database.
  • BollardPullCheck(tug_capacity, env_loads).check() compares supplied capacity (N), multiplied by efficiency, with vector resultant demand multiplied by reserve factor. Its margin is available minus required force (N). The existing tug package remains the authority for optional power-to-pull estimates.
  • optimize_configuration(...) exhaustively enumerates included bridle angle, length and diameter. Weight and MBL scale with diameter squared for the same construction. It minimizes amplified main-line tension, then symmetric leg tension. A leg carries T / (2 cos(angle/2)); fitting reaction is 2 T_leg sin(deflection/2). Clearance, scope, strength, fitting capacity and angle bounds filter the grid. Invalid or infeasible grids raise ValueError.
  • Strength, fairlead and angle checks return Result(passed, reason, margin, citations). Strength and reaction margins are N; angle margin is degrees. Geometry margins in the example are metres (clearance) and dimensionless (scope). Supplied geometric limits and fitting capacities are project inputs.

Qualification and limitations

The approved plan explicitly prescribes factors 3.0 dynamic and 1.67 static. Those factors are preserved. Citation metadata binds the available DNVGL-ST-N001 2016-06 reference, section 11. The implementation does not establish that those two factors alone constitute compliance with that edition, or with the current DNV-ST-N001 edition. A PASS means the named checks meet the supplied criteria; it is not a marine-warranty certificate or a control/stability verdict.

Dynamic tension is static tension multiplied by an explicit 1.3 example factor. No time-domain tug-barge interaction is solved. Line elasticity, seabed/water contact, buoyancy, wave loading, yaw control, girting, tug self-resistance and thrust degradation at speed are not established by this model. The line uses the plan's air-weight assumption even when its predicted shape would enter water. Operational acceptance requires appropriate line properties, vessel coefficients, dynamic response and the governing standard assessment.

The independent OCIMF regression uses only the 90° coefficient row from Static Towing Assembly Guidelines (2020), MARIN report 31746-1-PO, Table 5, report page 29. Synthetic geometry and wind speed yield hand-calculated loads; computed components meet the plan's 5% tolerance. This establishes the coefficient-to-load arithmetic, not the applicability of VLCC coefficients to a barge. The catenary analytic case meets the separate 0.5% tolerance.

Unit tests cover both safety factors, the diameter reduction, storm pull failure, each optimizer constraint, invalid inputs and missing citations. The fixture is explicitly included in installed package data.
