Summary

The shared workflow API retains failed execution, extraction and hashing evidence. Successful-run cleanup remains unchanged. Coverage is established by synthetic failure injection, not native execution or engineering qualification. The matrix regression preserves mixed historical response states while a diagnostic result is published.

Basis and acceptance criteria

Issue 2124 requires preservation of failed inputs, partial outputs and original exceptions. Linked issue 2093 and issue 2119 establish the preparation and diagnostic-lookup precedents. No equations, engineering constants or licensed source values are added.

The shared canonical input contract in assetutilities.workflow_api.envelope is used: Analysis, default and cfg_array are excluded. Retained .workflow-evidence/input.json bytes are bound to failure.json by their SHA-256 digest; the failure record identifies the stage and failed state. Existing files are retained rather than overwritten when the metadata name collides. Exception notes expose the retained directory; error envelopes keep the input digest and notes. Canonical bytes and their digest are frozen once before execution and reused for provenance, retention and reproducibility reruns. Metadata recording is best effort and cannot mask the primary exception. Retention limits and disposal remain separate decisions.

The starting offline suite passed 118 tests. The expanded offline suite passes 139 tests across failure retention, preparation, observed evidence, replay/publication and generator validation. Four strengthened regression cases failed before the corrections. Successful preparation and validation publication checks pass. Shared API result goldens remain unverified in this run.

Known limits and later slices

Failed evidence remains in the configured temporary storage until explicitly managed; a temporary location is not durable backup. Raw source files are retained only when the workflow copies them into its execution directory. The canonical configuration digest does not attest uncopied external files or volatile runtime configuration. Metadata-write failure retains partial evidence and the original exception but may leave an incomplete metadata record. A manifest retained after post-generation failure does not establish preparation completion or engineering acceptance. Failures before creation of an execution directory have no retained execution files. Second-provider review remains pending.

Later work will test variant preparation and smoke-probe exception cleanup without licensed execution, then inspect additional registered router failure paths individually. No claim of universal preparation coverage or new native qualification is made.
