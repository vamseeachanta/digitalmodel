Draft workflow policy

Heavy draft jobs are skipped while required aggregates fail closed; existing sweep, concurrency and runtime policies are preserved, and manual dispatch uses the shared ancestor for register diffs.

The implementation basis is revision e3292a8b. This document describes that behavior without changing workflow configuration.

Plan-lite

  • Heavy jobs will skip draft pull requests; required aggregates will remain unconditional.
  • All eight pull-request workflows will accept ready_for_review.

  • Existing push sweeps, concurrency groups, explicit timeouts and freshness limits will remain in force.
  • Policy tests will pin job names, draft guards, event subscriptions and dispatch diff routing.

What changed

The eight pull-request workflows skip heavy draft jobs and accept ready_for_review. The four workflows with existing edited subscriptions retain them; the other four omit edited. Existing path filters continue to apply. Manual dispatch is available in all twelve workflows.

The required Domain test aggregate and Run Quality Gates jobs retain always(). They fail when required dependencies are skipped, failed or cancelled. Drafts therefore remain blocked by these required checks until applicable checks succeed on a ready pull request.

The full sweep still runs on every push to main, the nightly schedule and manual dispatch. Each sweep retains its own run-specific concurrency group with cancellation disabled. Existing push groups and deployment concurrency policies are preserved.

Only two jobs have explicit timeouts: the existing 20-minute focused test budget and 40-minute sweep budget. No publish timeout is added. Baseline selection and comparison retain 24-hour freshness. Manual quality-gate dispatch computes the register diff base with git merge-base origin/main HEAD.

Verification basis

The workflow policy tests check the inventory, reject duplicate YAML keys at three mapping depths, and exercise mutated guards, triggers, timeouts and concurrency. Executable cases check aggregate failure handling and detector routing. The trigger tests cover register diff routing for dispatch, push and pull-request events, including unavailable ancestry. The baseline tests check ages below, at and above the existing freshness boundary.

Known limits

Local shell and policy tests do not establish hosted scheduling or ready-PR execution. Required checks on a ready pull request remain to be observed before merging. Existing path filters determine optional workflow coverage; global changes or unavailable push ancestry can still select every domain.
