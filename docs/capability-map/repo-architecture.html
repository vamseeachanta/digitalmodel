Method

No engineering equations or engineering constants are introduced. All work declarations in scripts/capabilities/build_onepagers.py:SPECS and all domain HTML pages are enumerated. Directory groups are preserved. Producer classifications come from scripts/check_generated_html.py:GENERATORS and scripts/generated_html_ownership.py. Direct calculation imports are recorded as source pointers, not transitive dependency certification. Explicit registry inputs and existing positional file arguments are included before page generation. Suffix-derived JSON outputs are traced through their writer; filename-only discovery would miss these outputs.

One drawing is embedded in the repository README; repo-architecture.mmd is its reviewable source. repo-architecture.json is a documentation snapshot, not a competing engineering dataset catalog. The snapshot is manually maintained with acceptance tests; a new page or changed declaration requires an evidence update. Acceptance checks use the named base tree with these documentation changes overlaid, without merging it into the branch. Deterministic generation remains follow-up work.

Worked example

Input: structural/wall-thickness-explorer.html from the capability declaration. Method: resolve the target under the documentation root, join the exact path to the generator registry, and inspect the producer imports and writes. Answer: scripts/capabilities/build_wall_thickness_explorer.py imports src/digitalmodel/structural/analysis/wall_thickness.py and emits both wall-thickness-explorer.json and an embedded-result HTML page. The JSON is also read by scripts/hf/build_capability_datasets.py:wall_thickness_rows for tidy data preparation. That HTML does not fetch the adjacent JSON. The separate wall-thickness surface page now fetches its bounded wall-thickness-3d-explorer.json sidecar; its full-resolution wall-thickness-3d.json remains a generated prerequisite. The source calculation is linked; a new solve, numerical equivalence, and remote publication are NOT_EVALUATED.

Execution and publication boundaries

Registered page generation uses repository inputs; upstream calculation readiness is not inferred. Drilling-riser pages use analytical screening. OrcaFlex and OrcaWave solve execution requires a licensed Windows environment; AQWA solves require a license. Reading or rendering saved results is separate. Some CFD pages need external OpenFOAM results; an open solver does not establish committed inputs or a reproducible page.

.github/workflows/pages.yml builds and publishes the MkDocs site, with docs/api as the root in mkdocs.yml. Hugging Face preparation has ten table projections across seven dataset groups (integrity, corrosion, artificial lift, mooring, hydrodynamics, well and field development) in scripts/hf/build_capability_datasets.py; scripts/hf/publish_atlas_explorer.py separately implements atlas publishing. The capabilities portal redirects to aceengineer.com. Coverage of remaining capability datasets, downstream hydration, and current remote publication are NOT_EVALUATED. Missing implementations are not drawn as completed pipelines.
