Capability report inventory plan

Summary

The capability inventory will distinguish reviewed evidence from engineering qualification using explicit observations and source digests.

02026-10-25The inventory scope, reviewed inputs and acceptance checks will be recorded so that the implementation can be assessed against an explicit plan.

Plan-lite

  1. Scope: Work will remain inventory-only. Tracked HTML pages under the declared roots will be enumerated, and the reviewed subset will be summarized. Report production, engineering calculations and website integration will remain outside this scope.
  2. Inputs: Explicit reviewed observations will supply evidence status, qualification, criteria, limitations, observation time and source digests through the saved JSON observations.
  3. Validation: The inventory builder will validate tracked public source paths and digest coverage, reject stale source digests, and preserve the reviewed judgments.
  4. Outputs: The JSON inventory and HTML inventory will be deterministic for unchanged observations and sources. Discovery counts and gaps will be derived separately from observations; observation time will be preserved without a new generation timestamp.
  5. Verification: The focused tests will exercise evidence boundaries, invalid inputs, stable ordering and output safety. Saved observations will be used to rebuild both artifacts byte for byte; source digests, local links and record counts will be checked independently.

Acceptance and limits

Acceptance will require the focused tests to pass, both reviewed artifacts to rebuild byte for byte, every recorded source digest to match its source bytes, and every local link to resolve. RETAINED will describe accessible records against a named criterion; it will not establish engineering qualification. Unreviewed pages and unresolved evidence gaps will remain explicit.
