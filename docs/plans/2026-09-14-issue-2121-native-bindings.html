Acceptance and verification

The copy set will be exactly all 21 original artifact-table entries, with the mandatory provenance/deck/metadata set checked as a subset. A private _owning_root() resolver will derive the production root from __file__; synthetic unit tests will monkeypatch this private resolver and will never write the real examples tree. The inventory digest will equal digest_bytes(canonical_bytes(runtime_sources())). Each inventoried working file will be compared byte-for-byte with its Git blob at source_revision, and a mismatch will refuse preparation. Failed revision labels will remain consumed by their preserved partial directory.

The execution consumers will be cylinder_canary._manifest (schema/order/artifact/runtime checks, additional lineage metadata ignored) and cylinder_adapter._bound_reference through make_execution_adapters (reference path and artifact digest selection, additional lineage metadata ignored). cylinder_reference_provenance.verify_prepared_reference will read copied sibling capture files and original frozen Git inputs. cylinder_benchmark.validate_deck will validate copied deck bytes without reading manifest lineage. analysis_pending_inputs.pending_inputs will continue reading the original fixed benchmark manifest and will not consume a successor. The integration receipt will exercise both execution consumers, and will independently verify the original matrix/source digests.

The original manifest and matrix-r2 digests will remain unchanged. All copied artifacts will match originals and frozen capture evidence. The successor runtime inventory will match loaded source bytes and an independent exact-current Claude review. Existing reference replay will pass without a new derivation. Refusal tests will pass before preparation. Changed code will pass the legal scan. A code commit will precede final runtime inventory pinning and generation; the generated artifact will receive exact-current reciprocal review before native use. Each successor will apply to its recorded source revision only and will intentionally expire after an inventoried source change. The pinning receipt will distinguish expected invalidation from unit-test failure. Existing manifest consumers will be enumerated; the successor will be execution-only and will not be fed to original-bundle matrix intake. Extra runtime_lineage metadata will be checked against the execution consumers.

Risks and limitations

Copied capture artifacts will be a versioned execution snapshot, not another result database. Failure during copying may leave a partial directory for diagnosis; it will not be reused or deleted automatically. Source-hash equality will not attest arbitrary callbacks. Storage allowances will remain operational budgets, not proven peak-scratch bounds. Numerical completion will not confer qualified reuse. Unknown ownership or checker identity will prevent execution readiness and will be surfaced as a factual question to CONTROL.
