# Issue #1983 -- Stage 0 triage: the 30 `scripts/` files that pytest collects

Evidence for the implementation of [#1983](https://github.com/vamseeachanta/digitalmodel/issues/1983).
Produced before any code change, on branch `fix/1983-scripts-named-like-tests` at base
`3f8a449b`. **The approved plan was measured at `2c4a556a`**; the drift between those two
commits touches only `docs/small_operator/`, so no plan premise moved for that reason --
but several plan figures did not survive re-measurement, and those are listed at the end.

## Method

Every one of the 30 files matching `python_files` (`test_*.py`, `*_test.py`) under
`scripts/` was run individually, twice, inside a single `uv run` process:

```
python -m pytest <file> --collect-only -o addopts='--import-mode=importlib --tb=short --strict-markers' -q -p no:randomly -p no:sugar
python -m pytest <file>                -o addopts='--import-mode=importlib --tb=short --strict-markers' -q -p no:randomly -p no:sugar
```

The `-o addopts=...` override is required: `pytest.ini` sets `-v`, which overrides `-q`
and yields tree output with no node IDs. `--import-mode=importlib` is load-bearing.

A complete recursive filesystem listing (excluding `.git/`, `.venv/`, `__pycache__/`,
`.pytest_cache/`) was taken before collection, between collection and run, and after the
run, so that side effects are attributed to the correct phase.

## Result: every filesystem side effect happens at COLLECT time

This is the sharpest single finding, and it is stronger than the plan stated. Across all
30 files, the set of paths created during the *run* phase was **empty for every file**.
Everything is created during `--collect-only`, because pytest collects by importing and
these modules do their work at module scope.

| writer | created at collect | at run |
| --- | --- | --- |
| `scripts/testing/test_converter_advanced.py` | 27 paths under `temp_test_conversion/` | 0 |
| `scripts/testing/test_model_generator_basic.py` | 10 paths under `temp_test_generator/` | 0 |
| `scripts/testing/test_complete_workflow.py` | 9 paths under `temp_workflow_test/` | 0 |
| `scripts/testing/test_converter_live.py` | 8 paths under `temp_test_conversion/` | 0 |
| `scripts/test_phase_convention.py` | `phase_convention_test_results.txt` (repo root) + one empty directory | 0 |

**Four files write, not two.** The plan named only `test_complete_workflow.py` and
`test_converter_live.py`; `test_converter_advanced.py` and `test_model_generator_basic.py`
also write, and `test_converter_advanced.py` is the largest writer of the four.

### `git status` is blind three times over

After a full `pytest scripts/` collection the tree carries five pieces of residue and
`git status --porcelain` reports exactly one of them:

```
$ ls -d temp_* ; ls phase_convention_test_results.txt ; find . -maxdepth 1 -name '*workspace-hub*'
temp_test_conversion
temp_test_generator
temp_workflow_test
phase_convention_test_results.txt
./D:\workspace-hub\digitalmodel\docs\charts\phase2\ocimf

$ git status --porcelain
?? phase_convention_test_results.txt
```

Three reasons it cannot see the rest:

1. `temp_test_conversion/` and `temp_workflow_test/` are matched by `.gitignore:39,40`;
   `temp_test_generator/` by `.gitignore:23` (`/temp*`).
2. `D:\workspace-hub\digitalmodel\docs\charts\phase2\ocimf` is a **single directory
   whose name contains literal backslashes** -- a Windows path taken literally on Linux,
   created in the repository root by `test_phase_convention.py`. It is *not* gitignored;
   git cannot see it because it is **empty**, and git does not track empty directories.
3. Only the repo-root text file is both tracked-eligible and non-empty.

Item 2 was not in the plan. It is an independent third reason the superseded
`git status --porcelain` acceptance criterion could never have failed, and it is why this
implementation compares full directory listings instead.

## Result: the collection abort is an unlicensed-box accident

```
########## UNLICENSED: pytest scripts/ ##########
INTERNALERROR>   File "scripts/test_orcaflex_loading.py", line 18, in <module>
INTERNALERROR>     sys.exit(1)
INTERNALERROR> SystemExit: 1
8 errors in 3.68s

########## LICENSED (OrcFxAPI stubbed on PYTHONPATH): pytest scripts/ ##########
!!!!!!!!!!!!!!!!!!! Interrupted: 9 errors during collection !!!!!!!!!!!!!!!!!!!!
9 errors in 4.89s
```

With `OrcFxAPI` importable the `except ImportError` handler never fires, the `sys.exit`
never runs, there is no `INTERNALERROR`, and the directory-wide write reproduces in full
(all five residue items above were present after the licensed run). The plan's claim
holds: fixing that one `sys.exit` in isolation would make the repo-root write reproduce
everywhere. It must not be fixed in isolation.

Note also that the root `conftest.py` `collect_ignore` does **not** protect this path:
`collect_ignore` is not consulted for a directory named explicitly on the command line,
which is why `pytest scripts/` still collects.

## Where measurement contradicted the approved plan

The plan's figures were taken at `2c4a556a` and several did not survive re-measurement at
`3f8a449b`. The base drift between those commits touches only `docs/small_operator/`, so
these are measurement corrections, not drift.

1. **40 items pass, not 39.** The extra one is
   `scripts/python/digitalmodel/orcawave/test_orcawave_integration.py`, which the plan does
   not list anywhere. It has zero assertions.
2. **Only 1 of the plan's 6 REAL TEST candidates survives as unambiguous.** The plan
   projected six files covering "doc tooling", "aqwa parser" and two shipped APIs.
   Measured:
   - `test_config_manual.py` -- confirmed, 15 real assertions against `digitalmodel.config`.
   - `test_calm_data_loader.py` -- exercises the shipped data loader but has **zero
     assertions**; kept as a test on the brief's stated criterion, flagged as a judgement call.
   - `test_migration_execution.py` (12) and `test_migration_metadata.py` (9) -- the plan
     omitted that **each also carries a failing test**. Both import stdlib only and assert
     on fixtures they create themselves. Relocating them would have turned CI red.
   - `test_structure_creation.py` (7) -- imports stdlib only; asserts that `Path.mkdir`
     worked and that its own in-file helper returns the expected value.
   - `test_aqwa_heading_fix.py` (2) -- the plan says "imports under test: aqwa parser".
     It imports `pathlib` and `re` only, has **zero assertions**, and re-implements the
     parser logic inline.
   So the plan's headline "renaming would delete 39 passing tests from the discoverable
   surface" overstates the loss considerably: of the 40 passing items, 33 assert only on
   fixtures or helpers defined in the same file, 3 assert nothing at all, and 7 (all in
   `test_config_manual.py`) are genuine coverage of shipped API.
3. **Four files write at collect time, not two** (see above).
4. **The exit-scan offenders are confirmed exactly as the plan describes** --
   `test_orcaflex_loading.py:18` (`sys.exit(1)` inside `except ImportError`) and bare
   `exit(1)` inside `except Exception` in `testing/test_complete_workflow.py` and
   `testing/test_model_generator_basic.py`. This was the plan's most-corrected finding and
   it held up.
5. **`test_git_repo_analysis.py` / `test_git_repo_optimization.py` fail for an
   import-path reason, not a missing module.** `git_repo_analyzer.py` does exist, as a
   sibling under `scripts/python/digitalmodel/tools/`; it is simply not importable under
   `--import-mode=importlib`.

## Routing rule used

- **REAL TEST** -- collects items that pass *and* exercises code outside the file itself
  -> relocate under `tests/<domain>/`.
- **BROKEN** -- collects items that fail -> rename to `check_*`. Fixing them is out of the
  plan's scope ("will not rewrite what any script does"), and relocating a red file into a
  CI gate is not an option.
- **SCRIPT** -- collects nothing, or collects items that pass without asserting on anything
  outside the file -> rename to `check_*`.

`check_*` matches neither `test_*.py` nor `*_test.py`, and is already the local convention:
`scripts/check_generated_html.py`, `scripts/legal/check_protected_identifiers.py`,
`scripts/python/digitalmodel/legacy/check_performance_regression.py`, `check_doc_coverage.py`.
