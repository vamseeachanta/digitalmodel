## Findings

1. **The plan's causal attribution for L01 is falsified by its own table.** §Reproduction proofs (plan line 168-169) says "Four of six DOF exceed 0.95 magnitude correlation and every one is recorded `NO_CONSENSUS` … which is D1 and D2 acting together." The gate at `multi_solver_comparator.py:469-471` is `corr > 0.99 AND rms < tolerance`. The report's six magnitude correlations are 0.958, 0.981, −0.855, 0.489, 0.968, 0.967 — **the highest is 0.981, so all six fail the correlation term regardless of rms.** D1 (absolute-vs-relative rms) cannot flip a single L01 DOF. The binding constraint is `CORR_MIN = 0.99`, which the plan demotes to a bullet under §Risks with no pseudocode, no TDD row, no acceptance criterion, and no decision rule. After Phases 1 and 2 the L01 verdict is still DISAGREE on all six DOF, so §Deliverable's "derived, dimensionally sound verdict" is a relabel, not a re-derivation.

2. **The external-oracle test cannot fail.** TDD row `test_l01_ship_heave_matches_aqwa_lis` states its expected output as "OrcaWave within stated tolerance, **or an explicit recorded disagreement**". Both branches pass. The acceptance criterion "At least one test asserts an OrcaWave-produced value against the AQWA `.LIS` external oracle (closes #1633 item 6)" is therefore satisfied by a test with no falsifiable assertion. Neither "stated tolerance" nor the disagreement-recording format is specified anywhere in the plan.

3. **D3's zero-variance guard silently breaks the deliberate near-zero-phase path.** `multi_solver_comparator.py:275-288` intentionally returns `correlation=1.0` with `errors=np.zeros_like(...)` when `peak_mag < 1e-10`, with the comment "Near-zero magnitude: phase is undefined … Override with perfect agreement instead of computing noise correlation." The plan's §Pseudocode `deviation_stats` says "if either series is empty **or has zero variance**: … quality = INSUFFICIENT_DATA", and `derive_status` says "if **any** DOF quality is INSUFFICIENT_DATA: return `incomplete`". Consequence: any vessel with one physically-null-response DOF becomes permanently `incomplete` and can never reach `pass`. The plan never cites lines 275-288, and no TDD row covers the interaction.

4. **The 36/36 exactly-`1.0` matrix correlations get a label, not a diagnosis — and the label still yields agreement.** Under §Pseudocode, `allclose` on non-constant arrays returns `correlation = 1.0, quality = IDENTICAL`. That feeds `pair_agrees` as `corr=1.0 > 0.99` and `rms=0 < tolerance` → **FULL**; `derive_status` downgrades only on `INSUFFICIENT_DATA` or `DISAGREE`, so `IDENTICAL` flows straight to `"pass"`. The acceptance criterion "no bare `1.0`" is met while the false verdict survives intact. More seriously, #1633's own title alleges the suite "compares OrcaWave to itself" — 72 exactly-identical matrix entries across two different BEM codes is the signature of a *data-plumbing* defect (same array fed to both legs), and no phase of this plan investigates which of the two cases (identical input vs. zero-filled arrays) actually obtains.

5. **Phase 2 has no identified OrcaWave input, and the obvious candidate directory holds a different vessel.** §Phasing Phase 2 says "Re-parse the existing `001_SHIP_RAOS_REV2.LIS` and **the existing OrcaWave results**". `benchmark_results/orcawave/` contains `UnitBox_Benchmark.yml`, `UnitBox_Benchmark_data.dat`, `unit_box_clean.gdf`; `benchmark_results/aqwa/` contains `WRK-031_3WAY_BENCHMARK.LIS` (307 bytes — the failed run) and `unit_box_clean.gdf`. **Neither directory holds ship data.** The only ship OrcaWave artifact on disk is `orcawave_001_ship_raos_rev2.xlsx` (2.34 MB) at the L01 top level, which the plan never names, and there is no stated parser for it. Phase 2 — the phase that "produces the deliverable the issue asks for" — has an unresolved input.

6. **§Deferred scope's L00 evidence is wrong in two ways.** It states "All 12 cases carry hand-authored `status: pass` while their `reference_data.yaml` files are `status: template` with no arrays." Actual tree: case `"2.2"` is `status: blocked` ("mesh file HemisphereAndLid0814.gdf missing"), not `pass`; and only **4** `reference_data.yaml` files exist across the 12 cases — 8 cases have no reference-data file at all, which is a worse condition than "template", not the same one.
