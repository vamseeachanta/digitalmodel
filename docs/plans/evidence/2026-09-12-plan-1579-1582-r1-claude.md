# Plan #1579 — inertia-tensor origin — **MAJOR**

## 1579-1 — MAJOR — the parallel-axis transform as written adds where it must subtract, and the stated sign mechanism cannot work

Plan lines 313–324:

```
function translate_inertia(I, mass, d):
    # d is the vector FROM the current reference point TO the new one.
    # ... moving the reference point AWAY from the
    # centre of mass ADDS m*(|d|^2 * identity - outer(d, d)); moving TOWARD
    # the centre of mass subtracts it. Callers pass the signed shift.
    S = mass * (dot(d, d) * identity(3) - outer(d, d))
    return I + S

function to_centre_of_mass(I, mass, origin_label, cog):
    if origin_label == "centre_of_mass": return I
    if origin_label == "body_origin":    return translate_inertia(I, mass, -cog)
```

`S` is **quadratic in `d`**: `dot(-d,-d) = dot(d,d)` and `outer(-d,-d) = outer(d,d)`,
so `S(-d) ≡ S(d)`. Passing `-cog` produces byte-identical output to passing
`+cog`. The comment "Callers pass the signed shift" describes a mechanism that
does not exist, and `to_centre_of_mass(..., "body_origin", cog)` therefore
returns `I_o + m(|c|²δ − c⊗c)` when the correct result is
`I_o − m(|c|²δ − c⊗c)`.

This is not a nitpick about pseudocode style — the plan contradicts itself two
sections later. Plan line 412 (TDD preamble) states the correct identity:

> `I_cm` denotes `I_o − m(|c|²δ − c⊗c)`

So the fixture definition and the transform definition disagree on sign. Every
acceptance criterion that depends on the transform direction (tests 16, 17, 19,
26–30) is pinned to one of two mutually exclusive definitions and the plan does
not say which.

**Must change:** replace the "signed shift" contract with an explicit direction.
State it as `to_point(I_about_cm, m, r)` where `r` is the vector **from the CoM
to the target point** and the operation is always `+S`, with
`to_centre_of_mass(I_about_P, m, r) = I_about_P − S(r)` as a separate, explicitly
subtracting entry point. Then restate `to_centre_of_mass(I, m, "body_origin", cog)`
as `I − S(cog)` and re-derive tests 2–5 against it.

## 1579-4 — MAJOR — the synthetic TDD fixture is physically inadmissible, in both frames, against the plan's own admissibility invariants

Plan line 412 fixes `m = 1.0e7 kg`, `c = [10.0, 2.0, −5.0] m`, and products
`Ixy = 3.0e6`, `Ixz = 4.0e6`, `Iyz = 5.0e6`. The only diagonal values the plan
supplies anywhere are in its own reproduction output (line 250):
`(1.0e+08, 2.0e+08, 2.5e+08, 3.0e+06, 4.0e+06, 5.0e+06)`, i.e.
`Ixx = 1.0e8`, `Iyy = 2.0e8`, `Izz = 2.5e8` with the same three products.

Huygens–Steiner requires `I_o,xx ≥ m(c_y² + c_z²) = 1.0e7 × (4 + 25) = 2.9e8`
for any real body. The fixture has `I_o,xx = 1.0e8`. Therefore

```
I_cm,xx = 1.0e8 − 2.9e8 = −1.9e8     (negative)
I_cm,yy = 2.0e8 − 1.25e9 = −1.05e9   (negative)
I_cm,zz = 2.5e8 − 1.04e9 = −7.9e8    (negative)
```

`assert_physically_admissible` (plan line 329, "require all eigenvalues > 0")
raises on `I_cm`. **Test 9 (`test_admissibility_accepts_offset_cog_fixture`,
"no raise") fails by construction**, and tests 16, 17, 19, 26, 27, 28, 29 and 30
are all built on a body that cannot exist.

The same defect appears a second time on the radii path. Test 14 uses
`radii_of_gyration=[12, 40, 42]` (taken from the plan's own reproduction, line
255). With `I = m·k²`: `144 + 1600 = 1744 < 1764`, so
`Ixx + Iyy < Izz` — the triangle inequality the plan itself proposes to enforce
(test 8) is violated. Any forward-emission path that calls
`assert_physically_admissible` on the radii-derived tensor (the AQWA pseudocode
at line 364 does exactly this) will raise on the plan's own fixture.

**Must change:** choose a fixture that satisfies both invariants, state its full
six components numerically in the plan, and show the hand-computed `I_cm` and the
triangle-inequality margins in the plan text so a reviewer can check them without
running code. A body-origin tensor for a body with a 10 m CoG offset and
`m = 1e7 kg` needs diagonal terms of order `1e9`–`1e10`, not `1e8`.

- `i<3, j≥3` (force / angular velocity) = `N/(rad/s)` = **`N.s/rad`**
- `i≥3, j<3` (moment / linear velocity) = `N·m/(m/s)` = **`N.m.s/m`**

`N.m.s/rad` is neither. It is `N·m/(rad/s)`, the **angular-angular** unit — which
is exactly what `_default_units` also returns for `"rotational"`
(`wamit_reference_loader.py:654-655`, both keys are the same string). So WAMIT's
label is simply wrong for both halves, not "right for one half". The plan offers
this sentence as the motivating justification for the two-label design; the
design is right for other reasons, but the stated reason is a dimensional error
in a plan whose purpose is to eliminate dimensional errors.

**Must change:** rewrite lines 263-265 to state that `N.m.s/rad` is the
angular-angular unit and is incorrect for both coupling halves, and that the
correct pair is `N.s/rad` / `N.m.s/m`.

(For the record, the rest of the dimension table at plan lines 424-441 was
checked term by term — all four added-mass blocks and all four damping blocks —
and **is dimensionally correct**, as is the `scale_to_canonical` exponent
formula, including its handling of a non-unit `time_in_s`.)
