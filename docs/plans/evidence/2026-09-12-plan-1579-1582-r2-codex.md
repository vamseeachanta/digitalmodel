## Findings

### 1. MAJOR — The shared reference-point dependency has no implementable interface

**Evidence:** P1579:341 proposes `Optional[Literal["body_origin", "centre_of_mass"]]`; P1579:490 promises reusable semantics. P1582:466 requires a 3-vector; P1582:651-655 calls the reference point an “opaque, required 3-vector plus a frame label” while forbidding redefinition.

**Defect:** An inertia-origin label is not a reporting-point vector. P1579 supplies neither a named reusable origin type nor a point/frame record or mapping API. P1582 invents a different representation while claiming to consume the first. Coordinates equal to `[0,0,0]` in different body frames need not identify the same physical point. An input rigid-body inertia reference also need not be the reporting reference of output added mass or damping. OrcaWave reports A/B in body coordinates and permits translated reporting origins; copying the inertia label is insufficient. [Orcina output convention](https://www.orcina.com/webhelp/OrcaWave/Content/html/Results,Addedmassanddamping.htm), [reporting-origin API](https://www.orcina.com/webhelp/OrcFxAPI/Content/html/Pythonreference,Diffraction.htm).

**Required change:** Specify one owner, import path, origin vocabulary, point/frame/body identity, coordinate units and finite-value validation. Define the mapping from input inertia origin to coordinates separately from extraction of each solver's matrix reporting origin. Make both plans use that contract before approval; reject unavailable reporting-origin evidence.

### 2. MAJOR — Parallel-axis subtraction cannot be implemented by negating the displacement

**Evidence:** P1579:313-324 says callers pass a “signed shift”, always returns `I + S`, and calls it with `-cog` to obtain centre-of-mass inertia. P1579:412 instead correctly specifies subtraction.

**Defect:** `S(-c) = S(c)`, because both the squared norm and outer product are even. The pseudocode adds inertia when it must subtract it. For `m=10^7 kg`, `c=(10,2,-5) m`, the correction in kg.m² is:

```
S(c) = [[ 290000000, -200000000,  500000000],
        [-200000000, 1250000000,  100000000],
        [ 500000000,  100000000, 1040000000]]
```

Correctly, `I_cm = I_o - S(c)` and `I_o = I_cm + S(c)`. For arbitrary reference points P and Q, the correction is `S(Q-C)-S(P-C)`, not generally `S(Q-P)`.

**Required change:** Replace the direction-by-vector-sign API with explicit source/target references or separate add/subtract operations. Pin independent numerical expectations for both directions and products of inertia before implementation.

### 3. MAJOR — The proposed physics fixture is incomplete and its apparent reproduction values are impossible at the CoM

**Defect:** Reusing that reproduction tensor gives CoM diagonal `(-1.9e8,-1.05e9,-7.9e8) kg.m²`, which cannot pass positive definiteness. If another tensor is intended, it is not defined. Test 5 at P1579:420 calls `trace(I)-2m|d|²` an invariant without distinguishing source/target tensors or distance from the CoM; arbitrary translation does not obey that statement.

**Required change:** Define all six values, preferably from an independently specified admissible CoM tensor or mass distribution, then publish both complete tensors and invariant equations. For example, shifting from CoM to O gives `trace(I_o)-trace(I_cm)=2m|c|²`; state the reference points explicitly.

### 6. MAJOR — Damping coupling justification assigns a rotational unit to a coupling block

**Evidence:** P1582:263-265 says that `N.m.s/rad` and `N.s/rad` are both correct for their respective mirror halves.

**Defect:** `B[linear,angular]` is force/angular velocity: `N.s/rad`. `B[angular,linear]` is moment/linear velocity: `N.m.s/m` (equivalent to `N.s`). `N.m.s/rad` is the angular-angular unit. The WAMIT coupling label is wrong for both coupling halves, not correct for one. P1582:433-436 has the correct block table and contradicts its own explanation. [Orcina block-unit definitions](https://www.orcina.com/webhelp/OrcaWave/Content/html/Results,Addedmassanddamping.htm).

**Required change:** Correct the explanation and explicitly identify the WAMIT label defect. Keep independently derived four-block tests. Separate SI dimension from retained angular-coordinate annotation: radian is dimensionless in SI, so P1582:438's assertion that the mirror blocks are different SI dimensions is misleading even though their quantity labels can distinguish angular input. [BIPM SI brochure](https://www.bipm.org/utils/common/pdf/si-brochure/SI-Brochure-9.pdf).

### 7. MAJOR — Force-base handling is absent from the advertised native-basis contract

**Evidence:** P1582:452-460 scales only mass, length, time and angle; P1582:547-553 tests tonne and kg bases only. There is no `force_in_N`, explicit coherent-basis constraint, or N/kN test.

**Defect:** The uniform factors are correct for the listed coherent metre-second-radian bases: one tonne is 1000 kg; one kN is 1000 N; both directions reverse with 0.001. Thus every A block on a tonne basis and every B block on a kN basis gets factor 1000, including both mixed blocks. No extra factor of 1000 or gravity belongs in rotational terms. But equating the damping factor with the mass factor assumes force and mass bases are coherent. OrcaWave allows independently selected user units and non-inertial systems. [Orcina model units](https://www.orcina.com/webhelp/OrcaWave/Content/html/Data,Model.htm).

**Required change:** Fully define each allowed `UnitBasis` member and verify the actual input/result unit system before selecting it. Either reject all non-supported/non-coherent systems or implement a separately evidenced force conversion. Add literal N↔kN and kg↔tonne expectations on all blocks and reject contradictory mass/force declarations. `ORCAWAVE_TE` must not be selected merely because a result came from OrcaWave.

### 10. MAJOR — Parse-time physical rejection is not implemented symmetrically

**Evidence:** P1579:297 promises parse-time rejection of physically inconsistent references. P1579:343-356 checks labels/keys only; P1579:364 applies physical admissibility only in AQWA emission. OrcaWave at P1579:371-374 only maps labels. P1579:309 defaults every omitted tensor component to zero.

**Defect:** The same inadmissible CoM tensor can validate and reach OrcaWave while AQWA rejects it. Empty/incomplete tensors, non-finite coordinates/components, and invalid radii are not covered by a shared rejection boundary. Existing `input_schemas.py:217-235` checks coordinate/radii length only.

**Required change:** Specify a shared finite-value and physical-validation boundary, including validation of the CoM image for body-origin inputs, used by both backends and reverse imports. Define required diagonal keys versus deliberately optional zero products; reject an empty tensor. Add non-finite, incomplete and invalid-radii tests. If idealized zero principal moments are intentionally excluded, document that restriction instead of treating strict positive definiteness as universal physical admissibility.

**Additional bypass:** P1579:344-356 branches on tensor presence, whereas `orcawave_backend.py:322` branches on `mode`. Current `input_schemas.py:238-248` allows a free-floating spec with both radii and a tensor. With `body_origin`, that object passes the proposed tensor branch while OrcaWave consumes the radii. Specify mutually exclusive alternatives or mode-specific precedence, and test both-present inputs; otherwise the proposed radii-origin rejection is bypassed.

### 11. MAJOR — Mixed-scale and transpose rejection has no evidence source

**Defect:** Numeric values with unchanged metadata do not reveal whether one block was already scaled or whether a matrix was transposed. A different physical matrix can contain exactly those values. A non-symmetric matrix and its transpose both violate symmetry; rejecting both does not identify an ordering error. For an exactly symmetric matrix, transpose changes nothing.

**Required change:** Define independently captured native data, immutable conversion state, revision/basis checks, and an explicit native-to-normalized consistency check. Define the comparison entry point and producer-specific ordering evidence. Recast numerical mutants as test-oracle checks where runtime detection is impossible; do not advertise impossible data inference as fail-closed behavior.

### 15. MAJOR — AQWA text precision contradicts the proposed round-trip tolerance

### 16. MAJOR — Displaced-water mass is conflated with general body mass
