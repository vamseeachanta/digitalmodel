Single-case installation replay plan

The workflow will reproduce one explicitly selected case from pinned inputs in a new output directory. The existing materializer, solver runner, extraction, screening and report modules will be composed.

  1. Input digests, code revisions, package versions and processor affinity will be verified before native execution.
  2. The master, matrix and selected change will be copied into a new study; materialization and solving will run without any resume path.
  3. Fresh traces and full tension-event metrics will be verified. Every numeric retained channel field, including extrema, static tensions and event summaries, will be compared using explicit absolute and relative tolerances.
  4. A single-case monitoring payload and HTML/PDF pilot reports will be generated. The full operating envelope will not be reconstructed from one case.
  5. Stage lineage and output hashes will be retained. Only the fresh simulation will be removed after comparison and artifact verification pass. A failed replay will retain its simulation for diagnosis.

Adversarial review

The review will challenge hidden resume paths, input drift, partial comparison coverage, default tolerances, unpinned dependency changes, misleading envelope claims and deletion outside the new run. Tests will reject missing or changed inputs and existing output roots; the retention boundary will be verified before deletion.

Historical campaign state and simulations will remain untouched. Native execution will be scheduled separately after code review.
