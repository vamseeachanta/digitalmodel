#1983 implementation plan: 30 scripts wearing a test name

Issue #1983 · branch plan/1983-collection-side-effects · base 2c4a556a · revision 2, after an adversarial REJECT · status: awaiting user approval

Revision 2 withdraws revision 1's withdrawal. Revision 1 opened by claiming the issue's headline was wrong — that pytest collection never writes into the repository. That claim was itself wrong, and the adversarial round proved it in one command. Collection does write. The issue as filed stands. Revision 1 also asserted that none of the 30 files is a test; 39 of them pass, some against production APIs. Both errors came from testing one path and generalising to all paths. The corrected evidence is below, and the recommendation has changed shape as a result.

Goal and authorization boundary

Thirty files under scripts/ are named test_*.py or *_test.py. Most are analysis and smoke scripts wearing pytest's collection prefix — but not all, which is the finding that reshaped this plan. Because pytest collects by importing, pointing it at these files executes them.

  • G1 — collection will not mutate the working tree, anywhere, including paths that are gitignored.
  • G2 — files that are not tests will not carry a test name; files that are tests will live in tests/.
  • G3 — guards will make both properties enforceable, so neither can silently regress.
  • G4 — the status of examples/, .codex/ and .gemini/ will be decided rather than left ambiguous.

Boundary. This plan will not rewrite what any script does and will not delete scripts. It changes names, locations, guards and collection status only.

Revision 1 tested only pytest scripts/ — the whole directory — which aborts early (below) and so never reaches this module. Concluding "never via pytest" from that single path was the error.

The abort is a local accident, not a property of the repo

scripts/test_orcaflex_loading.py:18 calls sys.exit(1) at module scope. pytest does not treat SystemExit as a collection error, so the whole run dies with INTERNALERROR> mainloop: caught unexpected SystemExit!.

That sys.exit sits inside an except ImportError: handler guarding import OrcFxAPI. On any licensed OrcaFlex host it never fires — collection completes and the directory-wide write reproduces exactly as the issue describes. The adversarial round demonstrated this with a stubbed OrcFxAPI on PYTHONPATH: 76 collected, 8 errors, no INTERNALERROR, file written. This box is unlicensed, which is the only reason revision 1 saw an abort. Fixing that one sys.exit in isolation would make the repo-root write reproduce everywhere.

Implementation sequence after approval

  1. Stage 0 — triage, no code changes. Run each of the 30 individually and record: items collected, passed, failed, errored, and whether it imports from src/digitalmodel/. Produce a table committed to docs/plans/evidence/ classifying every file as REAL TEST, SCRIPT, or BROKEN. This is the stage revision 1 lacked, and it is the one that prevents deleting tests.
  2. Stage 1 — guards, RED. Two guards in tests/contracts/test_collection_visibility.py (see below). Commit RED and open the PR immediately — quality-gates-by-domain.yml triggers on pull_request, not on a branch push.
  3. Stage 2 — relocate real tests. git mv every Stage 0 REAL TEST into tests/<domain>/, domain taken from tests/DOMAINS.md, and confirm each is picked up by exactly one gate.
  4. Stage 3 — rename the remainder to check_*. Excluding solver_smoke_test.py. Guards go green.
  5. Stage 4 — references, separate commit. The 17 references, with the five files carrying executable invocations verified by running the corrected command.
  6. Stage 5 — solver_smoke_test.py, gated. Do not rename until the deckhand queue repo and the licensed host's scheduled tasks have been swept. If the sweep cannot be completed, leave the file alone and record why — it ends in _test rather than beginning with test_, and a guard exemption with a comment is preferable to breaking an unattended lane.
  7. Stage 6 — examples/, .codex/, .gemini/ (G4). Confirm no real test lives under them, then add to the root collect_ignore. Note: those trees reach their contents through a symlink, so find reports 0 and find -L reports 14.

All stages land in a single pull request. scripts/** maps to no CI domain — detect_touched_domains.py lists only scripts/capabilities/ and scripts/ci/detect_touched_domains.py — so a rename-only PR would dispatch zero shards and go green having run nothing. Stage 1's guard lives in tests/contracts/, which does dispatch, and that is what keeps the PR honest.

TDD test list

  • test_no_script_is_named_like_a_test — no file under scripts/ matches any pattern in the live python_files, except an explicit, commented exemption list. The exemption list must be asserted fully consumed, so a stale entry cannot mask a new offender.
  • test_no_module_scope_exit_under_scripts — no sys.exit, bare exit, or os._exit call is reachable from module scope. Reachable means descending through If, Try (including handlers), With, For and While bodies, excluding only if __name__ == "__main__" blocks and function/class bodies. A shallow tree.body scan finds zero of the three real offenders, and a sys.exit-only matcher misses 17 bare exit() call sites. The guard must carry a known-positive control proving the descent works.
  • Both carry the vacuity guards #1977 established: assert pytestconfig.inipath.name == "pytest.ini", assert the pattern list is non-empty, assert the candidate file set is non-empty, and include a known-positive control.

Acceptance criteria

Revision 1 offered two criteria that could not fail. Both are replaced.

  1. Per-file, not whole-tree. For each of the 30, pytest <old-path> before and pytest <new-path> after must collect and pass the same items. Replaces revision 1's whole-tree node-ID diff, which was guaranteed to read "0 removed, 0 added" regardless — collect_ignore means no scripts/ node IDs exist in the baseline, so it would have reported success even if the rename had buried 500 passing tests.
  2. Filesystem snapshot, not git status. Before and after a full collection, compare complete directory listings (or find -newer against a stamp file), excluding .git/. Replaces revision 1's git status --porcelain assertion, which is blind by construction: collection creates temp_test_conversion/ and temp_workflow_test/, both matched by .gitignore, and the index stays clean while the tree is dirtied.
  3. pytest scripts/ collects 0 items and exits without INTERNALERROR — verified both with and without OrcFxAPI importable, since the unlicensed path is what masked this defect.
  4. Every file Stage 0 classified REAL TEST is collected by exactly one gate after relocation, verified through parse_domains rather than by reading YAML.
  5. Both guards demonstrably RED at Stage 1 and GREEN after Stage 3, provable from CI history.
  6. git log --follow traverses every rename and relocation.
  7. engine.py:834's solver_smoke_test dispatch still resolves, and base_configs/modules/solver_smoke_test/ is untouched — asserted by running the engine path, not by grep.
  8. Domain test aggregate and Run Quality Gates green with zero failures, in a single PR carrying all stages.
