#1983 implementation plan: 30 scripts wearing a test name

Issue #1983 · branch plan/1983-collection-side-effects · base 2c4a556a · drafted 2026-08-09 · status: awaiting user approval

This plan opens by withdrawing the issue's headline, which I wrote. #1983 claims that "collecting scripts/ writes a file into the repository root". That does not reproduce on main. The write is real, but it is reachable only by importing or executing the module directly — never through pytest collection, because collection aborts earlier for an unrelated reason. The stray file that prompted the issue was almost certainly produced by a delegated session running the script directly, and I attributed it to collection without testing that attribution. The reproducible defects are set out below and are a different, sharper problem.

Goal and authorization boundary

Thirty files under scripts/ are named test_*.py or *_test.py. None of them is a test. They are analysis and smoke scripts wearing pytest's collection prefix, and because pytest collects by importing, pointing pytest at that directory executes them.

  • G1 — pytest scripts/ will fail cleanly or not at all. It will never crash the runner.
  • G2 — files that are not tests will not carry a test name. This is the root cause; everything else is mitigation.
  • G3 — a guard will make the naming property enforceable, so the class cannot silently return.
  • G4 — the status of examples/, .codex/ and .gemini/ will be decided rather than left ambiguous.

Boundary. This plan will not rewrite what any script does, will not delete scripts, and will not attempt to convert any of them into real tests. It changes names, guards and collection status only.

TDD test list

Assertions are on properties, never counts. "30" will be wrong the moment a script is added or removed.

  • test_no_script_is_named_like_a_test — for every file under scripts/, assert it matches no pattern in pytestconfig.getini("python_files"). Fails today naming 30 files.
  • test_no_module_scope_sys_exit_under_scripts — AST assertion that no file under scripts/ calls sys.exit at module scope. This is the defect that actually crashed the runner, and it is worth guarding independently of naming: a module-scope sys.exit raises SystemExit, which pytest does not catch as a collection error.
  • Both carry the vacuity guards established by #1977: assert pytestconfig.inipath.name == "pytest.ini", assert the pattern list is non-empty, assert the candidate file set is non-empty, and include a known-positive control proving the matcher is live. Measured during #1977: with the ini key absent, getini silently returns pytest's built-in default and the test passes having checked nothing.

Acceptance criteria

  1. pytest scripts/ --collect-only collects 0 items and exits without INTERNALERROR.
  2. Node-ID diff across the change: 0 removed, 0 added. These files were never contributing tests, so a rename must move nothing. Baseline from a separate clean worktree.
  3. The working tree is unmodified after a full collection — no phase_convention_test_results.txt, no other artifact. Asserted by git status --porcelain being empty after the run.
  4. Both guards demonstrably RED at Stage 1 and GREEN at Stage 2, provable from CI history.
  5. git log --follow traverses every rename, so history is not severed.
  6. Domain test aggregate and Run Quality Gates green, zero failures across the rollup.
  7. The single live reference in src/digitalmodel/solvers/smoke/workflow.py resolves after the rename — verified by executing that path, not by grep.
