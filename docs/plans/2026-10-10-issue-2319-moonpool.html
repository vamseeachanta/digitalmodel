Mesh-level moonpool cutout

Authority: owner board card A01 and issue 2319, under item 4A. One isolated branch will supply one draft PR. No item 3 dependency will be introduced.

The API will accept a PanelMesh and a rectangular or circular footprint. It will return a new mesh and a report with a cutouts list. Coordinates will use metres, keel below a specified waterline. Half-hulls with y symmetry will be expanded before cutting. Other symmetry planes, footprints outside the flat bottom, intersecting existing cutouts and invalid dimensions will be rejected.

The implementation will subtract a convex footprint from intersected planar bottom panels using half-plane clipping. A circle will use at least 64 segments (area error below 0.5%). Retained fragments will be triangulated in four-index PanelMesh storage; walls will be genuine quads. Shared edge subdivision will prevent hanging nodes at seams. Wall normals will point into the moonpool water. Per-panel moonpool flags and cutout specifications will live in mesh metadata and the returned report.

Tests will precede production code: independent signed-tetrahedron volume, analytical footprint area times draft, incidence and directed-edge checks, wall normals and report/flag checks. Cases will include a closed box, non-grid-aligned rectangle and circle, and generated flat-bottom monohull. Only waterline boundaries will remain open; capping those for the test will establish watertightness without adding a diffraction lid.

Focused and existing hull-library tests will run, followed by repository Ruff lint and a broader suite attempt. Defect-hunting plan and artifact review will use frozen packets. Gmsh, BRep booleans, lid treatment, screening changes and column-pontoon generation will remain outside scope.
