Proposed process collection

  1. The pure population reconciler will accept an optional sorted, unique, bounded list of required relevant positive process identifiers. Each stage's relevant closure will include those identifiers, even when absent from that stage. Existing absence-only callers will preserve their current default behavior.
  2. The active collector will capture complete identity inventories A, B and C using the existing Windows identity enumerator: at selection, before detail reads, and at final stability. Parent maps will be derived from those observations, never reconstructed from older identities.
  3. The initial selected closure will be required relevant throughout reconciliation. Complete unrelated additions, exits and parent changes will be retained as observed events. New solver or message-passing processes, new descendants of relevant processes, selected disappearance or reparenting, identity drift, process identifier reuse, and incomplete changed identities will refuse.
  4. Existing executable, argument, working-directory, script and final selected-state checks will remain. Final selection membership will equal initial membership. Existing process-snapshot-2 initial_inventory and coverage will continue to describe inventory A; observed_inventories and population_check will add explicit A/B/C evidence without changing the meaning of existing fields. Both success and failure will retain completed inventories, parent maps, transition events and failed stage where applicable. Collection failure before inventory A will explicitly identify that missing observation.

Proposed retained-preparation accounting

A reviewed configuration will declare abandoned preparation roots, original configuration identities, and complete file membership with digests. Admission will require exact typed zero-launch/zero-adapter-call refusal evidence, settled reservation, matching case and output root, and absence of the next-attempt ledger. Unknown or contradictory execution evidence will refuse.

The declaration will include a bounded campaign preparation namespace and a fixed campaign membership rule. Admission will enumerate that namespace read-only and require exact equality between observed prior preparation roots and declared roots; current fresh output and the separately bound coarse predecessor will be handled explicitly. It will refuse ambiguous membership, incomplete enumeration, undeclared retained preparations and redirected paths. Configuration omission alone will never make retained bytes disappear.

Existing cumulative_storage will receive the coarse predecessor and all verified abandoned roots. Its containment, overlap, file-type and inode checks will remain. Inventory digests and membership will be rechecked at existing source/configuration binding checkpoints. The 1 GiB capture allowance and 2 GiB free-space reserve will remain fixed. The known preparation will contribute all 535,345 bytes, including its final refusal receipt.

Test-first validation

  • Tests will first reproduce unrelated addition, exit, transient middle-stage process and unrelated reparenting refusals, then verify retained events after correction.
  • Refusal tests will cover relevant process additions, benign-named descendants, selected loss or reparenting, identifier reuse, changed executable/name/creation identity, incomplete changed rows, malformed required identifiers, and selection mismatch.
  • Stage-read failures will retain completed prior inventories and the failed stage. Success will contain exactly three inventories and final coverage arithmetic. Existing absence tests will remain unchanged.
  • Accounting tests will cover omitted roots, extra/missing/changed files, redirects, overlaps, hardlinks, nonzero or uncertain launches, unsettled ownership, next-attempt ledger residue, incomplete namespace enumeration and exact known retained byte totals.
  • Regression, legal scanning, source-inventory checks and independent exact Claude code/artifact review will precede any new runtime/configuration. A fresh output root will be used only after complete accounting and review. Live admission will still enforce licence, capacity, ownership, freshness and stop criteria.

First review disposition and implementation sequence

The legacy _population function and its two call sites will be removed; no whole-host superset test will remain at those sites. The three-observation reconciler will replace that logic. The existing identity enumerator's within-observation consistency check will remain fail-closed: the proposed reconciliation will apply only between three successfully completed observations. Pre-yield disappearance or within-observation instability will never become evidence of unrelated churn. An enumeration failure will retain every completed prior stage and identify the failed stage; a failed first stage will explicitly contain no completed inventory. Partial identities from an unsuccessful observation will not be represented as complete.

Unreadable executable identity will remain a refusal for added, removed or reparented processes. An unchanged protected process with an unreadable executable will retain existing behavior. The proposed weaker admission of incomplete changed identities will not be adopted. Tests will distinguish stable protected rows from changed incomplete rows. Required selected identifiers will be positive; observed Windows inventory rows may include identifier zero under the existing inventory domain.

All retained review findings will require explicit recognized severity labels. Following source tests and exact code review, all changed source files will be committed together; source_files and source_revision will be regenerated from that immutable revision. A fresh runtime bundle will preserve the frozen physical inputs while recording new runtime_sources and runtime_inventory_sha256. Current-source retained replay will precede an exact review of the fresh configuration and runtime evidence. No old configuration will be reused after source changes.

The exact retained refusal and readback membership manifest will accompany review. The observed 535,345-byte total will be derived from the retained files; it will be a test fixture expectation, never a production accounting constant. Existing ORIGINAL_BYTES will continue to describe only the separate original zero-load capture.

Parent maps will explicitly be row-derived views of each successfully completed inventory, not claims to retain the full underlying operating-system table. The current enumerator's consistency checks will remain; its pre-yield disappearance limitation will be recorded. Pure map validation will serve caller consistency, not independent measurement. No removed process with unknown identity will be admitted through a failed observation.
