Outcome and evidence

The existing pressure driver will be extended to execute exactly one intermediate-mesh case, ocv-t60-p10-n8, without reopening either consumed predecessor. The source will reuse the reviewed read-only coarse replay at revision 9d30fbff34424b8e516c3e413f542cdef00202e9. The completed coarse case will remain diagnostic CONTINUE with one failed radial-stress criterion; it will not be described as PASS. A successful intermediate solve will be retained in the private authoritative dataset and exposed through the existing matrix with explicit provisional or incomplete status. Numerical qualification will remain unsupported by execution completion alone.

Resource intelligence will use cylinder_pressure_resume.py (currently fixed to ordinal 2), cylinder_pressure_admission.py (exact source/config/review gates), cylinder_pressure_journal.py (exclusive one-shot ledger), cylinder_pressure_resources.py (cumulative allowance and reserve), cylinder_pressure_capture.py (coarse-only at the published baseline 9d30fbff; the delegated extension will be reviewed in the integrated change set) and cylinder_refinement_replay.py (pinned original numerical recovery). The fixed geometry/reference/decks will not be regenerated. No new standards-derived constants will be introduced. Actual retained campaign evidence, rather than an external document search, will establish this operational continuation.

The interface contract will be: PressureJournal(parent, parent_sha256, *, writer=write_exclusive, ordinal=2, predecessor=None); cumulative_storage(original_root, parent_claim, output_root, ledger_paths, reservation_path, free_bytes, *, prior_capture_roots=()); capture_pressure(case, directory, execution, *, runtime_profile, capture_case_id=CASE_ID). Main-owned contract tests will verify caller keywords and these retained fields. Workers will not change preflight's _now interface.

Parallelism will end at a mandatory freeze barrier: all workers will report completion and stop edits; the main lane will integrate and test, obtain exact code review, make one scoped source commit, create one current runtime/configuration, obtain exact configuration review, then admit execution. Any source change afterward will invalidate that configuration and require regeneration and review. The plan and code review are distinct stages.

Admission and predecessor algorithm

  1. A common scope validator will accept only exact coarse ordinal-2 or intermediate ordinal-3 descriptors, each with one maximum attempt, diagnostic-only qualification and capture-only execution. Intermediate admission will require a distinct schema version and an explicit predecessor descriptor. Legacy coarse calls will retain their defaults and exclusions.
  2. The new predecessor validator will bind the original campaign parent and exact ordinal-2 invocation, consumed claim, terminal record, original outcome, execution and capture files. Fixed historical digests will prevent substitution. Paths will match the original campaign stem and the output directory declared by its consumed claim. Execution will require successful containment, finalized streams, zero remaining owned processes, no timeout or pending settlement, and released reservation. Original historical capture status will remain unchanged.
  3. Admission will retain existing zero-control lineage and frozen 21-artifact checks. Before any new claim, the production driver will freshly derive all 64 zero-control checks and invoke the pinned coarse replay from the retained private dataset. Coarse replay will reproduce exactly the historical 63 values, reaction and 22 checks, with CONTINUE and no qualification. The new descriptor will bind its dataset root, original frozen runtime root and observation file; that observation's hardcoded digest will remain authoritative.
  4. The new source inventory and configuration will be committed and independently reviewed at exact bytes. The copied runtime manifest will bind current sources while preserving every frozen deck, reference and criterion. Fast pre-launch binding checks will include the consumed predecessor records and every coarse replay input, so post-review changes will refuse. A diagnostic software reviewer identity will not be represented as a human engineering checker.

One-shot execution and storage

Both pressure scopes will require a non-null reviewed resource descriptor: either the existing version-2 active computational-fluid-dynamics family binding or the explicit absence route defined in the resource-absence addendum. Raw null and version-1 bindings will remain refused. The absence route will request no process exemption and will require fresh empty blocking observations at initial preflight, before launch and after claim. Regressions will refuse intermediate scope paired with either a version-1 or null binding. Case identity, ordinal, consumed counts and the numerical-not-evaluated reason will be threaded through empty/refusal outcomes as well as successful capture. Frozen case selection will match the exact case ID, not a positional assumption.

PressureJournal(..., ordinal=2, predecessor=None) will preserve old calls; ordinal 3 will require the pinned original-stem ordinal-2 consumed claim. Only integer ordinals 2 and 3 will be accepted. The original campaign stem will name ordinal-3 invocation, consumed-attempt and terminal siblings. Any existing matching sibling, including partial residue, will refuse restart. The predecessor claim will be rechecked before durable state transitions. A terminal recheck or write failure will be retained as an incomplete result; the independent outcome write will still be attempted and the driver will return a failure record rather than lose the consumed-attempt disposition. A failure after consumption will not enable a retry.

The existing 600-second invocation budget, 300-second solver timeout, observation-age limits, postclaim timing, exclusive reservation, resource classifier, containment and settlement rules will remain in force. The intermediate output directory will be new and exclusively created. Fresh license/process/capacity observations and a non-claiming measurement of the enlarged postclaim path against its five-second limit will be required; unrelated computational-fluid-dynamics controls will remain untouched.

cumulative_storage(..., prior_capture_roots=()) will count explicit prior capture roots as well as zero-control originals, parent claim, current output, owned ledger siblings and reservation. The intermediate call will include the coarse output tree and both pressure-ordinal ledger sets. Existing overlap, identity, redirect, fixed original-byte, one-gibibyte allowance and two-gibibyte reserve checks will remain. Prior-root labels will use prior-{n}/ and will never share the original/ namespace. Cross-tree hardlink aliases will refuse accounting. Accounting will remain a point-in-time observation, not a filesystem quota.

Storage planning will use the observed zero capture of 10,174,192 bytes and coarse tree of 2,021,786 bytes, plus a 64-mebibyte provision for intermediate output. This provision will be an estimate, not measured intermediate evidence or a replacement for live accounting. Fresh total/headroom and free-space checks will precede claim. All three output trees will be non-nested siblings. Driver ledger enumeration will explicitly include ordinal-2 and ordinal-3 siblings only. One mebibyte will mean 1,048,576 bytes and one gibibyte 1,073,741,824 bytes.

Capture and result intake

capture_pressure(..., capture_case_id=coarse_id) will preserve the old default. Explicit intermediate selection will require its exact frozen deck, token, model counts, runtime profile, native diagnostics and retained process streams. Native filenames will be derived from only the two admitted case IDs. The intermediate reason will state numerical assessment not evaluated, rather than inherit the historical coarse parser-unvalidated reason. Accepted numerical values will remain empty and engineering qualification false at capture time.

After settlement and original evidence retention, the existing strict numerical validators will assess the intermediate output offline against the unchanged reference. Unsupported native pagination or grammar will produce an explicit incomplete result and an offline remediation task; it will not trigger another solve. Matrix intake will reuse existing stable case/run IDs, owning manifest and versioned matrix workflow. If an existing intake schema cannot express ordinal 3, the case will remain explicitly unattempted in that view until a reviewed extension publishes the actual execution metadata; no fabricated row or competing result store will be created. All received native files will be copied, hashed, committed privately and checked by fresh remote readback before backup is claimed.

Tests, reviews and stop criteria

The 29 historical source pins in the coarse recovery observation will be compared with the exact change set before integration. The planned pressure, journal, resource, capture, preflight and new modules will not intersect that table; the criteria, numerical-parser files and src/digitalmodel/ansys/__init__.py will not be edited in this slice. Actual retained replay will run before source freeze and again before admission. An unexpected intersection or replay refusal will block execution without repinning history.

With no evidence errors, the intermediate numerical evaluator will return CONTINUE by the frozen coarse/intermediate construction, even when individual accuracy checks fail. Evidence errors will instead produce INCOMPLETE with their exact errors and empty checks; no receipt will relabel that branch CONTINUE. Every intermediate diagnostic receipt and matrix/checkpoint presentation will disclose the failed_checks list and count. CONTINUE will never be represented as numerical PASS; three completed attempts will still leave the four-case campaign incomplete, with refinement criteria unevaluated until the fine mesh is available.

The existing review transport will be preserved: findings will be strings with explicit leading severity labels, with absent, ambiguous or unknown labels refused by admission. A regression will reject an unlabelled prose blocker even under an overall MINOR verdict. The exact configuration review prompt will require those labels; no captured finding will be reworded by the operator. A formatting refusal will remain a refusal, never authority. Structured severity migration will remain outside this bounded extension; the conservative existing parser will not be weakened to enable execution.

The configuration reviewer will be instructed that each leading label must represent the finding's maximum severity. A label/body contradiction will require explicit disposition and will not be treated as clearance merely because the transport parser accepts the label; the checkpoint will record this prose-classification limitation.

Tests will precede implementation. New refusal tests will cover wrong scope/schema, missing or altered predecessor records, wrong campaign/output binding, incomplete settlement, failed zero replay, altered coarse evidence, duplicate/partial ordinal-3 records, frozen-input drift, late/changed resource observations, launch/retention errors, prior-storage exhaustion/overlap/aliasing and unsupported capture identities. Existing coarse, reservation, resource and capture tests will continue passing. Synthetic orchestration tests will remain labelled; the actual retained coarse replay will run without skipping before native admission.

Independent Claude will review the plan, integrated source and exact production configuration with a NON-APPROVE default. Supported blockers will be resolved before native execution. A final fresh preflight will either admit the one intermediate attempt or provide a concrete technical refusal; no routine user permission will be requested. The checkpoint will report native attempts/completions and matrix-row deltas separately from test totals. The fine-mesh case, extra runs, numerical-tolerance changes and destructive cleanup will remain outside this slice.
