Solver evidence decimal boundaries

Summary

The bounded correction for issue 2125 makes emitted canonical decimals readable under their receiving contract. It rejects overlong canonical output, replay values outside package bounds, and fixed-width values whose adjusted exponent falls outside package bounds. No result is promoted to qualified use.

Sources and arithmetic

The representation rules are software contracts, not engineering tolerances. Their source is repository revision 6476218e:

  • analysis_records.decimal_text defines ASCII decimal syntax, an input limit of 128 characters and adjusted exponents of magnitude at most 100.
  • analysis_replay.canonical_measurement defines the additional raw limit of 64 coefficient digits and stored exponent magnitude at most 128. Canonical output must remain within the same receiving bounds.
  • cylinder_results.parse_e24 defines the fixed-width E24.16 field and half-quantum q = 0.5 × 10e − 16. This correction preserves that equation.

Expected test strings are derived by moving the decimal point, with the independent arithmetic written in each test docstring. For example, 0.1 × 10−100 = 10−101 falls below the package bound. A positive expansion with two prefix characters, 99 leading fractional zeros and 28 coefficient digits has 129 characters and is refused. The corresponding 27-digit expansion has 128 characters and remains exact. The half-quantum examples are calculated directly from the equation above.

Adversarial checks and limitations

Plan inspection identified three ways a plausible decimal could cross one boundary but fail the next: expanded string length, adjusted exponent and non-ASCII digits. Code inspection additionally identified that a short positive exponent could expand beyond replay's own coefficient limit. Regression cases reproduced each defect before its correction. The correction rejects these inputs rather than rounding or changing their magnitude.

The focused regression run passed 104 tests. The affected-module run (test_analysis*.py, test_cylinder_results*.py and the new boundary module) passed 515 tests, with three existing private-fixture skips. The new module contains 27 representation cases. Ruff passed on the three changed source modules and the new test module.

The broader ANSYS run passed 2,416 tests with 410 existing platform or private-fixture skips and two licensed-solver tests excluded from execution. NumPy, pandas and psutil were constrained to the versions declared in pyproject.toml. An earlier unconstrained environment failed three unchanged weld-assessment tests because NumPy lacked trapz; the constrained run resolves those failures without a source change to that module.

Existing stored evidence is not rewritten. A previously accepted value outside the receiving contract now refuses; its original bytes must remain retained. No licensed solver is started or queried, and no native qualification is established by these synthetic tests. Exact independent reciprocal review is outstanding and is not replaced by the local inspection.
