Physical-zero qualification plan

The change will provide a diagnostic assessment for rotational radiation-zero candidates under issue 2112. It will retain NOT_EVALUATED because existing run records will not establish independent geometry and extraction authority.

Scope and method

  1. Slice 1 will assess exact-zero rotational rows and columns from existing matrix-set objects. Unknown sources, all-zero arrays, invalid axes and nonfinite coefficients will remain unqualified.
  2. Slice 2 will compare model, body, origin, axes, native-output and coefficient bindings supplied independently of the proposed declaration. Matching claims will establish consistency only.
  3. Slice 3 will expose serializable missing-evidence reasons and an executable synthetic example. Every result will remain NOT_EVALUATED; comparator correlations, refusals and coverage will remain unchanged.

Implementation will add physical_zero.py, contract tests, an example and an HTML guide. Existing schemas, extractors, catalogues and comparator policies will remain unchanged.

The source will be Orcina, OrcaWave online help, “First-order equations: The radiation potential” and “Results: Added mass and damping”, undated edition accessed 2026-10-20. The rotational boundary term will be interpreted as (x × n)j; the coefficient relation will be Aij − 𝑖 Bij/ω = ρ ∫ nvel,i φj dS, where 𝑖 denotes the imaginary unit. The source will not be treated as independent validation of a particular geometry.

No empirical coefficient or acceptance tolerance will be introduced. Exact zero will designate an observation only. Sampling adequacy and near-zero acceptance will remain the comparator's responsibility.

Adversarial plan assessment

The assessment will reject copied or stale bindings as authorization: hashes will identify bytes, not establish causality. It will never convert consistency into qualification. Tests will attempt mismatched model, body, origin, axes, native output and extracted arrays, incomplete declarations, placeholder sources, all-zero arrays and nonfinite data. Synthetic expected values will be derived explicitly in test docstrings.

A separate provider review will remain pending for the draft change. No other assistant or licensed solver will be invoked.

Verification and remaining scope

New module and example tests, actual matrix-schema interoperability tests, Ruff on added Python files, structure checks, LFS attributes and outgoing-text checks will be run. A reviewed geometry authority, independently recorded run-to-extraction lineage and a physical-mode validation procedure will remain prerequisites for any future exemption in issue 2112.
