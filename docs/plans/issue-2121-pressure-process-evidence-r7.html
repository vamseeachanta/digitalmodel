Proposed pressure process evidence correction, revision 7

Under issue 2121, this bounded correction will support the existing ordinal-2 capture-only N4 pressure diagnostic. It will supersede earlier process-evidence proposals. It will preserve original run and case IDs, CFD processes and controls, source evidence, one execution owner, fixed resource and numerical stop criteria. A software review will not qualify numerical results.

Collection and classification

The v1 route will remain available for historical callers, with the same complete nominated-descendant closure correction as v2. Pressure admission will use the validated approval.scope, because ProductionPreflight receives the nested operational configuration; a non-null pressure CFD binding will require cfd-process-binding-2. Null will grant no process exemption. The v2 collector will select all solver/MPI seeds, nominated process identities and their complete descendant closure. Any additional unpinned descendant will remain visible and prevent preservation of the bound family.

V2 rows will retain the eight v1 fields plus cwd and executable_resolved_path. Original argv will remain literal. Interpreter script_sources will bind argv_index, path, sha256 and resolution_basis. The wrapper-source gap will be resolved by treating observed uv forwarding parents as launchers rather than Python script interpreters. Nominated forwarding parents will skip all script resolution and emit empty script_sources, including TEMP-relative arguments. Interpreter children will resolve every script argument from its absolute argument or observed interpreter cwd; unsupported relative escapes and inline/module invocation will refuse.

The supported forwarder will require the observed uv kind02 resource, bounded PE parsing without loading the image, exact embedded target, parent/child creation identities, direct ancestry, identical argument tails and independently read alias/resolved target bytes. The supported installation will require the single declared immediate-parent interpreter junction. Other junction positions and layouts without that junction will refuse; no generalized adapter compatibility will be claimed. The pure classifier and collector will enforce that same position. Current junction identity and raw target will be retained and rechecked, with no historical loaded-byte or binary-build-attestation claim.

Regular non-alias, non-forwarding process images will permit hard links explicitly and retain their link count. Source, launcher and interpreter alias/target reads will retain strict single-link checks. Hard-link allowance will never relax redirected-path refusal. Every declared path will receive an independent read and identity/content recheck; cache reuse will preserve its original declaration. A top-level declared_file_observations list will retain copied metadata and digests without executable payload bytes.

Snapshot time will precede collection. Missing, inaccessible, changed or post-start-created selected processes will produce explicit incomplete error evidence. Coverage will account for selected rows plus errors without overlap. Classification will require full pin/role/topology/forwarder equality and will return UNKNOWN for incomplete observations; no partial family will be preserved. This classification will establish only conditional structural relationships, not licence, capacity, operational authority or native readiness.

Owner facts and preflight integration

The operational cfd_owner_evidence id/path/digest will match binding.owner_reference. The existing pressure-current-resource-facts-1 receipt will remain the factual source. The resolver will verify its fixed controller configuration, actual integer schema1, current script/configuration digests, interpreter ancestor sources resolved by absolute argument or observed interpreter cwd (not launch-time cwd), case branch, retained queue relationship and exact recorded family. The existing 126-member family and 60-rank/60-console restriction will remain specific to this receipt; changed family/branch conditions will refuse with a stale-receipt disposition. No person, new authority store or historical source execution will be invented.

All three _bindings calls, including production_phase2 after claim, will recheck the same fixed receipt/configuration/source files. Controller-state.json will never be read or hash-gated by the resolver. Its historical fields will not be used as a heartbeat condition. Owner reads will use the redirect-refusing path check and a four-MiB limit before opening and during bounded read, followed by digest verification. Duplicate/nonfinite/oversized/nested JSON will refuse; ordinary historical decimal metadata will be preserved without becoming engineering input. Deferred imports will avoid an eager preflight/admission dependency cycle.

Verification and native boundary

Negative tests will cover the additional controller descendant, mismatched alias position, hardlinked image versus strict source/alias policy, malformed PE, missing/changed source, late-created processes, bounded owner reads and stale family. Actual read-only installed-file tests will establish current junction and image link-count facts. Actual fixed source readbacks will be distinguished from synthetic missing process pins. ProductionPreflight and production_phase2 will be exercised together to establish three resolver calls and no postclaim licence query.

The complete preclaim code interval will be measured from the capacity final sample and snapshot start through _ages(...,20), including licence observations, preflight serialization/write, case directory/copy/fsync/readback and storage traversal. Delay-injection tests will verify that write/copy/storage time cannot escape the bound. The subsequent claim-to-launch interval will retain its five-second limit and all retained-observation limits. Those tests will not establish actual host timing: fresh complete process binding, new source/runtime inventory, actual production configuration, exact independent artifact review, real preflight timing, licence/capacity/storage and ownership checks will precede any native invocation. No timing limit will be relaxed to admit a slow observation.

Current source and this plan will receive independent exact Claude adversarial review. Blocking findings will be remediated before adoption. Then a new runtime/replay descriptor will bind the reviewed source; earlier preparations will remain preserved. Only the fixed ocv-t60-p10-n4 ordinal-2 capture will proceed when all prerequisites pass. Original outputs will be retained and verified in private digitalmodel-data, with existing matrix references and explicit provisional/not-evaluated states. No result will become reusable merely from execution or user authorization.
