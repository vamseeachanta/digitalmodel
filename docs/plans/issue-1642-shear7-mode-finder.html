Shear7 mode finder implementation plan

The implementation will port the result-reading behavior of ModesFind.m and FindModes.m (2009), inspected read-only under the authority of issue 1642. No restricted source files or analysis data will be published.

Scope and sequence

  1. The first slice will parse the above-cutoff mode list and the first modal excitation region into immutable records. Regex markers will tolerate spacing and capitalization. Missing markers, malformed rows and truncated tables will raise errors rather than produce plausible empty results.
  2. The second slice will process sorted directory inputs without changing the working directory and reproduce the ordinal NodeList cross-tabulation with zero padding. Explicit zero-mode cases will produce empty lists.
  3. The third slice will expose an installed command and module CLI, export CSV, JSON and YAML, and document a synthetic worked example.

Files and method

The code will live in the current installable package at src/digitalmodel/subsea/viv_tools/, rather than recreating the obsolete hyphenated source tree. The entrypoint will be declared in pyproject.toml. Tests will live in tests/subsea/viv_tools/; documentation and synthetic inputs will live in docs/domains/viv/ and examples/viv/.

No physical equations, coefficients or acceptance limits will be introduced. The algorithm will read counts and identifiers from input. For each file column, each row will equal the correspondingly listed node, or zero beyond that list's length. This indexing rule and first-mode selection will follow ModesFind.m (2009), NodeList assignment and output loops. The mode count will follow its above-cutoff sentinel, rather than the potentially-excited modal table.

Validation and adversarial plan assessment

Tests will precede implementation. Synthetic expected values will be written out independently in test docstrings. Tests will cover first-mode selection, ragged columns, repeated calls, zero modes, whitespace, malformed data, missing sections, CLI discovery, each export format and readback. Available archive outputs will be compared read-only to their saved ExcitedModes.dat and PowerInRegion.dat counterparts; only aggregate results will be reported.

The defect assessment will challenge accidental selection of potentially excited modes, unioning all modal regions, silent truncation, stale column padding, output overwriting input, empty discovery and changes to process cwd. The original algorithm's first-mode limitation will remain explicit. No independent provider verdict will be claimed; independent review will remain pending before merge.

Required checks will include the new module tests and Ruff on touched Python files, direct file checks, an added-line publication scan, LFS attribute checks and a cleanup audit. Tests will run against the uncommitted tree.

Limits and later work

Support for other undocumented output dialects and extraction of every modal region will remain outside the compatibility port. No solver will be invoked. Public manual access failures will be recorded without inferring unseen content.
