Deliverable and API

inputs.calculation_type: DNV_RP_B401_offshore will accept a mutually exclusive inputs.components[] extension. Top-level flat-mode structure, environment, and design life will be rejected in component mode rather than required as dummy values. Each component will carry a unique name/type, positive design life, local environment, and locally unique zones. Results will be nested by component so repeated zone names cannot collide.

Each designed zone will name one physical anode-family ID. Each family will name its host component and installed count. A family may protect one or more components through allocations[]. A single target will default to a capacity fraction of 1.0; multiple targets will require explicit positive finite fractions whose sum is within an absolute tolerance of 1e-9 of 1.0. The allocation target set will have to equal exactly the set of components whose designed, positive-demand zones reference that family; missing or extra reciprocal mappings will fail. Per-component mass and current-output checks will use only that target's allocated share, while the family check will compare pooled demand against the physical family once. Required/allocated values will belong to protected components; installed/hosted mass and count will belong to host components. Overall hosted totals will equal the sum of physical families exactly once, and overall allocated fractions will equal one per family.

inputs.electrical_continuity[] will contain explicit undirected component pairs and an available_for_years interval. A component's own availability will equal its declared design life. Self-protection will need no edge. For cross-component protection, edges and hosts that do not cover the protected component's life will first be removed; a deterministic shortest path will then be selected from the remaining graph, with lexicographic tie-breaking. Unknown endpoints, self-edges, reversed duplicates, non-positive or non-finite intervals, disconnected paths, and insufficient-life hosts/paths will fail closed. Cycles and multiple paths will be accepted only when deterministic path selection produces the same reported result.

Demand will belong to the protected component: its seawater temperature, zone exposure/depth, coating, and design life will control current and mass. Anode resistance/electrochemistry will belong to the physical host: the host's anode environment, electrolyte resistivity, and anode surface temperature will combine with the family's material/geometry/utilization. Duplicate family environment/resistivity/temperature fields will be rejected in component mode so precedence cannot be ambiguous.

Zone coating will use either the existing B401 coating_category, coating: {basis: f103_linepipe, edition, system, concrete_weight_coating, operating_temperature_C}, or coating: {basis: f103_field_joint, edition, system, infill, operating_temperature_C}. The F103 edition will be mandatory and limited to supported table editions; the system/infill pair will resolve through the existing edition-aware lookup, including mandatory 2019 infill choices. Reports will show the selected system, concrete/infill choice, the table's compatible-linepipe description, operating-temperature basis, tabulated maximum temperature, applicability result, and Table A.1/A.2 (2010) or Table A-1/A-2 (2019) citation. An operating temperature above a tabulated limit will fail closed. A blank tabulated limit will produce NOT EVALUATED applicability and the overall coverage failure described below rather than an inferred limit. B401 will remain the current-density and anode-design basis.

Every zone will carry an explicit CP disposition. designed will require positive demand, a family, and reciprocal allocation. no_cp_demand will be allowed only when all three cited B401 phase densities calculate as numerical zero; it will prohibit a family/allocation and remain coverage-neutral. excluded_self_protected will require a rationale, retain its area, prohibit a family, and be marked EXCLUDED rather than zero or PASS. not_evaluated will require a rationale, prohibit a family, and override overall status to FAIL with governing case coverage:not_evaluated and no numerical ratio. Thus true zero, exclusion, and missing evaluation will remain distinct, and none can create an unused-family reference.

Calculation and output contract

  1. Component zones will be converted to B401 structural zones under nested component identities, using protected-component temperature and life.
  2. Demand will use B401 Sec. 7.4 Eq. 1, I=A·i·f. Coating factors will use the selected cited B401 or F103 linear constants.
  3. Each allocation will contribute I_mean·t to its physical family. Mass will use B401 Sec. 7.7 Eq. 2, M=Σ(I_mean,c·t_c)·8760/(u·ε). Family counts will be the maximum of pooled mass, initial-output, and final-output counts. Per-component required counts and allocated-share checks will remain visible without being summed as physical anodes.
  4. Anode current output will use B401 Sec. 7.8, I_a=ΔE/R_a, with Table x-7 resistance and Table x-8 utilization through existing cited helpers.
  5. A new cited kernel in _kernels.py will calculate mass from finite non-negative ampere-years; the existing single-life mass kernel will delegate to it. The component route will sum each protected component's I_mean·t and will not implement formula arithmetic outside the kernel.
  6. For allocation fraction f, installed family mass M_i, fresh/final family output I_ai/I_af, and component requirements, the component ratios will be M_req/(f·M_i), I_initial/(f·N·I_ai), and I_final/(f·N·I_af). Allocated mass and both allocated outputs will reconcile to the physical family totals within the same 1e-9 absolute tolerance. Each protected component will report these values and its governing family/case/ratio. Each host will separately report physically hosted family IDs, installed count/mass, and output.
  7. Overall totals will sum physical families once. Governing selection will first choose any coverage failure, then the largest allocation/family-pool ratio, then allocation before family-pool, component/family name lexicographically, and fixed case order mass, initial, final. This will keep results deterministic and will prevent pooled surplus from overriding an explicitly insufficient allocation.
  8. The standard anode-design report will select component layout through an explicit result-mode marker before the existing family layout. It will add component life/environment, nested zones and dispositions, protected allocations, hosted families, continuity paths/lives, family pool checks, totals/invariants, governing case, F103 applicability, and citation tables.

Verification and risks

Focused cathodic-protection and reporting tests, touched-file Ruff and mypy, import smoke, adversarial code review, identifier/path leakage scan, private comparison readback, and the pre-completion cleanup audit will precede the local commit.

  • F103:2003 coating tables are not implemented; the route will reject that edition rather than relabel later-edition values. Private source rows dependent on F103:2003 coating constants will be marked unsupported/not evaluated. Source totals that depend on those rows will be labelled diagnostic, partial-input, and non-reproducible—not regression acceptance. Only edition-compatible B401 rows, topology, allocation behavior, and resistance equations will be eligible for numerical regression comparison. Synthetic 2010/2019 coating tests will not be described as source regression.
  • Shared physical families will require explicit capacity fractions for per-component checks. This will be a declared engineering allocation, not a claim that galvanic current cannot redistribute within a continuous pool.
  • TSA or otherwise self-protecting surfaces will be excluded with an explicit rationale, not converted to zero demand; the B401/F103 route will not introduce an uncited TSA model.
  • Private source results will remain comparison evidence, not acceptance or table authority.
