#1977 implementation plan: root-anchored collection exclusions

Issue #1977 · branch plan/1977-norecursedirs-bare-basenames · base 1dcc59c9 · drafted 2026-08-05 · status: awaiting user approval

Goal and authorization boundary

A recursive pytest tests/ run will enter every directory under tests/, or it will fail loudly. Today it silently skips two of them and reports a clean sweep over ground it never covered.

  • G1 — Recursive collection will include tests/scripts/ and tests/docs/.
  • G2 — The top-level scripts/ and docs/ directories will remain excluded, because they hold 35 collectible files that are not tests.
  • G3 — A guard test will fail if any future norecursedirs entry prunes a directory under tests/, so this defect cannot silently return.
  • G4 — Any test that newly surfaces red will be recorded as a pre-existing finding, never as a regression introduced by this change.

Boundary. This plan will change collection visibility only. It will not modify, repair, or delete any test under tests/scripts/ or tests/docs/, and it will not attempt to make pytest . (whole-repo) work — that invocation is broken today for unrelated reasons recorded under Out of scope.

Severity is therefore lower than filed, and the defect is narrower. norecursedirs prunes only during recursion below the paths named on the command line; it never filters a directory passed as an explicit argument. Every CI workflow passes explicit paths, so CI has been running these 218 tests all along. What is broken is the documented developer command: README.md:142, Makefile:23 and AGENTS.md:4 all describe a whole-tree run that silently covers 218 fewer tests than CI does. Local baselines undercount; local and CI disagree about what "the test suite" means.

Why the issue's suggested fix will not work

The issue proposes to "anchor the exclusion to the repository-root scripts/". That is not expressible in norecursedirs. pytest's own matcher, _pytest.pathlib.fnmatch_ex, was called directly against the four candidate directories:

patternprunes tests/scriptsprunes top-level scriptsverdict
scripts (current)yesyesthe defect
./scriptsnonolooks anchored; silently equivalent to deleting the entry
*/scriptsyesyesidentical to the bare form
absolute pathnoyescorrect, but not portable across machines or CI
The most tempting fix is the most dangerous one. A reviewer skimming ./scripts would read it as "anchored to root". It matches nothing at all: because the pattern contains a separator, pytest switches to full-path matching and prefixes */, producing */./scripts, which never matches a normalised path. Shipping it would leave the top-level scripts/ collectible — 8 collection errors — while appearing to fix the issue. This plan will not use it.

Chosen mechanism

Root-only exclusions will move out of norecursedirs and into collect_ignore in a new repository-root conftest.py. collect_ignore entries resolve relative to the directory holding that conftest, which makes them root-anchored by construction rather than by pattern.

# conftest.py (new, repository root)
collect_ignore = ["scripts", "docs"]

# pytest.ini:4 — bare basenames removed, path-anchored entries retained
norecursedirs = .venv .git __pycache__ node_modules htmlcov
                tests/data_systems/data_scraping
                tests/marine_ops/artificial_lift/dynacard/benchmark
                tests/workflows/integration

This combination was measured end-to-end on the clean checkout before this plan was written:

pytest tests/ collects 21,854 node IDs — tests/scripts/ = 177, tests/docs/ = 41, exactly the intended delta. pytest . collects 0 from the top-level scripts/ and 0 from docs/. The scratch conftest.py was then removed and the worktree returned to a clean state.

A partial secondary benefit: pyproject.toml:263 documents its [tool.pytest.ini_options] table as the fallback "if pytest.ini is ever deleted", but that table carries no norecursedirs key at all, so the fallback has never been equivalent. Moving the root exclusions into conftest.py makes those survive independently of which config file is live. The three remaining path-form entries in pytest.ini would still be lost, so this scopes the benefit to root exclusions only — it does not make deleting pytest.ini safe.

A note on wording, because the same imprecision is what this plan criticises in the issue. The three retained entries such as tests/workflows/integration are not root-anchored. fnmatch_ex prefixes */ and fnmatch's * crosses path separators, so they are suffix-matched and would also prune /anywhere/else/tests/workflows/integration. The pytest.ini comment will say "path-form, suffix-matched" rather than "anchored", so the next reader is not misled the way ./scripts would have misled them.

Implementation sequence after approval

  1. Stage 1 — guard test, RED. Author tests/contracts/test_collection_visibility.py and commit it failing. It will assert, using _pytest.pathlib.fnmatch_ex against the live norecursedirs value, that no entry prunes any directory under tests/. On today's config it will fail naming scripts and docs. The RED commit will be pushed so the failure is on the record before the fix exists.
  2. Stage 2 — the fix, GREEN. Add the root conftest.py, edit pytest.ini:4. The guard test will pass. This commit will touch nothing else.
  3. Stage 3 — fallout, separate commit. Capture a node-ID diff against the Stage 1 baseline and run the 218 newly-visible tests. Measurement predicts zero failures. If CI disagrees, each failure will be recorded on the issue as a pre-existing finding with its own follow-on issue, and will not be repaired inside this branch.
  4. Stage 4 — gate ownership. Confirm tests/docs/ resolves to exactly one gate. tests/scripts/ already has one (tests-workflows, .claude/quality-gates.yaml:242) and will need no change.

Stages 1 and 2 are the whole fix. Stages 3 and 4 exist so that the fix and its consequences never share a commit.

TDD test list

All assertions will be on the property, never on a count that drifts as tests are added. A test pinning "21,854" would pass today and mislead within a week.

Revised after adversarial round 1. The guard test as first drafted here was wrong in two independent ways, both found by implementing it rather than reasoning about it. (a) It asserted that no norecursedirs entry may prune any directory under tests/ — but __pycache__ is itself a bare basename and tests/**/__pycache__ exists everywhere, so the test reported 197 offenders even under the corrected config. (b) It was vacuously satisfiable: with the ini key absent, getini("norecursedirs") returns [], the loop body never executes, and the test reports 1 passed while checking nothing — measured, not hypothesised. The corrected property and its vacuity guards are below.

The property, stated correctly: no separator-free norecursedirs entry may prune a directory under tests/ that contains at least one file matching python_files. Path-anchored entries are deliberate and are exempt; directories holding no collectible files are irrelevant. Measured against this property: 3 offenders pre-fix (tests/docs, tests/scripts, and tests/solvers/orcaflex/mooring-tension-iteration/fsts-l015-test-cases/scripts), 0 post-fix.

  • test_no_bare_norecursedirs_entry_prunes_a_collectible_tests_directory — the guard. Fails today naming exactly those 3 directories; passes after Stage 2. It will carry five explicit vacuity guards, each asserted before the main assertion:
    • pytestconfig.inipath.name == "pytest.ini" — proves the live config was actually loaded. Round 2 measured that from outside the rootdir getini silently returns pytest's built-in default ['*.egg', '.*', '_darcs', …], which contains nothing capable of pruning under tests/, so every config-resolution failure would otherwise produce a confident green.
    • Sentinel entries .venv and htmlcov are present in the returned list — a second, independent check that the value is this repo's and not a default.
    • The separator-free entry list is non-empty (currently 5 post-fix).
    • The candidate directory set is non-empty (currently 190).
    • A known-positive control: fnmatch_ex("scripts", tests/scripts) is True, proving the matcher is live rather than silently returning False for everything.
    The exemption list for path-form entries will be asserted fully consumed — every exemption must correspond to a directory it actually matches — so a stale exemption cannot mask a newly-introduced offender.
  • test_top_level_scripts_is_not_collected — assert the root collect_ignore names scripts, and that the directory exists and contains at least one file matching python_files. Guards against the exclusion being quietly dropped once it is no longer in pytest.ini.
  • test_top_level_docs_is_not_collected — same for docs.
  • test_every_tests_subdirectory_is_reachable_by_recursive_collection — enumerate directories under tests/ holding at least one file matching python_files, and assert each contributes at least one node ID to a recursive collect. This is the property the issue actually cares about, stated independently of the mechanism that broke it.
  • test_collect_ignore_entries_exist — assert every root collect_ignore entry names a directory that exists, so a future rename cannot leave a silently dead exclusion the way projects did.

Acceptance criteria

  1. Node-ID diff between pre-change and post-change recursive collects shows 0 removed, and every added node ID lies under tests/scripts/ or tests/docs/. Stated as a property, not as the literal 218 — that count grew from 124 to 218 between this issue being filed and this plan being written, and pinning it would make the criterion wrong within a week. Baseline captured from a separate clean worktree, not from the working tree.
  2. The 218 newly-visible tests run, and every failure among them is filed as a pre-existing finding before merge.
  3. pytest . --collect-only yields zero node IDs under the top-level scripts/ and docs/.
  4. The guard test is demonstrably RED at the Stage 1 commit and GREEN at the Stage 2 commit, provable from CI history. This requires the pull request to be opened at Stage 1 and left red: quality-gates-by-domain.yml:17-22 triggers only on pull_request and push to main/develop, so pushing the RED commit to the branch alone runs no workflow and produces no evidence.
  5. Domain test aggregate and Run Quality Gates both green, with zero failures across the whole rollup.
  6. Every directory under tests/ containing collectible files is owned by exactly one gate — no path gains a second owner and starts running twice.
  7. A comment on #1977 records that node-ID baselines captured before this change undercounted by 218, so earlier comparisons can be re-read correctly rather than silently trusted.
