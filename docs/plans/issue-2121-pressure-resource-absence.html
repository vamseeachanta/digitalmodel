Problem and intended result

The pressure admission path will stop requiring an unrelated CFD solve to become active when no competing solver resource is present. A new non-null cfd-resource-absence-1 descriptor will request no CFD-family exemption. The active cfd-process-binding-2 route will remain unchanged.

The absence route will collect the existing ansys-mpi-lineage-v1 scope and classify it with cfd_binding=None. It will pass only when the selected rows, dispositions and blocking inventory are empty and the complete initial inventory contains no orphan interFoam.exe. It will not identify, preserve, reserve, stop or otherwise control the unrelated idle Python controller.

Pressure-absence collection amendment

A new pressure-absence-only collector will be added at src/digitalmodel/ansys/cylinder_absence_collection.py, with contract tests at tests/ansys/test_cylinder_absence_collection.py. It will expose collect_absence_snapshot() and return process-snapshot-1. It will not replace or modify the active-family v2 collector.

The collector will call cylinder_parent_map.enumerate_windows_v2(), retain its byte-for-byte field values in original_initial_inventory, and create a separate normalized initial_inventory. A successful empty executable string will become null only in the normalized table. A blank process name will remain unresolved until corroborated; no PID, including PID 820, will receive an allowance.

When blank names are present, one bounded Windows PowerShell subprocess will query only those validated integer PIDs through Win32_Process. The executable will be required at the current SystemRoot\System32\WindowsPowerShell\v1.0\powershell.exe path with no reparse component; its bytes will be hashed between stable file-identity reads. The subprocess will use -NoProfile, -NonInteractive, CREATE_NO_WINDOW, a static encoded script, numeric PID input on standard input, captured streams and an enforced timeout no greater than two seconds. A timeout will terminate the child through subprocess.run and refuse the observation; no persistent thread, shell session or background process will be used.

name_resolution will retain whether the query ran, the exact argv, numeric standard-input bytes, static script digest, executable digest, elapsed duration, return code, and base64 standard output and error. It will retain the parsed raw Windows provider rows and the provider name; it will not claim pywin32 identity because that package will not execute on this path. The parsed result PID set will equal the unresolved set exactly, names will be bounded and nonblank, and parent PIDs will equal the original table. Raw DMTF dates will be retained. DMTF conversion, including positive and negative UTC offsets, and psutil epoch conversion will use integer and Fraction arithmetic, and their represented instants will differ by no more than one microsecond. No new floating-point timing conversion will be introduced.

After name resolution, the collector will reread read_windows_parent_map() and refuse any new PID or changed parent among the original rows. It will run the existing _seed selector over the normalized table, close over descendants, and use the existing _details reader for selected rows. Coverage counts will describe the normalized table. The original table and query evidence will remain additional top-level evidence for later refusal analysis.

The snapshot observation time will be formatted directly from integer nanoseconds as bounded decimal text accepted by the existing classifier. A collection refusal after initial enumeration, including subprocess timeout, reconciliation, population or selected-detail failure, will raise CollectionError with JSON-safe evidence containing the original table and all name-resolution evidence available at that point.

RED tests will require raw-table preservation, empty-executable normalization, exact targeted-name reconciliation, positive and negative DMTF offset agreement, blank or duplicate result refusal, parent/population change refusal, existing seed and descendant selection, existing detail capture, no query when every name is present, at most one query per collection, bounded strictly typed PIDs, executable and script identity fields, strict JSON/return-code/error-stream handling, and an actual subprocess.run timeout argument no greater than two seconds with partial streams retained on failure. A protected blank-name row resolved to an ANSYS seed will be selected, but normalized-vs-live identity comparison will refuse it; it will never become a usable exemption or a clear absence result. CollectionError will carry JSON-safe evidence so root integration can retain failed observations. Root-owned integration will call this collector only for the reviewed absence descriptor at the initial, before-launch and phase-2 observations. Each complete production call will still have to demonstrate a duration below the five-second phase-2 limit. The measured 0.525-second full query excluded process startup and therefore indicates feasibility without establishing it.
