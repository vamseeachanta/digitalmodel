Unit Box pre-calculation mesh-details preparation

This proposal will continue digitalmodel issue 141 and issue 714. It will replace the operative preparation instructions in the original mesh-export plan while preserving that plan and its exact review unchanged. The result will be an OrcaWave diagnostic export supporting the AQWA comparison basis, not an AQWA solve or a qualified comparison.

Authority, ownership and boundary

The root SOLVERS session will own the derived-input bundle and any later native worker. Delegated preparation will remain offline and will write only new coordination outputs. Repository originals will remain unchanged. A native operator will require separate exact code/artifact review, actual executable/library identity, licensing/reservation, resource bounds and owned-process containment before native import. Standing non-destructive lifecycle authority will not waive these requirements. No preparation receipt will declare launch readiness.

Frozen semantic intent

The validator will freeze physical meaning independently of native field names. It will require five wetted panels, four side-panel windings reversed and the bottom preserved; no artificial top pressure panel and no symmetry. Mesh coordinates will remain x,y in [0,1] m and z in [-1,0] m, with waterline z=0 m. The centred CoG (0.5,0.5,-0.5) m will be an explicitly prescribed ideal benchmark assumption, not recovered source data. Vertical sides will be assumed to continue locally across the equilibrium waterline for the conditional linear hydrostatic reference.

SI model intent will be density 1.025 tonnes/m³, mass 1.025 tonnes, diagonal inertia (0.164,0.164,0.164) tonne m² about CoG, from prescribed radii 0.4 m. Both body/result origin and inertia origin will be at CoG; axes will retain the mesh orientation and right-handed convention. Position, heading, heel and trim will be zero. Hydrostatic integration will be analytic, and stiffness will use displacement-based hydrostatics. External stiffness/mooring loads will be absent. Depth will be 100 m; one placeholder angular frequency 0.3 rad/s and heading zero will carry no response sampling claim.

Native key spellings and enumeration literals will remain UNVERIFIED until each mapping has a retained, version-identified native exemplar or documented installed-data-field source and exact locator/digest. Semantic field names in the intent will not be passed to OrcFxAPI as guessed native names. Missing mapping evidence will stop YAML production before native loading. Once mapping evidence is available, a separately hashed mapping record will bind each semantic field to native key, literal, units and coordinate convention; exact review will precede its use. The physical intent will not change to accommodate a parser or native default.

Canonical intent and conditional reference

Canonical JSON bytes will be UTF-8 without BOM: json.dumps(value, ensure_ascii=False, sort_keys=True, separators=(',', ':'), allow_nan=False) + '\n', with exactly one terminal LF. Numeric physical inputs will be canonical decimal strings: optional minus only for negative values, no leading plus/zeros, no exponent, no negative zero and no trailing fractional zeros; zero will be "0". Float objects, duplicate object keys, NaN/infinity, extra/missing fields and unsupported types will refuse validation. Digests will be SHA256 of these exact bytes. Raw received GDF/YAML hashes will remain hashes of received bytes, without newline normalization. Derived YAML/GDF serializers will be version-pinned UTF-8/LF and their exact byte hashes will be retained.

The existing conditional hydrostatic reference will remain frozen as rational numerator/denominator strings, separate from decimal-only physical inputs. Denominators will be positive and fractions reduced. At proposed g=9.80665 m/s² only, C33 will be {"numerator":"8041453","denominator":"800000","units":"kN/m"}; C44=C55 will be {"numerator":"8041453","denominator":"9600000","units":"kN m/rad"}. The governing quantities will remain V=1 m³, waterplane area=1 m², central waterplane second moments=1/12 m⁴, CoG=CoB, and mass equal to displaced mass. Other ideal unrestrained entries will be zero. A rounded display will never become the comparison reference.

Native SI gravity will remain unresolved until an independent native field or unit-conversion observation establishes its numeric value. Neither the GDF header nor gravity inferred from the same stiffness being examined will supply that evidence. Missing gravity will produce GRAVITY_UNRESOLVED while retaining the diagnostic export. Numeric tolerances will remain unfrozen; no engineering PASS or qualified response row will be assigned by this preparation.

Subsequent native diagnostic checkpoint

The separately reviewed root-owned worker will verify isolated output nonexistence, frozen input hashes and reviewed mapping before importing OrcFxAPI. It will refuse preloaded OrcFxAPI, library-handle overrides and incompatible interpreter architecture, explicitly select the pinned Win64 DLL through the installed configuration API, and retain loaded DLL location/version/module identity and post-load file digest. Static file hashes alone will not authenticate the loaded runtime. One explicit worker thread, bounded timeout and output storage, owned-process settlement and retained stdout/stderr/ordered events will govern the checkpoint; licence prompts or failures will stop without retry.

The worker will load only the reviewed derived input and retain SaveData roundtrip, validation text and SaveMeshDetailsSpreadsheet output before any Calculate call; Calculate will be absent from the worker. It will verify roundtrip semantics against the intent, including all frames/units/mass/inertia/integration settings, before interpreting exports. Missing, empty, stale, partial or ambiguous outputs will refuse extraction. Native warnings/errors, source mutation, timeout or failed export will remain diagnostic failures. The first retained native output will establish parser evidence; output grammar will not be guessed. Native data will remain raw evidence with hashes, units, release and intended-use status, not qualified lookup rows.

TDD and exact review

  1. The revised plan and bounded source evidence will undergo independent Claude defect-hunting review, default non-APPROVE. The exact verdict, revision and finding dispositions will be retained separately.
  2. Tests will first fail against absent offline implementation. They will cover original mixed winding; four-side reversal and no cap; source/derived mutation; ledger coverage; explicit symmetry/origins; mass/density/inertia and zero pose; canonical serialization and rational reference; unknown native mapping refusal; unsupported schema values; existing destination refusal; and absence of native imports/process execution.
  3. The offline validator and builder will implement only reviewed contracts. Synthetic native-state flags will test refusals, not authenticate a runtime. The native worker will remain a distinct implementation and exact-review gate. Opposite-provider code/artifact review will precede use; focused RED/GREEN receipts will retain commands, counts and hashes.
  4. The next handoff will contain derived-input evidence or a precise missing native-mapping fact. It will not substitute synthetic dictionaries for observed units, origin, gravity or native output.
