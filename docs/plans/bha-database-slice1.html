BHA database slice 1

Tracking: implementation issue.

The database will use strict Pydantic YAML records, per-value units and provenance, Pint SI conversion, fixed-file bounded reads, manifest digests and row counts. Unknown keys, missing sources, nonfinite or dimensionally invalid values, duplicate IDs and CLIENT-PRIVATE rows will fail closed. Sources will distinguish synthetic assumptions from public terminology references.

  1. A failing test will cover a single synthetic pendulum pilot, then the minimum loader/calculations will make it pass before the other examples are added.
  2. Eleven focused tests will cover load, tampering, provenance, strict keys/duplicates, geometry, connection compatibility, unit roundtrips, R1–R6 including near-bit above MWD, computed lengths/weights, R7 and restricted-row refusal. Tests will precede the behavior they cover.
  3. Rotary building and motor examples will use only assumed components. Every numeric physical value will carry value, unit, source_key, basis, as_published and as_published_on. Counts/positions will remain schema integers. Output calculations will carry source references and formula basis.
  4. R1–R6 will be errors. R4 will enforce nondecreasing collar/HWDP/drill-pipe order while allowing intervening tools. R5 will require matching thread labels and opposite genders at every interface, including both sides of crossovers. R7 will warn when inputs are missing or planned WOB exceeds buoyed below-HWDP weight with an explicitly assumed margin; no API margin will be claimed without a verified clause. R8 will remain OPEN for a later slice.
  5. The API will expose assembly sections, bit distances, blade centres, total length, maximum OD, air and buoyed weight. Scalar lengths will be required for examples; alternative catalogue lengths will require selection before use.
  6. The independent ISO branch will retain all 23 PDF-checked Table 14 rows and a check record; no table values will enter this PR. Publication confirmation will remain pending. No licensed PDF or private dataset will be copied.
  7. Frozen plan and code packets will receive adversarial review. Relevant existing tests, eleven new tests, lint, CLI and public-content inspection will precede one draft PR. The separate ISO branch will be pushed without a PR.

Review focus: modified manifests must not bypass row validation; crossovers must not waive incompatible interfaces; roles must not bypass R2; counts must affect distances/weights; stabilizer blade OD must participate in R3. Original acceptance T1/T4–T7 ISO-specific assertions will be held with the ISO branch and replaced by public synthetic schema/rule checks in this PR.

Rule and loader contract

R1 will require exactly one bit at position 1. R2 will require each near_bit-role stabilizer directly above that bit, bottom box, count 1; a near-bit stabilizer above MWD will fail R2. R3 will compare body, maximum and blade OD with hole size. R6 will reject unknown component references before dereferencing. R4 will compare classified component types from bit up and ignore intervening tools; incomplete strings will be permitted. R5 will match exact canonical thread labels, opposite genders; aliases and external end interfaces will remain out of scope.

The loader will allow exactly examples.yml and manifest.yaml, reject symlinks, duplicate YAML keys and aliases, cap each read at 1 MiB, validate strict unknown-forbidding records, finite positive lengths/OD, nonnegative bore below OD, positive strict integer counts, contiguous positions and all source references. Data_class will be a closed enum on each component and assembly; CLIENT-PRIVATE will always fail independent of manifest validity. Unknown marker spellings will fail schema validation without echoing payload values. Manifest hashes will detect accidental inconsistency, not authenticate author intent; semantic validation will run even for rehashed fixtures.

R7 will consume provenance-wrapped mud density, material density, planned WOB and margin. Missing inputs will emit R7 NOT_EVALUATED; excess WOB will emit R7 EXCEEDED with available load and comparison. Synthetic assumptions and mechanics identities will supply calculation sidecars; no standards-derived margin or formula will be introduced into public code. R8 will remain deferred. The eleven test functions will include the pilot; parametrized failures will sit within the rule test function.

The originating task explicitly authorizes pushing branch bha-iso-table14 to the same public repository without proposing it; that exact destination/action will be used, with no PR, while maintainer confirmation remains pending. This branch is publicly accessible; branch separation will not imply confidentiality. The originating task also explicitly moves all ISO acceptance checks out of this PR. Registry changes in other repositories will remain outside this slice. Reviews will cover the plan and code with available providers; unavailable authentication will be recorded.
