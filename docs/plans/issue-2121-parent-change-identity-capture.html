Proposed identity evidence for refused process-table observations

ANSYS diagnostic campaign. Complexity T2; single-lane source ownership and independent Claude review. Existing non-destructive analysis authority will govern this bounded correction.

Resource intelligence and reproduction

The design will build on cylinder_parent_map.py at 577c2201, the prior issue-2121-parent-map-refusal-evidence.html plan, and the retained refused observation SOLVERS-fluid-discovery-577c2201-r1.json. The numeric refusal contract will remain intact. Existing initial identity rows will supply facts already read; later follow-up evidence will address the gap exposed by a transient added process. Installed psutil source inspection will govern API selection: its Windows per-process parent accessor internally reads a whole parent table, so that accessor will not be called. No numerical criterion or engineering standard will be changed.

Implementation and bounded evidence

  • The current parent-table refusal boolean, message, numeric tables, event and completion counts will remain unchanged.
  • Only after that predicate fires and numeric evidence has been built, a helper will attach rejected_parent_identity with schema parent-change-identities-1. This will remain supplemental, with resource relevance NOT_EVALUATED and table identity binding NOT_ESTABLISHED.
  • Candidates will be ordered as sorted unique triggers, followed by the sorted union of their initial and final nonzero parents, with first-occurrence deduplication. Only the first eight will be retained/read. Selected identifiers, candidate count and omitted count will be explicit. Omitted identifiers will remain reproducible from the unchanged numeric tables and this rule. Eight or more triggers can leave all parents outside the capture limit.
  • Original rows will be copied only for selected identifiers with existing valid rows. Each retained row will carry initial_image_basis=original_collector_psutil_high_level_may_guess; this will preserve uncertainty in the unchanged original collector, separately from the later native image accessor. original_row_status will be RETAINED, NOT_IN_INITIAL_TABLE, UNOBSERVED_INITIAL, INVALID_FIELDS or OMITTED_SIZE_LIMIT. The last status will supersede the others when all details for a candidate must be omitted.
  • For candidates present in the final table, two fresh process objects will independently supply creation time, name and executable path. No additional parent-table accessor (ppid_map, read_windows_parent_map or ppid), command-line accessor, environment, file-content read, image hash, process creation or retry will be introduced. Executable path will use the pinned Windows backend accessor, avoiding the high-level command-line guessing fallback. Native creation-time metadata fallbacks may have broader internal acquisition; no single-process-only native query guarantee will be made. The final table parent will be retained separately as final_table_parent_pid; it will not be presented as part of the later identity.
  • Agreeing bounded fields will produce OBSERVED_AFTER_TABLE or INCOMPLETE_AFTER_TABLE. Differing samples will produce IDENTITY_CHANGED. Disappearance, inaccessible identity and invalid fields will produce DISAPPEARED, UNAVAILABLE or INVALID_FIELDS. Candidates absent from the final table will have NOT_IN_FINAL_TABLE without a new read. No later identity will be asserted to match the process that occupied an earlier numeric table entry.
  • Creation times will use the active collector grammar: 1–20 ASCII digits with an optional decimal point and 1–20 fractional digits. Name and image fields will be null or strings of at most 4,096 characters; oversized values will not be copied or truncated into valid identities. Empty or unavailable fields will preclude completeness.
  • The supplemental record will be limited to 32,768 bytes under existing analysis_records.canonical_bytes. Candidate details causing overflow will be replaced by OMITTED_SIZE_LIMIT metadata, retaining actual attempted identifiers. All omission stubs, actual attempted identifiers and final duration-clock digits will be installed before identity details are considered in candidate order. Each detail replacement will be measured against the complete metadata, so later stubs cannot overflow an earlier decision. This is a canonical-data bound, not a claim about pretty-printed physical file size; actual storage accounting will remain unchanged.
  • Start/end monotonic_ns integers will describe capture timing, never birth epochs. The limit will bound candidates and API calls rather than promise a hard wall-clock timeout. An outer Exception handler will preserve numeric refusal and attach CAPTURE_FAILED under the distinct parent-change-identities-error-1 schema with a bounded exception type. KeyboardInterrupt and SystemExit will not be swallowed.

Superseded scope and tests

The historical prohibition on identity text will continue to apply to rejected_parent_observation. Only the new separate namespace will retain bounded text. Existing test_unbounded_process_text_is_excluded assertions on len(json.dumps(error.evidence)) and the absence of executable_path will be explicitly re-scoped to error.evidence['rejected_parent_observation']; additional checks will enforce the supplemental canonical bound and absence of oversized values. Existing success and refusal fixtures will continue forbidding per-process parent calls.

Tests will precede implementation for retained versus missing original facts, additions, disappearance, inaccessible fields, reuse, changed names/images, deterministic deduplication and limits, aggregate Unicode size, copy independence, whole-helper failure, canonical serialization and collector transport. The exact pre-change predicate syntax and message will be compared. The whole evidence will remain the prior numeric payload plus a bounded supplemental payload; no new global 2 KiB bound will be claimed for complete population tables.

Review, validation and next observation

Supported findings from the two plan reviews will be disposed inline. Exact-current code review, full relevant regression, static/legal checks and published-byte readback will precede one read-only collection. The artifact will retain either a collected outcome or the original refusal and available supplemental capture. A new table change is not guaranteed and no process will be created to manufacture one. No automatic retry will occur.

SOLVERS will own helper, integration, tests and reviews. Fluid-analysis controls, staged matrix-intake work, original evidence, native attempt counts and authoritative result matrix will remain unchanged by this diagnostic task. No execution clearance or qualified reusable row will be inferred.
