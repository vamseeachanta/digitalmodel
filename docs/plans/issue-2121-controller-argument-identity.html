Controller argument identity correction

Issue: ANSYS cylinder diagnostic campaign. This bounded correction will preserve literal observed arguments while joining either the existing relative arguments or absolute local paths to the same pinned controller files. Standing user lifecycle authorization will apply; independent plan and implementation review will remain required.

Scope and method

The owner-evidence resolver will accept an absolute controller script argument only when it identifies rotation_queue.py immediately under the pinned controller root. The configuration argument will identify the pinned configuration record immediately under that same root. Existing relative forms will continue to resolve against the observed interpreter working directory. The implementation will not rewrite observed arguments, infer launch ownership, relax digests or accept a different configured case.

Argument validation will reject drive-relative, root-relative, network/device paths, traversal, alternate streams, empty components and trailing-dot/space aliases. The existing pinned reader will continue to reject redirected filesystem paths. Exact source joins, ancestor identities, executable forwarder evidence and process classification will remain required.

The existing controller configuration root-equals-observed-interpreter-working-directory invariant will remain unchanged. Absolute arguments will be compared on both sides against the expected pinned path under that root; path joining will not substitute for that comparison. Source resolution_basis will match the actual argument form. Windows case-insensitive identity will remain supported; short-name aliases will not substitute for the pinned literal file identity. Junction/symlink refusal will remain the pinned reader's responsibility and will retain regression coverage.

Console branch identity

The two supplemental consoles will each belong to exactly one of the two independently validated forwarder/interpreter pairs: controller and guard. Each console will have a direct parent in its assigned pair. Duplicate consoles within a branch, absent branch coverage, third consoles, unbound parents, changed creation times, source-bearing consoles and incomplete snapshot coverage will refuse. The implementation will use this same branch rule in binding validation, historical-source resolution and classification output, preserving agreement. It will not allow arbitrary descendant consoles or replace observed parent identities.

The retained 128-row discovery receipt and original launch provenance will support the factual case; the offline candidate validation will produce a digest-identified result rather than rely on a skipped optional test. These observations will not grant ongoing resource clearance or authenticate historical loaded bytes.

The version-two binding validator will pass both validated endpoints of each forwarder pair to console validation. Historical supplement resolution and classifier reporting will use the identical pair-aware rule. Existing serialized wrapper_console_pids field names will remain for compatibility; descriptions will identify them as supplemental branch consoles.

The current controller configuration bytes, pressure-current-resource-facts-1 owner candidate, standalone process-snapshot-2 supplement and binding declarations will be included with digest pins in the implementation review. Current controller-state corroboration will be retained as raw bytes and referenced from the candidate. The original optional historical test and its synthetic helper will remain limited to their original relative-argument receipt; a separate current offline evaluation will establish the new evidence case. No historical fixture will be relabeled as current.

Test-first implementation and review

  1. Tests will first demonstrate refusal of otherwise matching absolute script/configuration arguments under the existing implementation.
  2. Tests will cover relative compatibility, mixed relative/absolute forms, wrong roots or filenames, traversal and malformed Windows path forms, unchanged literal arguments, changed source digests and missing source evidence.
  3. A bounded pure argument resolver will be introduced in the existing owner-evidence module. Focused owner/resource tests will run before integration checks.
  4. Retained current factual bindings will be evaluated offline without a solver launch or licence reservation. Independent Claude review will inspect the exact correction and test evidence with a non-APPROVE default.

Acceptance and limits

Acceptance will require correct relative and absolute forms to join the same pinned files, all refusal cases to fail closed, and no changes to literal process evidence. Native admission will remain separate: exact configuration review, current resources, licence availability, reservation, timing and stop criteria will still govern the intermediate-mesh run. Matrix values and engineering qualification will remain unchanged by this correction.

One root owner will integrate source and execution configuration. Delegated work will remain disjoint: the owner-argument module and its tests will be separate from console-branch modules and tests. No fluid-dynamics control, original result or existing attempt record will be altered. The unrelated matrix-intake write denial will remain in force.
