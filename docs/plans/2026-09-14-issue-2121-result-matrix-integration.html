Outcome and authoritative owner

The maintained ANSYS result matrix will remain authoritative. Its dataset identifier will remain ansys-retained-evidence and its schema will remain ansys-evidence-1. The response CSV will remain a derived export. A new immutable revision will preserve the eight historical cases and add the four cylinder cases; no second matrix, workbook or dataset owner will be introduced. The original frozen intake and revision r1 will remain reproducible.

The initial next revision will expose the cylinder cases before native completion through explicit unattempted and not-evaluated states. Subsequent evidence-backed revisions will replace missing observations only when retained native evidence supports them. Case IDs and response definitions will remain stable. The current package findings will remain preserved and will receive explicit case/response applicability dispositions; no finding will be silently dropped.

Stable case IDs will be ocv-zero-t60-n16, ocv-t60-p10-n4, ocv-t60-p10-n8 and ocv-t60-p10-n16. Each row will bind model/deck/source revision, pressure and geometry with units, PLANE183 axisymmetric method, requested solver profile and any observed native version. Analytical comparator values will remain distinguished from native observations.

The existing schema will encode unattempted native work as execution_status=unknown with an explicit unattempted detail and reason, and calculation_status=not_evaluated with value=null. A preflight refusal will consume no attempt. A launched case with incomplete evidence will retain its consumed-attempt identity and failure reason; it will not be represented as an unattempted case or a true zero. An optional schema extension will require review before use; no status outside the existing validator will be silently emitted.

Proposed implementation sequence

Revision construction will remove derived package and row hashes before calling the existing builder, then will assert that recomputed hashes and payloads of the eight historical cases remain unchanged. Pending native rows will use source_kind=unverified; response evidence IDs will resolve retained deck, manifest and criteria bytes, not nonexistent output files. Station/quantity names and the RFY name will be unique within each case. All evidence references will be resolvable even when marked optional because the builder verifies them. The current lookup gate will continue to require each inherited finding's supported resolved disposition, justification and live evidence; not_applicable will not bypass that gate.

  1. The exact-current B1 report review and this integration plan review will be completed when Claude is available. Codex will independently disposition Claude findings. Existing standing authority will continue to govern unchanged objective scope.
  2. Tests will first specify preservation of r1 and its eight cases, 12-case/350-response membership, no duplicate IDs or query identities, typed null versus zero, units, immutable revision publication and diagnostic-only retrieval. Missing or changed evidence and absent review/rights will be tested as refusals.
  3. A bounded matrix integration entry point will reuse build_package, publish_package, load_package and response_csv. It will publish the next unused revision of the same dataset at the existing configured owner root, verify its readback, then refresh the canonical manifest and derived CSV. It will not repurpose the r1-only importer or overwrite an existing revision. The package's general criteria and each historical case's basis will remain distinct from the cylinder-specific criteria.
  4. The real authority/preflight/adjudication binding will be implemented with tests and exact-current review. It will name the operator and competent independent checker, validate the approved manifest/executable/profile, use an authoritative attempt ledger and hold cooperative resource ownership until process settlement is established. Existing Deckhand components will be reused only where their semantics meet the frozen canary requirements; automatic lock release on uncertain settlement will not be accepted.
  5. Live licence, process ownership, output residence, retention rights, capture allowance and reserve evidence will be obtained. The unrelated MPI process will remain untouched until its ownership is established. The four-case sequence will then run under the reviewed operator with one SMP core, 300 seconds per attempt, 1,800 seconds overall and no automatic retry. Failed prerequisites will produce explicit incomplete state, not a launch.
  6. Native inputs and outputs will be retained with original-byte hashes, source rights and storage disposition. The operator's outcome, fixed numerical criteria and independent adjudication will determine recorded PASS/FAIL/INCOMPLETE states. Every failed and unattempted case will remain visible in the matrix. A native numerical pass will remain provisional until all requirements for the intended reuse are independently established.
  7. The current code and resulting artifacts will receive reciprocal review. Legal, register, evidence-resolution, publication-readback and cleanup checks will be completed. The final checkpoint will report matrix completeness and reusable/provisional/incomplete counts, rather than treating test totals as the analysis outcome.

Acceptance and rollback

The integration will be accepted only when the existing authoritative store exposes all 12 stable case rows and 350 defined response records, preserves the historical r1 evidence, binds each new observation to immutable inputs and retained outputs, and reproduces its CSV from the typed package. Four case states will be visible even if execution stops early. Qualified lookup will continue to require independently checked response registers, owner authority, live evidence, rights, withdrawal checks and finding dispositions. Missing validation or a provider outage will not grant readiness.

Publication will remain atomic and non-overwriting, within the existing 5 MB revision and 25 MB dataset-directory limits. A failed refresh will preserve the previous canonical revision and failed-run evidence. Recovery will not delete another owner's lock or mutate solver controls. The report will distinguish local saves, repository retention and publication.
