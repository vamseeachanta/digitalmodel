Outcome and authoritative owner

The maintained ANSYS result matrix will remain authoritative. Its dataset identifier will remain ansys-retained-evidence and its schema will remain ansys-evidence-1. The response CSV will remain a derived export. A new immutable revision will preserve the eight historical cases and add the four cylinder cases; no second matrix, workbook or dataset owner will be introduced. The original frozen intake and revision r1 will remain reproducible.

The initial next revision will expose the cylinder cases before native completion through explicit unattempted and not-evaluated states. Subsequent evidence-backed revisions will replace missing observations only when retained native evidence supports them. Case IDs and response definitions will remain stable. The current package findings will remain preserved and will receive explicit case/response applicability dispositions; no finding will be silently dropped.

Proposed implementation sequence

The backward-compatible ansys-evidence-1 validation extension will recognize the optional paired fields attempt_consumed and native_attempt_count in validate_case, so construction and later loading will apply the same rules. Both absent will mean not recorded; either present will require both, a true boolean and a nonnegative integer excluding booleans, with attempt_consumed == (native_attempt_count > 0). A capture_role=pending_native case will require both fields, zero attempts, unknown execution, unverified source kind and exclusively not-evaluated null responses. Rehashed inconsistent or missing discriminator records will be rejected. Historical rows without these fields will retain their original representation. This additive contract will not convert missing historical counts to zero.

Pending rows will record author=unverified, author_status=unverified, capture_role=pending_native, observation time in generated_at, retention_rights=approved for repository-generated benchmark inputs under standing authority, and use_rights=unresolved. The input descriptor will separately record matrix_preparer=Codex. Shared validation will require unverified author status for pending-native cases; lookup tests will verify refusal without authenticated native provenance. No human operator/checker or completed native version will be inferred. Parameter names will carry units, and the input descriptor will also provide an explicit parameter-unit mapping including dimensionless mesh counts and Poisson ratio. Analytical comparator values will remain in the frozen reference artifact; every new response value will remain null, no observed_value will be allowed, and every pending response will carry the fixed limitation native-not-attempted.

The next package will retain the frozen 17-candidate intake reference solely for the eight historical cases and will bind the four pending cases through a separate retained benchmark manifest descriptor. The code fingerprint and method revision will identify the pending builder and shared schema extension. Coverage will retain six native captures and zero qualified responses, add four pending cases and 256 pending responses, and distinguish 12 total cases / 350 total responses. A requested revision will be explicit rather than selected by an automatic increment. On retry, an existing identical immutable revision will be revalidated and refreshed idempotently; a differing revision or changed canonical baseline will be refused. No duplicate successor revision will be allocated during recovery.

The publication wrapper will acquire a separate owner-recorded integration lock once for baseline check, immutable publication, manifest refresh and derived CSV refresh. The existing inner revision publisher lock will remain nested within that critical section. This cooperative protocol will serialize participating integration writers; nonparticipating writers will remain an explicit limitation, and a changed baseline digest will stop replacement. Lock content will identify host, PID, start time and expected baseline digest. A stale lock will require evidence of owner termination before any removal; this slice will not implement automatic removal. Revision storage limits will include every JSON in the existing dataset directory. The historical revision will remain at its existing owner root rather than being copied into a second result store.

Revision construction will remove derived package and row hashes before calling the existing builder, then will assert that recomputed hashes and payloads of the eight historical cases remain unchanged. Pending native rows will use source_kind=unverified; response evidence IDs will resolve retained deck, manifest and criteria bytes, not nonexistent output files. Station/quantity names and the RFY name will be unique within each case. All evidence references will be resolvable even when marked optional because the builder verifies them. The current lookup gate will continue to require each inherited finding's supported resolved disposition, justification and live evidence; not_applicable will not bypass that gate.

Acceptance and rollback

The integration will be accepted only when the existing authoritative store exposes all 12 stable case rows and 350 defined response records, preserves the historical r1 evidence, binds each new observation to immutable inputs and retained outputs, and reproduces its CSV from the typed package. Four case states will be visible even if execution stops early. Qualified lookup will continue to require independently checked response registers, owner authority, live evidence, rights, withdrawal checks and finding dispositions. Missing validation or a provider outage will not grant readiness.

Immutable revision publication will remain atomic and non-overwriting, within the existing 5 MB revision and 25 MB dataset-directory limits. Failure before canonical replacement will preserve the previous canonical manifest. Failure after manifest replacement but before CSV completion will retain the new manifest, the old immutable revision and explicit failed-refresh evidence; idempotent retry will repair the derived CSV without another revision. Recovery will not delete another owner's lock or mutate solver controls. The report will distinguish local saves, repository retention and publication.
