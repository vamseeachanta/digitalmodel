Diffraction diagnostic evidence contract

Summary

Frequency alignment, statistic quality and sampling are retained from producer to export. A diagnostic correlation does not establish physical acceptance. Missing comparison policy, malformed matrices and invalid hydrostatic differences produce explicit refusals.

Method and sources

Radiation and coupling coefficients remain signed. Piecewise linear interpolation is applied on the coarser source grid within the qualified overlap, using the existing benchmark_abscissa sampling and coverage policy. No new physical threshold is introduced.

For matching aligned vectors, Pearson correlation is Cxy / sqrt(Cxx Cyy), as defined by the NumPy corrcoef reference (accessed 2026-10-20). A constant vector has zero variance, so its correlation is unavailable even when the two vectors are equal. The NumPy interpolation reference defines the piecewise linear interpolant (accessed 2026-10-20). RMS difference is sqrt(sum((b-a)^2)/n), from the root-mean-square definition; positive scaling preserves both RMS algebra and correlation while limiting intermediate overflow.

Six-DOF matrix dimensions and three-component coordinates follow the repository's output_schemas.HydrodynamicMatrix and HydrostaticResults. Acceptance thresholds remain required inputs to ComparisonPolicy, with uncertainty, absolute resolution and a justification. Correlation alone is insufficient.

Worked example

The executable example is examples/diffraction_evidence_contract.py. The first frequency grid is [1.00, 1.08, 1.16, 1.24, 1.32] rad/s; the second grid has six evenly spaced samples over the same interval. Each coefficient is the synthetic affine function y = omega - 1.16 in arbitrary consistent units.

Linear interpolation retains the signed crossing and gives the aligned vector [-0.16, -0.08, 0.00, 0.08, 0.16] for both inputs. Their difference is zero, so RMS is 0.0, correlation is 1.0 and the aligned sample count is 5. Equal constant vectors instead produce null correlation with INSUFFICIENT_DATA. Missing axes produce null correlation and sample count with INVALID_ABSCISSA. These are algebraic test results, not engineering measurements.

Limits and way forward

Native solver validity is not established by these offline diagnostics. Physical-zero qualification remains a separate provenance task. The existing abscissa defaults are reused without re-qualifying their physical basis. Scalar compatibility status output is retained for callers but is not evidence of production acceptance. A complete uncertainty budget and qualified input provenance are required before numerical acceptance can be established.
