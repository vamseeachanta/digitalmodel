Wall-thickness load interaction worked example

The illustrative reference section changes from collapse-governed at zero tension and moment to combined-load-governed at the loaded corners. The largest corner reaches 154.5% of the inherited utilisation criterion of 100.0%. This establishes agreement with the implemented equations at the tested corners; design qualification remains NOT_EVALUATED.

Method and sources

The source is the repository implementation of API STD 2RD (2013), Method 1: ApiStd2rdStrategy, functions compute_plastic_tension, compute_yield_moment, _check_burst, _check_collapse and _check_combined. The standard text is not independently verified in this example. The coefficients are inherited from that implementation, and no new standards-derived factor is introduced.

  1. Exact integration of the annulus gives A = pi*t*(D-t). Multiplying this area by yield strength gives T_y = SMYS*A: 7,749.6 kN.
  2. The inherited thin-wall moment approximation is M_y = (pi/4)*SMYS*(D-t)^2*t: 592.7 kN m. This is not an exact thick-wall section-modulus calculation.
  3. The implemented burst equation gives p_b = 51.9 MPa. The pressure correction is evaluated from the inherited design factor and the net pressure ratio, as specified by _check_combined.
  4. The combined utilisation is u = (abs(T)/T_y + abs(M)/M_y)/F_corrected. The independent arithmetic is written in full in the corner tests; the analyzer is not used to calculate those expected values.

Each load endpoint is a sampling choice of 60.0% of its reference capacity, rounded to the nearest N or N m. This choice spans a change in governing check; it is not a factor prescribed by a standard or an allowable-load envelope.

Reproduction and data contract

The full grid contains 354,609 rows: 41 wall values, 31 tensions, 31 moments and nine design codes. Every full row carries its code, axes, utilisation, governing check, per-check values, code reference and qualification status. A null per-check value means that check is not implemented for that code; it does not mean zero utilisation.

Set STUDY and DATASETS to destinations outside the checkout, then run from the repository root with the reporting dependencies installed:

PYTHONPATH=src python scripts/capabilities/build_wall_thickness_3d.py --output "$STUDY"
python scripts/capabilities/build_wall_thickness_3d_page.py --source "$STUDY"
python scripts/hf/build_capability_datasets.py --wall-thickness-source "$STUDY" --out "$DATASETS"

The second command produces the page and compact sidecar together. Serve the docs through HTTP to use fetch; opening the HTML directly as a local file can block it. The existing dataset builder prepares the full rows for publication; it does not upload them.

The display snapshot contains at most 22,869 points and less than 400 kB of JSON. It retains every second wall and every third load sample, including endpoints. Displayed utilisation is quantized; cell colours use the majority governing check among the corners. Neither cell colour nor interpolated boundaries establish off-grid capacity.

Limits and way forward

Qualification is NOT_EVALUATED because the governing standards and source case have not been independently qualified. Compression, fatigue, defects and installation history are outside this study. Different codes implement different check sets and do not all respond to tension and moment. Engineering use requires a qualified case, the applicable standard and checks outside this demonstration. External dataset publication and website registration require separate maintainer actions.
