1. Summary

The module provides sizing and code-selected capacity routes. This report maps their implementation evidence and checks only the common annular section geometry against independent polar integrals. The chosen dimensions are geometric probes, not realistic pipe dimensions or code allowables.

Pressure containment, collapse, combined loading, material strength and code compliance remain NOT_EVALUATED. The parent issue remains open for broader numerical qualification.

3. Data Basis

All numerical geometry inputs are defined synthetic values: outside diameter Do = 4.0 m, inside diameter Di = 2.0 m, hence outer radius Ro = 2.0 m and inner radius Ri = 1.0 m. These are arithmetic probes of a concentric annulus about its centroid. No service input is assumed.

The method is unit agnostic: consistent input lengths are interpreted as metres here, with no conversion. Area units are m^2 and all second-moment units are m^4. No material, pressure, corrosion, manufacturing, temperature, density, design factor or loading mapping is supplied.

{"Outer_Pipe": {"Geometry": {"Nominal_OD": 4.0, "Nominal_ID": 2.0}}}

The dimensional input definition is the source for these constants; the independent integrals supply all equation coefficients. Dates and revision identifiers are document metadata, not engineering inputs.

4. Theory and Equations

Let x = r cos(theta), y = r sin(theta), and dA = r dr dtheta, with Ri <= r <= Ro and angle from zero to 2*pi. The angular integral of unity is 2*pi; the angular integral of sin(theta)^2 or cos(theta)^2 is pi.

A = 2*pi * [r^2/2]_1^2 = 3*pi m^2
Ix = Iy = pi * [r^4/4]_1^2 = 15*pi/4 m^4
J = 2*pi * [r^4/4]_1^2 = 15*pi/2 m^4 = Ix + Iy
I denotes either centroidal diametral moment, Ix or Iy.
Disk controls: Ao,Ai = 2*pi*[r^2/2]_0^R;
Io,Ii = pi*[r^4/4]_0^R; Jo,Ji = 2*pi*[r^4/4]_0^R.
R is Ro for the outer disk and Ri for the inner disk.

The radial antiderivatives follow integration of r and r^3. Substituting R = D/2 yields the module's diameter expressions: A = pi*(Do^2 - Di^2)/4, I = pi*(Do^4 - Di^4)/64, J = pi*(Do^4 - Di^4)/32. The test oracle uses the evaluated polar integrals directly.

6. Validation Evidence

The new report suite checks independent unrounded geometry and units, J = Ix + Iy, each visible result against both the oracle and a fresh module call, and a controlled area mutation that must change visible output. It also checks isolated deterministic rebuilds, source resolution, escaped HTML/JSON, import safety and output confinement. Reproducibility is not physical validation.

The numerical tolerance is derived specifically for this probe: at most eight rounded steps per expression path, sixteen across the module and reference paths, including representation of pi. Integer powers and binary scale factors are exact for these inputs. With binary64 epsilon = 2^-52, use gamma(16) = 16*epsilon/(1 - 16*epsilon); the relative budget is gamma(16)*5/3. The subtraction amplification for area is (Ro^2 + Ri^2)/(Ro^2 - Ri^2) = 5/3; for fourth powers it is 17/15, which is smaller. Using epsilon rather than half epsilon overbounds individual rounding steps. No engineering tolerance is inferred.

The existing standalone example suite preserves its separate command and output contract. The common capacity suite covers regression behaviour of a parallel implementation; passing those assertions does not provide independent pressure, collapse, material or standards qualification.

Geometry alone establishes no allowable pressure, utilisation, code compliance or fitness for service. No licensed solver is imported or queried. No standards table, factor or production engineering behaviour is changed.

The method map records incomplete inverses, implicit defaults, parallel implementations, fixed load terms and legacy units concerns as source findings. Their presence is not a numerical evaluation or an accepted design basis.

8. Recommendations

Before service use, select a single dispatch path and intended standard edition; establish geometry units, material certification, dimensional allowances, load envelopes, temperature and explicit design factors. Replace or exclude incomplete inverses before using thickness recommendations. Review fixed loads, pressure/force conversions, interpolation bounds and material defaults against documented input contracts.

Then obtain independent references for pressure, collapse and interaction, derive case-specific tolerances, test boundaries and failed cases, and review edition-specific clause applicability. Qualify each sizing copy and the complete router separately. Keep the parent issue open until that broader evidence is reviewed.

10. Appendix

Rebuild and output contract

PYTHONPATH=src uv run --no-project --with pytest python docs/reports/modules/pipe_capacity/build_report.py --output-dir "$TMPDIR/pipe-capacity-report"

Supply writable scratch storage through TMPDIR. The builder writes only report.html, sources.json and changes.json in the explicit output directory. All intermediate data stays in memory. The generated page has no external resources, absolute paths or runtime timestamps. Relative repository links resolve beside this report; an isolated exported page retains all narrative, equations, results and styling without fetching linked files.

The builder requires the standard library and the existing common sizing class. An already prepared interpreter can run the command without uv; preparing pytest through uv may require network access.
