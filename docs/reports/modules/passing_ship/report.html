1. Executive Summary

The section-shape helpers are checked against an independent synthetic quadratic. The report provides a source-linked module map and reproducible section results. Physical-force qualification is NOT_EVALUATED; the parent issue remains open for broader numerical qualification.

The solution for this bounded example is the normalized parabola H1 and its interior derivative. The way forward is to reconcile force conventions, obtain independent numeric references and establish an applicability envelope before using forces.

2. Introduction

The package exposes configuration, force calculation, batch processing, histories and plotting interfaces. This report calls only s1_function and ds1_dx, loaded directly from the shipped source. NumPy and SciPy are needed by that file; package initializers, benchmark generators and solver adapters are not imported by this builder.

Normalized shape is dimensionless, while a dimensional sectional area requires an additional physical area scale. The synthetic section illustrates an algebraic property, without an engineering load campaign.

4. Theory and Equations

H1: independent hand derivation

Let S(x) = a*x^2 + b*x + c. The synthetic conditions S(-2 m) = S(2 m) = 0 and S(0) = 1 give c = 1, 4 m^2*a - 2 m*b + 1 = 0, and 4 m^2*a + 2 m*b + 1 = 0. Subtracting gives b = 0 m^-1; substitution gives a = -1/4 m^-2.

Thus S = 1 - x^2/(4 m^2) and dS/dx = -x/(2 m^2). At x = (-2, -1, 0, 1, 2) m, direct substitution gives S = (0, 3/4, 1, 3/4, 0) and interior slopes (1/2, 0, -1/2) m^-1. The endpoint polynomial limits are (1, -1) m^-1.

The shipped expressions S = 1 - (2*x/L)^2 and dS/dx = -8*x/L^2 reduce to H1 at the synthetic length. They return zero outside the section. Endpoint slopes are one-sided limits from the interior; the zero extension is not differentiable at the join at either endpoint.

Roundoff budget: all selected values and intermediate operations are exactly representable binary integers, halves or quarters. Multiplication, squaring, division by powers of two and subtraction are exact here. The absolute comparison tolerance is zero in dimensionless shape and m^-1 slope; relative tolerance is zero. This budget applies only to these stations and operations, not to quadrature or a physical-force tolerance.

Table 4. Deferred engineering evidence.

No force in N or moment in N m is computed. Force coefficients, calibration, force-sign qualification, finite-depth suitability, mooring response and solver qualification remain outside this example.

Finding: the existing methodology describes positive lateral direction to port, while package conventions say starboard. The methodology also describes dimensional sectional areas, whereas these section helpers return normalized shape. The convention document's force-scaling narrative and the calculator's delegated force path require reconciliation. These are source-inspection findings, not a determination of correct physical signs or scaling.

The existing benchmark deferral records an unavailable numeric reference. H1 does not resolve that gap, establish a peak-search window or justify applying another comparison's force tolerance.

8. Recommendations

  1. Reconcile documented axes, section normalization, area scaling and the actual calculator path against an independently reviewed method basis.
  2. Obtain a public numeric force/coefficient reference with geometry, units, signs and uncertainty; establish the peak-search window and error budget before comparison.
  3. Check quadrature convergence and depth/separation applicability on that basis, then review histories and downstream response separately.
  4. Retain NOT_EVALUATED for the deferred categories until their evidence is available. Keep the parent issue open.

10. Appendix

Entry points inspected, not executed

YAMLConfigParser.parse_file/parse_string builds validated configuration models. VesselConfig requires length, beam and draft in m and a dimensionless block coefficient; EnvironmentalConfig carries depth in m, density in kg/m^3 and current speed in m/s. An absent depth selects the infinite-depth path. CalculationConfig carries stagger and lateral separation in m, passing speed in m/s and numerical integration/cache settings. PassingShipConfig combines both geometries, environment, calculation settings and output-unit selection. Input-model checks do not establish a physical validity envelope.

PassingShipCalculator.from_config_file constructs a calculator; from_imperial converts dimensional inputs. calculate_forces(separation, stagger, velocity) returns surge, sway and yaw, with optional caching. calculate_batch(scenarios, parallel, n_workers) consumes scenario dictionaries; parametric_study varies one parameter. These descriptions are source inspection only.

The CLI process_single reads a configuration; process_batch discovers YAML files with a pattern, supports recursive discovery and a dry run, and optionally uses a thread pool. The workflow router writes scenario forces to CSV. generate_benchmark_report builds a separate sweep report with runtime metadata; compare_benchmark requires supplied numeric references and criteria and does not qualify peak sampling. None of these entry points is run for this report.

Symbols and rebuild

L: section length in m; x: midpoint-relative station in m; S: normalized dimensionless shape; dS/dx: slope in m^-1. Force interfaces use SI force N and moment N m; neither is a result here.

With NumPy and SciPy available in the active environment, run from the repository root with a supplied writable scratch directory:

PYTHONPATH=src uv run --no-project --with pytest python docs/reports/modules/passing_ship/build_report.py --output-dir "$TMPDIR/passing-ship-report"

The builder writes only report.html, changes.json and sources.json in the explicit output directory. All content is embedded; file links are repository-relative source locators. There are no output-directory paths, runtime timestamps, external resources or import-time outputs. The standalone example CLI and output remain separate.
