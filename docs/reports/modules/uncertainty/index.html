1. Executive Summary

The uncertainty module is a sampling and response-analysis library. Analysis is performed to determine whether its public linear example recovers analytical moments; key results are summarized below.

  • Use the library to propagate declared input distributions through a scalar evaluator.
    • The sampled mean is 13.500 against an analytical mean of 13.500; the numerical comparison limit is 2.000 percent.
    • The sampled variance is 4.039 against an analytical variance of 4.083; the numerical comparison limit is 5.000 percent.
  • Use these comparisons to assess this numerical example.
    • Physical validation and application acceptance are not evaluated. The comparison limits are software-test tolerances, not operating limits.

2. Introduction

Input uncertainty is represented by probability distributions, and responses are evaluated for sampled combinations. The module separates distribution specification, sample generation, response evaluation and statistical interpretation.

The example is dimensionless and is defined by the repository's existing linear-model verification test. It represents a mathematical response with uncertain slope and offset; it is not a representation of a physical installation. No physical geometry, mesh or boundary condition is assigned.

The main workflow comprises normal and uniform priors, Latin hypercube sampling, callable evaluation, percentiles and sensitivity ranking. The term Latin hypercube denotes stratified sampling of each marginal distribution.

3. Inputs and Outputs

Distribution parameters and sampling controls are supplied by the user. Named input columns are returned with finite scalar output columns after evaluation.

3.1 Example inputs

The response is y = ax + b. Here x is the fixed argument, a is the uncertain slope, b is the uncertain offset and y is the calculated response. All quantities are dimensionless. The fixed argument is 4.0; the normal slope has mean 3.0 and standard deviation 0.5; the uniform offset extends from 1.0 to 2.0. The design contains 2000 samples with seed 2026. These are example inputs from the existing test, not measured properties.

Input dependence is not specified by this interface. The analytical comparison assumes independent slope and offset. Distribution names and their parameters are checked, including finite values, positive scales and ordered bounds. Samplers reject duplicate prior names.

3.2 Interface and returned data

The Prior class defines a distribution. The sample_lhs function returns a table with prior names as columns. The run_matrix function accepts that table and either a callable or an object exposing run; the evaluator returns a mapping from output names to scalar values. An exception aborts evaluation and identifies the failing row. An output name matching an input is prefixed with output_.

The percentile_summary function returns named output quantiles. The tornado function ranks standardized regression coefficients by absolute magnitude. The spearman_ranks function returns rank correlations and significance estimates. These quantities describe sampled responses; none is a physical acceptance decision.

4. Basis and Criteria

The example is assessed against analytical moments of the declared distributions. Acceptance is restricted to the numerical comparisons defined in the existing test.

4.1 Theory

For a uniform offset between bounds L and H, the density is 1/(H − L). Integrating b times this density gives E[b] = (L + H)/2; integrating (b − E[b])² gives Var[b] = (H − L)²/12. The density and inverse-distribution mapping are described in the SciPy uniform-distribution reference, edition 1.15.3, description and methods.

For a normal slope, the mean μ and standard deviation σ are the location and scale. Their meanings and the normal density are stated in the SciPy normal-distribution reference, edition 1.15.3, description and notes. Independence makes the cross term in the variance integral vanish, giving E[y] = xμ + (L + H)/2 and Var[y] = x²σ² + (H − L)²/12. These equations are derived here from the stated densities and the defined linear response.

Each marginal probability interval [j/n, (j + 1)/n) contains one Latin hypercube draw, with j the interval index and n the sample count. The inverse cumulative distribution maps each draw to its physical or dimensionless input value. This construction follows the SciPy LatinHypercube reference, edition 1.15.3, description.

Sample percentiles use linear interpolation between sorted responses at position (n − 1)p, where p is the cumulative probability. This is the default linear method in the NumPy percentile reference, edition 1.26, notes. A percentile of response is not a confidence bound on the estimated percentile.

4.2 Numerical criteria

The signed percentage difference is 100(sample estimate − analytical reference)/analytical reference. Absolute mean difference is limited to 2.000 percent and absolute variance difference to 5.000 percent. These limits come from the relative tolerances in tests/uncertainty/test_roundtrip.py:23-24 (percentage limit = 100 × rtol); they check approximate moment recovery for this sample design. They do not establish tail convergence or a reliability target.

5. Methodology

The public module is called directly for sampling, evaluation and response summaries. The analytical reference is calculated separately from the declared distribution moments.

The sampled variance uses the population divisor n, consistent with the existing comparison test. For regression sensitivity, each input and the output are centered and divided by their population standard deviation; least squares minimizes the residual norm of the standardized output against the standardized input matrix. The mathematical minimization is described in the NumPy least-squares reference, edition 1.26, description.

Spearman correlation measures monotonic association as described in the SciPy spearmanr reference, edition 1.15.3, description. Neither regression magnitude nor correlation establishes causal contribution. No significance decision is made from the returned significance estimates for this stratified design.

6. Detailed Results

The sampled mean is 13.500 against an analytical mean of 13.500; the numerical comparison limit is 2.000 percent. The sampled variance is 4.039 against an analytical variance of 4.083; the numerical comparison limit is 5.000 percent.

The mean difference is -4.8e-04 percent and the variance difference is -1.1 percent. The absolute differences lie within the respective numerical limits.

The sampled input correlation corr(a,b) is -0.032. The covariance cross term contributes -0.9 percentage points to the total variance difference of -1.1 percent. Finite-sample correlation therefore explains most of the variance difference; the analytical reference continues to assume independent inputs. The cross term is 2x Cov(a,b), following JCGM 100:2008, first edition, clause 5.2.2, Evaluation of combined standard uncertainty for correlated input quantities. For this linear response the propagation is exact.

The output percentiles are P10: 10.842; P50: 13.493; P90: 16.042, dimensionless. Standardized regression coefficients are a: 0.994; b: 0.144. Spearman correlations are a: 0.989; b: 0.115. The slope dominates the sampled response ranking for this example; that ordering depends on the supplied distributions.

7. Validation Evidence

Existing evidence consists of automated numerical and interface tests. Experimental validation is not established by the inspected uncertainty tests.

The sampling tests compare a fixed-seed Latin hypercube with SciPy, check one draw in each uniform stratum, check repeatability of random sampling, and reject malformed priors. Configuration tests exercise text loading and reject invalid evaluator selection, blank identifiers and non-finite values. Evaluator tests check object and callable dispatch, name prefixing, exception reporting and invalid outputs.

Analytics tests check ranking, correlation signs, ordered percentiles and step summaries. The round-trip test compares sampled moments of the linear response with analytical expectations using the numerical limits stated above. It does not test a physical response model. No measured benchmark dataset or field comparison is provided by these tests.

The accompanying report tests check the deterministic anchor values by hand calculation, compare every retained sample with a fresh module call, independently check standardized coefficients, rank correlations and interpolated percentiles, and rebuild the report. The independent normal/uniform convolution gives P10/P50/P90 = 10.910/13.500/16.090; the seeded sample comparison uses a 0.10 dimensionless absolute tolerance. These are response percentiles, not confidence limits. Evidence locations and the rebuild command are provided in the references.

8. Findings, Limits and Recommendations

The numerical example meets its moment-comparison criteria. Application acceptance remains not evaluated because no physical model, measured input distributions or engineering acceptance limit is supplied.

8.1 Limits of use

UncertaintyStudy and load_study validate and load configuration; they do not resolve a configured evaluator or execute a screening decision. That orchestration remains the caller's responsibility. Normal priors are unbounded and can generate physically inadmissible inputs. Units are not enforced by this module.

Constant columns are rejected by regression standardization. Rank-deficient or nearly dependent inputs can make regression rankings misleading; the returned ranking contains no conditioning diagnostic. Response mappings with missing keys can produce missing values across rows. Prefixing an output can also collide with an existing prefixed input name. Inputs and output schemas require separate checks before application use.

No joint dependence model, adaptive convergence study, uncertainty on estimated tail probabilities, or physical acceptance assessment is established here. A single seeded design does not establish tail accuracy. Sampling algorithm and dependency changes can change the individual draws.

8.2 Recommendations and not covered

Before application use, supply a unit-aware response definition, measured or justified priors, dependence assumptions and an acceptance criterion. Check complete, consistent and noncolliding output names before response summarization. For a response near its application limit, repeat the analysis across sample counts and seeds until a stated precision target is met; no target is assumed here. These recommendations address the interface limits and the scope of the available numerical evidence.

Not covered: lognormal and triangular worked examples, naive random-sampling comparisons, stepwise percentile bands from fan, configured evaluator resolution and automatic screening. Their interfaces exist, but their application-specific numerical performance is not assessed in this report.
