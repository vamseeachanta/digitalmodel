Executive Summary

The code checks module is an offline calculator for supplied engineering loads. Analysis is performed to determine the tension and bending screening response of a published riser example; key results are summarized below.

  • The calculated maximum utilisation is 53.2% at 1500.0 m, below the implemented screen limit of 100.0%.
    • The supplied load distribution can be ranked by section using this calculation. The example inputs are ASSUMED - to be confirmed.
  • Pressure interaction and project design acceptance are NOT_EVALUATED.
    • Release for design use is conditional on an applicable equation source, checked factors, pressure interaction and independent benchmark evidence.

The calculation and its restrictions are set out in the worked example and the limits of use.

Introduction

The module is used to compare caller-supplied section loads with implemented resistance expressions. No global structural response, sea-state limit or installation operating envelope is calculated.

The principal workflow is the offline riser router. A configuration mapping is read, pipe properties and station loads are passed to the load checker, and station results with a governing summary and comma-separated output are returned. The documented public example and workflow registry provide the calculation basis.

The calculation is an engineering-calculations report. Marine installation controls require a coupled analysis and are outside this scalar load screen.

Analysis basis

The analysis basis is the public repository example and the equation actually called by its router. The comparison threshold of 100.0% is taken from the implemented Boolean comparison; it is not an independently established design acceptance criterion.

Geometry, material strengths, load values, temperature multiplier and the design factor are demonstration inputs: ASSUMED - to be confirmed. The named riser standard and edition are recorded in the references. An equation-specific clause, applicability assessment and project factor selection are not established by the repository example; code qualification is NOT_EVALUATED.

The rationale for the displayed limit is a dimensionless demand-to-resistance comparison. The returned pass flag follows the checker after its utilisation rounding. Results close to the threshold require an unrounded independent assessment before a design decision.

Theory and equations

The section response is calculated from an annular steel area and an annular plastic bending modulus. The implemented utilisation is an elliptical tension and bending interaction; pressure is not a term in this equation.

d = D − 2t; A = π(D² − d²)/4; Z = (D³ − d³)/6
Tᵧ = fᵧ η A; Mₚ = fᵧ η Z; U = √[(T/Tᵧ)² + (M/Mₚ)²] / f

D and d are the outside and inside diameters, t is wall thickness, A is steel area, Z is plastic section modulus, fᵧ is specified minimum yield stress, η is the temperature multiplier, Tᵧ is yield tension, Mₚ is plastic bending resistance, T is effective tension, M is bending moment, f is the supplied design factor and U is utilisation. Geometry and stress use compatible length and force units; the checker converts resistance to the force and moment units of the supplied loads.

The numerical divisors and powers in the section equations are geometric definitions, not tabulated design factors. The equation transcription and unit conversions are evidenced by the called checker and checked by the rebuild test. The separate plastic-moment property on the input model is not used by this checker and is not substituted here.

Inputs and outputs

The input mapping is supplied with geometry, material properties, factors and equal-length arc-coordinate and load arrays. A single load value can be broadcast by the router; the example supplies explicit arrays.

Outside diameter and wall thickness use metres, yield and ultimate strengths use pascals, effective tension uses kilonewtons, bending moment uses kilonewton metres, pressure difference uses megapascals and utilisation is dimensionless. The complete example input register is given in the appendix.

The output contains station coordinates, tension, bending moment, an echoed pressure difference, utilisation and a Boolean screen result. The summary contains the governing station, maximum utilisation, count of stations and overall screen flag. The comma-separated output holds the station rows. A calculation-source citation sidecar is not returned by this workflow.

The supplied ultimate strength is retained by the input model but is not used in this interaction equation. Pressure is echoed without affecting utilisation. Load signs are removed by squaring in the interaction; cyclic fatigue and load history are not assessed.

Validation evidence

The repository evidence is assessed as regression and arithmetic evidence. The inspected inventory contains 53 test function definitions across the calculation, router and example suites; this is a source inventory, not a count of independently validated engineering cases.

The existing tests check low and high loads, increased utilisation with increased demand, factor sensitivity, governing-summary output, unknown selector rejection, pipeline collapse and propagation arithmetic, and tank-shell sizing. Published examples exist for riser loads, mooring loads and tank-shell sizing. The inventory and source locators are given in the appendix.

This report adds direct recalculation of every displayed example value, a separate evaluation of the implemented annular interaction equation, and a pressure-variation check demonstrating that pressure does not enter the result. The rebuild also checks source fingerprints and exact delivered bytes.

No independent published riser benchmark, measurement record or edition-specific compliance assessment is established by these tests. The worked example is a repository demonstration rather than an external benchmark.

Limits of use and recommendations

The results are limited to the implemented tension and bending screen for the supplied section loads. Use as a complete pressure-containing riser assessment is not established.

Limits of use

Pressure interaction, collapse, local buckling, fatigue, corrosion loss, installation dynamics and global stability are not evaluated in the selected workflow. A separate standalone pipeline function does not extend this router's coverage. The router checks array presence and length, but a complete finite-value, geometry and load-basis preflight is not provided. The caller must establish positive inner diameter, finite inputs, consistent units and factored load combinations.

Utilisation is rounded before its Boolean comparison; a marginal screen result does not establish an unrounded margin. The example design factor and temperature multiplier do not establish project-specific applicability.

Not covered

Other available sub-areas are dynamic-riser screening using a separate offshore standard, mooring breaking-load screening, standalone pipeline containment and buckling resistance, and bottom-up atmospheric tank-shell sizing. These are identified as available interfaces; their equations and engineering qualification are not assessed in this analysis.

Recommendations

The next engineering step is to establish the applicable standard edition, equation clause, pressure interaction, material allowables, effective wall and load combinations before adopting a design limit. The named standards and the implemented exclusions are recorded in the references. Design release is conditional on an independent calculation or published benchmark with the same geometry, units and factors.

A first improvement slice is recommended: input validation for finite values and coupled geometry, followed by an explicitly sourced combined-loading assessment with pressure and an unrounded comparison. The router and checker define that boundary. Until those checks are established, the current result is suitable only for reproducing and ranking this demonstration's tension and bending loads.

The implementation does not record a specific equation clause; that locator is NOT_EVALUATED. No licensed table or standard coefficient is reproduced as an established criterion.
