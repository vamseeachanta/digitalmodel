1. Executive Summary

The signal processing module is a set of numerical tools for scalar time histories. Analysis is performed to determine the frequency content of a uniformly sampled voltage signal; key results are summarized below.

  • The dominant tone is resolved at @@peak_hz@@ Hz against the published @@sine_frequency_hz@@ Hz input.
    • The frequency error is @@peak_error_hz@@ Hz, below the half-bin comparison limit of @@peak_limit_hz@@ Hz. This result supports dominant-tone identification for this synthetic example.
  • The estimated high-frequency noise density is @@noise_density_estimate_v2_per_hz@@ V²/Hz against the published @@noise_density_v2_per_hz@@ V²/Hz input.
    • The estimate is within @@noise_error_percent@@ % of the input. This observed difference is reported without a noise acceptance criterion or confidence interval; no equipment acceptance is established.
  • Measured-signal use requires a documented acquisition basis.
    • Frequency content above the @@nyquist_hz@@ Hz sampling boundary is unresolved at the example's sampling rate. Instrument bandwidth, calibration and anti-alias filtering remain required inputs for measured data.

Input values and the synthetic signal definition are taken from the published example. Comparison criteria are defined in Section 3; calculated results are developed in Section 6.

2. Introduction and scope

A signal is represented as ordered scalar values with a known sample interval. Frequency analysis is performed to identify repeating components and to distribute mean-square signal content across frequency.

The module exposes spectral analysis, time-history processing and cycle counting through documented classes. Spectral density estimation and peak identification are covered here from signal definition through returned arrays and numerical comparison. The calculation is performed on a synthetic voltage source; no asset response or field measurement is represented. The public interfaces and existing evidence are identified in Section 9.2.

2.1 Not covered

Rainflow cycle counting, stress-life curves, fatigue damage, digital filter design, adaptive filtering, legacy configuration workflows, file readers and batch export are outside the worked example. Their presence does not establish their suitability for a particular engineering decision. Recorded rainflow discrepancies and the separate fatigue regression evidence are identified in Section 7; licensed-solver interfaces are not used.

3. Analysis basis and criteria

The calculation basis is defined by the published voltage-signal example and the module's documented spectral interface. Numerical comparison criteria are selected for this demonstration; operating limits are not assigned.

3.1 Signal and comparison basis

The sine amplitude, tone frequency, sampling rate, record length, white-noise density and segment length follow the SciPy reference manual, edition 1.14.1, Examples. A fixed random seed is introduced as an analysis choice because the published realization is unseeded. Its displayed sample values are therefore not comparison targets.

The dominant peak is compared with the input tone using half the returned frequency spacing. This grid-based criterion applies to this isolated dominant tone and is not a general bound on the resolution of neighbouring tones. The mean density in the upper half of the spectrum is compared with the input noise density as an observed relative difference. The band excludes the tone for this example. No noise acceptance criterion or confidence interval is assigned; the cited example supplies the averaging recipe without an acceptance band.

3.2 Sampling boundary and numerical agreement

The Nyquist boundary is the sample frequency divided by two, following the NumPy Fourier convention. A measured acquisition requires suppression of frequencies at and above that boundary before sampling. A spectral plot of sampled values cannot establish that suppression.

Each returned density bin is also compared with an independently assembled periodic-window Fourier calculation. Relative tolerance is 10−12 with absolute tolerance 10−15 V²/Hz, as specified by the report test. These tolerances check numerical agreement, not sensor accuracy. Every comparison is performed on unrounded values.

4. Inputs and outputs

The spectral calculation is supplied with a real, finite, uniformly sampled scalar array and a positive sampling rate. Frequency and density arrays are returned in a tabular object with one row per frequency bin.

The public SpectralAnalyzer class is initialized with the sampling rate and the Welch method. Its compute_spectrum operation is supplied with the signal, segment length, overlap length and Hann window explicitly. Constant detrending is applied within each segment by the underlying density calculation. TimeSeriesProcessor.calculate_statistics supplies the record length, root mean square and variance. Peak identification is performed by SpectralAnalyzer.find_peaks on the returned density. Interface locators and a complete invocation are given in Section 9.2.

Frequency is returned in Hz. For a voltage input, the power column is a power spectral density in V²/Hz, and the magnitude column is its square root in V/√Hz. Magnitude is therefore an amplitude density, not the sine amplitude. The phase column contains zero placeholders; a phase relationship is not measured by this route. The output column contract is confirmed by the implementation.

The spectral interface does not accept timestamps or unit metadata. Sample regularity, channel units, finite values, acquisition gaps, stationarity and instrument calibration require checks before the array is submitted. For other scalar quantities the squared input unit replaces V².

5. Theory and method

The density estimate is calculated by averaging windowed segment periodograms. The numerical model is a synthetic voltage source followed by ideal uniform sampling; no structural geometry or spatial boundary condition is introduced.

5.1 Signal definition and frequency grid

The public signal is xn = √2 arms sin(2π f0 n / fs) + en, where xn is voltage, arms is sine root mean square voltage, f0 is tone frequency, fs is sampling rate, n is sample index and en is zero-mean Gaussian white noise. For the one-sided noise-density input q, noise variance is q fs/2 (SciPy, Examples).

For segment length L, the frequency spacing is Δf = fs/L and frequency fk = k Δf. The index k runs from the zero-frequency term through the even-length Nyquist term (NumPy, Implementation details and Real and Hermitian transforms).

5.2 Windowed density and peak selection

For segment j, the sample mean x̄j is removed and Xj,k = Σn=0…L−1 wn(xj,n − x̄j) exp(−2π i k n/L). Here i is the imaginary unit, xj,n is the segment voltage and wn is the dimensionless periodic Hann window. The window is wn = (1 − cos(2π n/L))/2, obtained from the Hann definition with the periodic spectral-window convention.

With J complete segments, the two-sided density is Pk = Σj=1…J |Xj,k|² / (J fs Σn=0…L−1 wn²). The one-sided density doubles interior positive-frequency terms and retains the zero-frequency and Nyquist terms without doubling. This normalization follows the spectral-analysis guide, Spectral Analysis and Welch's Method. Summing the returned density multiplied by Δf gives the detrended, window-weighted mean-square estimate.

The module identifies local maxima and ranks them by density. Its minimum-distance option is forwarded directly to a sample-index distance argument, although the module description calls it a frequency distance. A requested spacing in Hz requires conversion to bins before that option is used (peak-finding parameter definition; module implementation). The worked example requests only the strongest peak and does not use a distance threshold.

6. Worked example

The published sine-plus-noise signal is reproduced by calling the module's public spectral and statistical interfaces. The realization is fixed by the declared seed; all reported values and plotted bins are obtained from those calls or calculated directly from their returned values.

The input is sampled at @@sampling_rate_hz@@ Hz for @@samples@@ samples, giving a record duration of @@duration_s@@ s. The sine root mean square is @@sine_rms_v@@ V. The estimated signal root mean square is @@rms_v@@ V and variance is @@variance_v2@@ V²; these include the added noise. Input values are from the public example.

Segments contain @@segment_samples@@ samples with @@overlap_samples@@ overlapping samples. The calculation averages @@segments@@ complete segments and returns @@bins@@ frequency bins at @@spacing_hz@@ Hz spacing. The integrated spectral density is @@integrated_density_v2@@ V². This estimate uses segment detrending and window weights, so equality with full-record variance is not an acceptance criterion.

The peak density is @@peak_density_v2_per_hz@@ V²/Hz. Peak density depends on segment length, window and tone position between bins; it is not a direct measurement of sine amplitude.

The upper-band mean is calculated from @@noise_band_start_hz@@ Hz through the sampling boundary. The mean and input reference are displayed below as an observed comparison without a noise acceptance limit.

7. Validation evidence

Numerical evidence is established for the selected synthetic spectral workflow. Existing analytical tests and narrower regression checks are distinguished from field qualification.

The existing spectral tests cover isolated tones, multiple tones, frequency spacing, detrending, alternative windows, density output, peak selection, spectral masking and several edge cases. An existing integration test exercises spectral computation, peak selection and masking together. The retained execution record contains @@validation_passed@@ passing cases with no failures in the selected evidence set (execution evidence). The distribution is given in the appendix.

The new example comparison evaluates every returned density bin against a separate windowed Fourier calculation, using the tolerances defined in Section 3. It checks the wrapper's numerical result for this input, with NumPy used for the independent transform. Shared numerical infrastructure remains a limitation of that comparison.

The repository also holds a cycle-table export readback test and a user-defined single-slope damage calculation. These checks establish output preservation and a limited closed-form damage result; they do not qualify the cycle-counting algorithm or built-in standards curves. The recorded rainflow verdict matrix retains non-conforming results for this module's cycle-counting path. A passing matrix regression preserves that finding rather than resolving it (existing evidence records).

The legacy inverse-transform tests check returned type and allow a shortened reconstruction. Their success does not establish exact sample count or waveform recovery. No measured signal, instrument certificate, field benchmark or independent equipment acceptance is established by this report.

8. Limitations and recommendations

The demonstrated result is limited to a finite, real, uniformly sampled synthetic signal with stationary white noise and an isolated tone. Additional evidence is required before measured-signal or fatigue conclusions are issued.

8.1 Limits of use

Sampling regularity and physical units are supplied by the caller and are not verified by the scalar-array interface. Out-of-band content can alias into the returned band. Segment averaging reduces random variation but discards time localization; a transient or changing speed requires a separate analysis basis. A single seeded realization does not establish uncertainty or a confidence interval.

The Fourier route uses a different power normalization from the density route, omits the even-length Nyquist coefficient and doubles the zero-frequency magnitude. Its inverse reconstruction shortens the record. Treat its power column and the window-averaged Fourier power as separately scaled quantities, rather than integrating them as V²/Hz. A density column added by a convenience method does not correct that scaling. These behaviours follow the implementation and existing inverse tests.

Cycle-counting discrepancies remain unresolved. Built-in fatigue curves require their own edition, clause, material and environmental basis; that basis is not established here. The legacy configuration workflow and command interface are not qualified by this example. No equipment operating limit, remaining life or structural acceptance is calculated.

8.2 Recommendations

Use the demonstrated density route for scalar frequency-content screening only after finite-value, timestamp, unit and acquisition checks. Record instrument calibration, sample-clock accuracy, sensor bandwidth and anti-alias response beside each measured dataset. If acquisition evidence is missing, retain the analysis as a numerical illustration and obtain the missing evidence before accepting an engineering result (sampling convention; finite-value warning).

For closely spaced tones, compare results at multiple segment lengths and document the effect of window broadening. For nonstationary signals, define time-resolved acceptance criteria before applying an averaged spectrum (spectral-analysis guide). Do not infer a phase relation from the placeholder phase column.

Before Fourier reconstruction is used, correct the frequency-grid endpoints and demonstrate exact length and amplitude recovery against independent signals. Before fatigue decisions are issued, resolve the recorded counting discrepancies and qualify the applicable curve basis. These actions follow the recorded regression findings; no repair is included in this analysis.

The worked calculation is called as follows, using the input recipe and seed defined above. The rebuild command is run from the repository root with the source directory on the Python import path.

import json
from pathlib import Path
import numpy as np
from digitalmodel.signal_processing.signal_analysis import SpectralAnalyzer
from digitalmodel.signal_processing.signal_analysis import TimeSeriesProcessor

basis = json.loads(Path(
    "docs/reports/modules/signalprocessing/public-example.json").read_text(encoding="utf-8"))
data = basis["inputs"]
fs = data["sampling_rate_hz"]
time = np.arange(data["samples"]) / fs
rng = np.random.Generator(np.random.PCG64(basis["adaptation"]["random_seed"]))
x = data["sine_rms_v"] * np.sqrt(2) * np.sin(
    2 * np.pi * data["sine_frequency_hz"] * time)
x += rng.normal(scale=np.sqrt(data["noise_density_v2_per_hz"] * fs / 2),
                size=time.shape)
analyzer = SpectralAnalyzer(data["sampling_rate_hz"], method="welch")
spectrum = analyzer.compute_spectrum(
    x, nperseg=data["segment_samples"],
    noverlap=data["segment_samples"] // 2, window="hann")
peak = analyzer.find_peaks(spectrum, n_peaks=1)
statistics = TimeSeriesProcessor().calculate_statistics(x)
PYTHONPATH=src uv run --no-project --with-requirements tests/signal_processing/signal_analysis/report-requirements.txt python docs/reports/modules/signalprocessing/build_report.py --check
PYTHONPATH=src python -m pytest tests/signal_processing/signal_analysis/test_module_report.py

The input recipe, generated signal digest and full plotted arrays are retained. Exact retained-byte comparison is performed in the pinned environment by the separate continuous-integration job.
