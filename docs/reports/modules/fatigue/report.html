1. Executive Summary

The structural fatigue package is mapped and an explicitly bounded arithmetic example is checked. The synthetic counted-cycle block gives total damage 0.3 dimensionless and 1500.0 cycles processed. These values agree with the independent rational derivation under the numerical comparison budget in Section 6.

The synthetic curve has no material identity. Standard coefficients, signal counting, spectral methods and physical remaining life are not qualified by this example. Broader numerical qualification remains open.

4. Theory and Equations

The artificial definition is N*S^m = A, with A and m supplied in Table 1. The independent derivation uses integer multiplication and exact rational division: N_i = A / S_i^m; d_i = n_i / N_i; D = Σ d_i; C = Σ n_i. N_i and n_i are cycles; S_i is MPa; d_i and D are dimensionless; C is processed cycles.

The coefficient unit is cycle*MPa^2 for the specified exponent. Each allowable life is obtained by dividing the coefficient by the squared supplied range. Each contribution is obtained by dividing its applied count by that allowable life. The exact quotients and their rational sum are compared with module results in Table 2. Synthetic input definition supplies the arithmetic basis; get_allowable_cycles and calculate_damage supply the evaluated methods.

6. Validation Evidence

The report tests assert every unrounded example quantity and its unit against an independent hand calculation, then compare parsed visible quantities with that oracle and a fresh module call. Controlled changes to allowable lives, damage contributions, the total and the processed count exercise visible result bindings.

The numerical regression tolerance is relative 32 epsilon, with zero absolute tolerance; epsilon is the binary64 spacing above unity, expressed as 2^(-52). The positive-input path has fewer than eight rounding stages through reciprocal-square evaluation, multiplication, division, summation and oracle conversion. Four epsilon per stage allows for the power evaluation. This budget addresses roundoff for this example; it does not represent physical uncertainty.

The existing S-N suite and existing accumulation suite provide regression coverage beyond this example; passing them does not independently qualify their standard data. Two isolated rebuilds and the delivered records are compared byte for byte. Reproducibility is not physical validation.

frequency-domain methodsNOT_EVALUATEDPSD units, spectral-moment checks and independent damage-rate benchmarks
physical remaining lifeNOT_EVALUATEDQualified material/load basis, service duration and acceptance criterion
Table 4. Unevaluated methods remain outside this arithmetic example.

The counting registry distinguishes paths and a declared retained residual convention. The time-series analysis entry point refuses damage on its affected structural counting path; the structural counter remains available for diagnostic use. Other paths have distinct contract records. Their recorded status is not transferred to this example and no counting refusal is changed or bypassed.

Review findings beyond scope: the single-slope cutoff caps finite life even with a zero fatigue limit; the synthetic cutoff deliberately avoids that branch. Nonpositive ranges or counts are skipped by accumulation; this positive-input example does not qualify malformed or non-finite input handling. The accumulator also exposes a repeated-block remaining-cycle estimate; no physical life follows without a qualified load basis and duration. These concerns are findings for broader qualification, not behavior changes.

No full-module, standards-compliance or solver-qualification claim is made.

8. Recommendations

Way forward

  1. Review standard coefficient provenance and material selection separately, with independently derived curve points.
  2. Qualify a counting path against hand-counted range, mean and count distributions under its declared residual policy before damage integration.
  3. Check spectral moments and damage rates against independent benchmarks with explicit frequency and PSD units.
  4. Supply a service-duration basis, material evidence and governing acceptance criterion before reporting physical remaining life.

The parent module-report scope remains open for these numerical qualifications.

10. Appendix

Rebuild

From the repository root, set FATIGUE_REPORT_PYTHON to a Python interpreter containing the repository dependencies. The supplied TMPDIR, UV_CACHE_DIR and PRE_COMMIT_HOME remain exported:

PYTHONDONTWRITEBYTECODE=1 MPLCONFIGDIR="$TMPDIR/matplotlib" PYTHONPATH=src uv run --no-project --python "$FATIGUE_REPORT_PYTHON" python docs/reports/modules/fatigue/build_report.py --output-dir "$TMPDIR/fatigue-report"

The explicit output directory receives report.html, changes.json and sources.json. Calculation and rendering use memory; no intermediate files are written. The fixed issue date is a revision record, not a runtime timestamp.
