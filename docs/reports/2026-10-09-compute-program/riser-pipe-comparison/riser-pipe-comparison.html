Program benchmarking analysis: riser pipe modules

Summary

Internal program benchmarking analysis for one generic assumed pipe. The comparison covers repository-module outputs; standard conformity is not established.

API RP 1111: governing returned check is propagation, case operating, utilisation 97.8% — within the module unity criterion. Dispositions use unrounded results.

API RP 2RD: governing returned check is collapse, case operating, utilisation 40.4% — within the module unity criterion. Dispositions use unrounded results.

API STD 2RD: governing returned check is combined, case operating, utilisation 174.0% — above the module unity criterion. Dispositions use unrounded results.

API RP 1111 module edition metadata is unqualified: the strategy defaults to 2015, with an edition label that conflicts with the standards inventory. The comparison uses that implementation without endorsing the edition label.

Discussion and limits

API RP 2RD burst utilisation is 20.0% higher than its comparator for the same supplied pipe and loads. The modules return equal characteristic pressure capacities and different design capacities for these pressure checks.

API STD 2RD collapse utilisation is 11.1% higher than its comparator for the same supplied pipe and loads. The modules return equal characteristic pressure capacities and different design capacities for these pressure checks.

Not Evaluated: the legacy module returns no combined-load check (tracked in #377). A ranking of complete code assessments is not established. Not Evaluated: legacy edition and clause locators are not established; STD clause locators are inherited from repository references and have not been checked against a licensed standard. RP 1111 returns propagation but no hoop or combined check; neither 2RD strategy returns propagation. The report uses one generic pipe; shallow and deep reference configurations are tested separately. The next step is to qualify the citation basis and complete legacy combined-load coverage before a design disposition.
