Proposed reusable contract

The following requirements are proposals for separately reviewed production repairs, not claims that all five sources enforce them. Content integrity is testable offline; authentication of process observations and engineering acceptance require additional evidence.

RequirementProposed adversarial acceptance case
Independently declare the exact required input set.Remove a mandatory source while retaining another hash: fail before child launch. Empty or nonempty partial manifests never satisfy exact coverage. Optional-output absence cannot excuse a missing required input.
Reject missing, unreadable, substituted and escaping inputs.Exercise read denial, changed bytes, source locator substitution and path escape. Bind each path explicitly, even when distinct files have identical bytes.
Keep input and output identities distinct, including hard links.Reject one underlying file used for both roles; permit different files with identical contents. Define alias handling explicitly.
Bind source and retained artifact bytes before and after work.Mutate sources, manifest, native exports or saved simulation between phases: fail. Independently recompute retained-file hashes instead of trusting a child hash string.
Validate completed child proof independently.A fake child returning only ok=true, thread counts and a hash must fail. Omit completion, settings readback, manifest binding or result arrays; corrupt one retained readback sample: fail.
Separate byte preservation from physical settings readback.Unchanged input bytes cannot replace observed native settings, units and coordinate frames. Report content checks separately from physical acceptance.
Observe cleanup after requesting termination.Timeout, failed wait, active descendants or failed handle release deny success and further phases. Record successful waits and whole-job absence separately from a termination request.
Retain diagnostics without a success verdict.Failure leaves error stage/type and available diagnostic artifacts; diagnostic output enumeration cannot be promoted to required-input coverage.
Exercise optional licensed API absence and enroll offline tests.Offline inventory must work without importing the optional licensed API merely to prohibit construction; also guard already-loaded constructors where relevant. Keep tests under executed CI roots, not metadata alone.

Known limits and way forward

No native harness, solver-smoke CLI or whole solver tree was run. Cleanup implementation was read without importing either process module. Inventory validation does not authenticate producer observations, qualify numerical results, validate engineering acceptance, or protect against hostile concurrent filesystem replacement. Production raw-byte identities differ from these normalized review digests.

Further work requires a separately reviewed bounded repair based on a concrete consumer defect, then targeted fake-child tests, native cleanup qualification where needed and independently reviewed engineering criteria. Additional adapters and generic production validation remain outside this slice. The complete-bundle and native-harness owners should be reused before proposing another shared helper.
