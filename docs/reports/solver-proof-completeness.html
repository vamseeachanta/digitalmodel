The missing model_results.py is omitted, while AST inspection establishes its unconditional import. This proves a mismatch between the declared source inventory and the import dependency. It does not prove a successful child with the module missing. Adapter adoption will explicitly declare this dependency and test refusal before child launch.

B — cleanup claim gap. A source-only operating-system double raises PermissionError during signalling. The final caller result is terminated=true, running=false, although the injected liveness observer remains true. The reusable contract rejects the equivalent unconfirmed observation. A separate adapter repair will preserve diagnostic failure and require a final observation; it will also distinguish root-process absence from owned-tree absence.

The observation tests read frozen Git bytes so later adapter repairs will not be required to preserve the audited defects.

Reusable contract and method

solver_proof.py is independent of optional solver APIs. The caller supplies a trusted mapping of required input names to pinned digests, explicit required output names, untrusted child evidence, and a separate parent-owned cleanup observation. capture_inputs will be called before launch; audit_proof will be called after observed cleanup. Optional diagnostics are retained outside the mandatory manifests.

names(observed inputs) = names(declared inputs) = names(child input manifest)
SHA256(current input bytes) = pinned input digest = child input digest
names(observed outputs) = names(required outputs) = names(child output manifest)
SHA256(current output bytes) = child output digest
cleanup confirmed = successful owned-tree observation AND exited root AND zero active processes
complete = every required comparison passes AND child reports success AND cleanup confirmed

The set comparisons and cleanup predicate implement the acceptance proposed in issue 2085. The digest method is illustrated by the public NIST SHA-256 worked example, One Block Message Sample, PDF modified 2012, opened successfully on 2026-10-20. No physical equation, coefficient, engineering tolerance or licensed-publication value is introduced.

Worked example: inputs, method and answer

The runnable example writes separate input and fake-result files containing the three ASCII bytes abc. The independently published digest is ba7816bf8f01cfea414140de5dae2223b00361a396177a9cb410ff61f20015ad. Each required manifest contains exactly its one declared filename; no optional diagnostic is counted.

PYTHONPATH=src uv run --no-project python examples/solver_proof_completeness.py <new-scratch-directory>
observed:       complete=true,  failures=[]
requested_only: complete=false, failures=["cleanup_unconfirmed"]

The positive observation is a synthetic fixture with an exited root and zero active processes. The second fixture contains only a termination request. Both audit answers and original fixture bytes are retained and read back; no existing directory is overwritten, no solver is imported, and no process is terminated by the example.

Checks and limitations

The focused tests cover missing/unreadable/substituted inputs, changed bytes during hashing, path redirection, exact manifests, retained output bytes, fake-child flags, unconfirmed cleanup, independent expected digests and example readback. A fresh interpreter rejects optional solver imports while importing the helper. Inventory digests are independently recomputed from frozen Git bytes.

Completeness is not engineering acceptance. Native settings, units, result arrays, simulation completion and readback remain adapter-specific checks. The helper cannot authenticate a caller-supplied observation or discover undeclared dependencies. A caller-controlled declaration is not approval evidence. Symlink/reparse checks and metadata comparisons are observational; hostile concurrent directory replacement, Windows containment and full process-tree observation are not qualified here. No existing solver writer is migrated. No licensed solver is started, imported or queried. Second-provider review remains pending.
