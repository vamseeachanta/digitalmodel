X03 private-source fix-up plan

Scope will follow owner-confirmed X03, 2026-10-09: raw DWGs will move to private storage; only abstracted geometry will remain eligible for public publication; history will not be rewritten. The fix-up will address review 6085227528 on the existing draft stack for issue 2272.

  1. Six originals and a filename-bearing SHA-256 manifest will be retained in the owner-authorized private archive on ace-linux-1: /mnt/ace/private/digitalmodel-hulls/. Every copy will be verified against its Git blob before tracked removal. Directory permissions will be 0700; private files will be 0600.
  2. The X03 branch will remove the six tracked DWGs and guard both lower- and upper-case extensions in that folder. Provenance will identify the role path and retained historical exposure. Tests will first establish the missing source-removal guard and explicit private-source option. The exporter will require --source-dir and will report an unavailable directory without its private path; the real-source regression will accept HULL_DWG_SOURCE_DIR and will skip when private access is not configured. Unit and literal collision gates will remain enforced.
  3. The A07 branch will replace source-manifest records with stable ordinal, sha256 and size only, freezing the current manifest array order as the stored SHA-256-to-ordinal mapping; ordinals will not be derived from directory enumeration or filename sorting. The exporter will continue resolving each requested source by the existing probe record filename; manifest sanitization will not broaden to probe.json. The regression will compare the committed order against the existing probe array. Unknown extra files will not be consumed by the exporter, and the all-six regression will reject a mismatched directory inventory or source digest. Only an unset access variable will cause a skip; configured-but-invalid private access will fail. This mapping will cover only these six already historically exposed sources. A regression will first reject extra source metadata. The A07 change will be committed and merged into X03 without rebase or history rewrite.
  4. Both branches will run focused probe/build/exporter tests, lint and whitespace checks. Review will hunt privacy leaks, ordinal instability, missing-source regressions and unintended publication-gate changes against frozen text packets. The raw originals will remain in the A07 proposed tree until X03 is applied; both PR bodies will therefore require owner-reviewed squash merge together and will prohibit independent A07 merge. X03 will keep A07 as its PR base and will carry the deletions plus ignore guard in one pathspec commit. Only existing task branches will be pushed without force; git ls-remote will verify the pushed heads. Both draft PRs will receive review comments; the X03 body will state the confirmed decision.

Acceptance will require six verified private originals, zero tracked DWGs in the X03 hull folder, both-case ignore coverage, six metadata-neutral public manifest entries, passing focused regressions with zero skips on ace-linux-1 using both private-source and decoder environment variables, and remote heads matching local commits. Git ls-files will establish zero tracked DWGs in the X03 hull folder, and private manifest SHA-256 will pin the verified archive mapping. The explicitly requested private host archive will define this task retention scope; private repository migration and backup will remain outside this owner-authorized fix-up. Private storage will be reported as a local archive, not a private Git or backup copy. The copy/removal operations will use raw bytes without decoding; the all-six integration tests will decode in memory and will suppress drawing diagnostics and will serialize no title-block values. No geometry will be published, no main branch will be pushed or merged, and owner merge authority will remain unchanged.
