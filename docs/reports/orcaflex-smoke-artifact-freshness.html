OrcaFlex smoke artifact freshness

Summary

The existing finite-result, one-thread and simulation-readback checks are extended to reject pre-existing smoke.dat or smoke.sim entries before model construction. A failed save cannot borrow an earlier simulation as current evidence. Previous files, directories and symlinks are preserved. The affected result returns ok=false and stage=prepare.

Freshness is a prerequisite for the save/reload proof in issue 2082. This change establishes offline contract behavior; native acceptance for the changed source is NOT_EVALUATED.

Method and criterion

The output directory is created if needed. Both reserved artifact names are checked before the first model is constructed. Any existing entry, including a dangling symlink, produces a structured failure. An unrelated file does not prevent the probe. The caller shall retain exclusive ownership of the directory throughout the probe; the preflight does not provide locking against concurrent writers.

The existing criteria remain those of the bounded plan dated 2026-09-10, Bounded design: each model requests and reports one thread, static tension is finite, dynamics complete with at least two finite samples, and the saved simulation independently reloads with the expected line, completed state and matching finite sample count. The two-sample minimum is a smoke criterion, not a convergence limit.

The official Model reference, accessed 2026-10-20, defines the constructor's threadCount parameter and the threadCount, simulationComplete and LoadSimulation interfaces. No new physical constants, coefficients or engineering acceptance limits are introduced.

Worked offline example

The input and expected-answer fixture contains chosen synthetic values. A fake API supplies these results and writes synthetic artifacts. No physical simulation is performed, and the values are not qualified engineering inputs. The independent calculations are written in the executable test docstring.

Run from the repository root with the repository's test dependencies:

python -m pytest tests/solvers/smoke/test_orcaflex_smoke_example.py -q -p no:cacheprovider

For the freshness counterexample, place a synthetic previous smoke.sim in the selected directory and configure the fake save to produce nothing. The earlier implementation returned ok=true by reloading that file. The preflight now returns ok=false at prepare, constructs no models and preserves the previous bytes. Select a new output directory for the next attempt; previous evidence need not be removed.

Verification evidence

Before the repair, the freshness tests produced nine failures and one pass. After the repair, all ten freshness tests and all 42 existing numerical, completion, thread-count and readback contract tests passed. All three worked-example cases passed. Eight existing workflow and CLI tests and both CI-registration tests passed.

The existing engine-dispatch test cannot complete in the isolated test environment: digitalmodel.engine imports the unavailable assetutilities dependency. The same test and import are present on the base revision. That integration result is not established by the passing probe tests.

The original native proof in the earlier smoke report concerns earlier source. It is not native acceptance of this revision. A second-provider review and native acceptance remain outstanding.

Limits and way forward

The freshness check changes reuse of the reserved filenames from overwrite to failure. The existing CLI exit-code, workflow failure-reporting, scratch-cleanup, AQWA dispatch and explicit host-disclosure contracts are retained. Exact serialized numerical equality and engineering adequacy remain outside the smoke criterion.

Other evidence writers may require the same freshness criterion; no audit of those writers is established here. The related completeness audit is tracked in issue 2085. Native acceptance of fresh output and rejection of reused output should follow on an authorized installation before merge.
