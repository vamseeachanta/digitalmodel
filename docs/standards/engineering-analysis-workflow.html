Engineering analysis workflow

Revision 1 · 13 September 2026 · Owner: digitalmodel · Ecosystem routing.

Revision 1 composes with ENG-ANALYSIS-CRITERIA Revision 1. This operating definition applies the engineering analysis criteria across programs, components, assemblies and structures. It defines actions and evidence handoffs; it is not an installed orchestration engine. Each analysis records the criteria revision and this workflow revision. Existing source ownership, authorization and reciprocal-review requirements govern every stage.

Package and handoff contract

Use one owner-issued analysis ID and dataset ID; preserve existing catalog IDs. The owning repository retains the basis, study configuration, case ledger, verification register, dataset manifest, report and reproducible generation entry point. Raw evidence follows the shared residence contract. Logical evidence references resolve through local configuration; public artifacts shall not embed private machine paths or credentials. A reference is not a backup.

Each case record binds exact inputs and dependencies, source/load/model descriptors, parameter key, revision and attempt ID. Each response binds value or typed null, units, definition/location, criterion/comparator, verification evidence, intended-use readiness and limitations. Canonical serialization distinguishes absent, null, empty, not applicable, failed and true zero; hashes bind metadata as well as values. No failed or rejected case disappears from the ledger. Numerical convergence variants retain their relationship to the physical case rather than inflate physical coverage counts.

The handoff records the common stage number and domain action name, owner, artifact references/digests, gate decision, unresolved items and the next authorized action. Native completion, numerical verification, engineering qualification and publication are separate state fields. An all-green solver log or a populated database cannot substitute for these decisions. Existing standing approvals cover only their recorded scope; changed scope follows the shared planning route.

Program workflows and current rollout

ANSYS workflow maps the stages to structural model/result definitions and retained evidence. AQWA workflow maps them to hydrostatics, diffraction/radiation conventions and frequency/heading coverage. Other programs inherit the common stages through separately reviewed domain mappings; software-specific thresholds and physics are not universalized.

Current delivery comprises documentation definitions in the digitalmodel branch. Automated enforcement, adapters, native campaigns and cross-repository installation are not established by these documents. The ANSYS adapter remains under issue 2119; the AQWA unit-box basis remains under issue 141. Original datasets retain one authoritative owner; no competing catalog or database service is introduced.
