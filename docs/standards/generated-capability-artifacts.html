Regeneration contract

scripts/check_generated_html.py registers deterministic HTML producers and explicit JSON sidecars. HTML ownership and brand checks retain their existing scope. Sidecars participate in output removal, successful-output validation and byte comparison. A copied sidecar is removed before execution, so a producer that stops writing it cannot pass using stale bytes.

uv run python scripts/check_generated_html.py --check

The command copies inputs into a temporary shadow tree and leaves the source checkout unchanged. The existing documentation workflow runs it for generator, source and documentation changes. Required scientific dependencies are declared by the repository; an isolated test environment needs the same generator dependencies. A nonzero result identifies regeneration errors or the relative paths with byte differences.

The shadow includes package version metadata for source-only imports. Generator child processes discard inherited Git repository bindings so their working directory, rather than a caller's Git environment, selects the tree.

The regeneration contract is supported on Linux with LF line endings in the checkout. Generators use platform-native newlines: Windows regeneration can produce CRLF bytes that differ from committed LF bytes, and a CRLF checkout differs from Linux output. Newline-only drift can have an empty text diff because the diagnostic splits text into lines. Run this byte comparison from a Linux checkout with LF line endings.

Worked example: unchanged page, stale sidecar

Inputs: a committed page containing <html>same</html> and a sidecar containing {"status":"current"}. The regenerated page is identical, while its sidecar contains {"status":"stale"}. Method: compare both registered files as bytes. Answer: the JSON differs, so freshness fails despite unchanged HTML. These literal fixtures are used in tests/capabilities/test_sidecar_freshness.py; no engineering constants or solver outputs are involved.

Pressure-only wall-thickness data

The source decision is digitalmodel issue 1903, sidecar reconciliation decision dated 29 July 2026. The existing sweep applies pressure with zero effective tension and bending moment. Its unloaded combined check is omitted from exported checks, because a zero could be interpreted as an evaluated tension and bending capacity. Pressure-dependent checks named combined_loading remain included. The study inputs, strategy equations, governing utilizations and passing-wall results are unchanged.

Export fails if any omitted combined value is not exactly zero or if combined governs the result. The value is checked before rounding, so a small nonzero value cannot be hidden by the projection.

Independent projection example: input checks {"burst":0.5,"combined_loading":0.25,"combined":0.0} become {"burst":0.5,"combined_loading":0.25}. The largest utilization remains 0.5. These arbitrary dimensionless test values establish the projection behavior; they are not engineering acceptance limits. Both the HTML and JSON carry the pressure-only limitation. The dataset reshaper consumes these exported checks without adding the omitted check back.

Coverage and limits

The added sidecar coverage is explicit: wall-thickness, dynacard troubleshooting and sloshing explorer JSON. It is not a census of every JSON file. Other JSON outputs require separate registration before this freshness check covers them. Existing non-reproducible HTML exclusions remain documented in scripts/generated_html_ownership.py. Licensed solvers are not needed by the registered deterministic generators.

External dataset publication is a separate maintainer action. This change does not establish the contents or freshness of any hosted dataset.
