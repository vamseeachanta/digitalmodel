Signed residual operators for analysis criteria

Summary. The reusable comparison contract distinguishes a signed value from an absolute residual and a relative error. Each criterion names its operator, comparator, units and source. Numerical PASS means only that the declared comparison holds; source qualification and engineering acceptance remain separate. This supplement supports the engineering analysis criteria, AC-01, AC-02 and AC-08.

Operator definitions

Let q be the observed value and r the reference in the declared response unit U. The comparator is one of <, <=, > or >=. Equality is decided by that comparator, without an implicit tolerance. The limit and comparator basis are required inputs.

OperatorMetricMetric and limit unitBasis
signed_valueqUThe observed quantity is compared directly. This is the identity operation; it does not imply a magnitude bound. A reference is refused.
absolute_residual|q − r|U NIST DLMF, equation 3.1.8. The reference is required, including an explicit zero for a residual origin.
relative_error|q − r| / |r|1 (dimensionless)NIST DLMF, equation 3.1.9, for a nonzero reference.
 Explicit transformations precede the declared comparator.

Dimensioned floors and zero references

With an explicitly supplied positive denominator floor f in U, relative error is defined here as |q − r| / max(|r|, f). This is a declared software policy extending the nonzero-reference definition; NIST supplies no floor or acceptance limit. Both reference_floor and floor_source are required together. The floor is refused for the other operators. A relative limit has unit 1; the denominator floor has the response unit.

A zero reference without a floor returns NOT_EVALUATED, even for a zero observation. A nonzero near-zero reference without a floor uses its actual magnitude; no hidden cutoff is introduced. Missing observations or required references and mismatched units also return NOT_EVALUATED, with a reason and no metric. Invalid definitions, nonfinite numbers and binary floats are refused with ValueError. Unit tokens match exactly; conversion and alias resolution are not implemented.

A denominator floor is distinct from the dimensioned absolute-error allowance in a hybrid rule |q − r| <= max(relative_limit × |r|, absolute_floor). That rule can use absolute_residual with its independently established limit supplied by the caller. This module does not silently translate either floor policy into the other or choose engineering tolerances.

Reusable interface and evidence

The public interface is digitalmodel.infrastructure.analysis_criteria: Quantity, Criterion and CriterionResult. Inputs use exact decimal strings or Decimal. Comparisons use exact rational arithmetic, independent of ambient decimal precision and rounding. to_record() retains inputs, units, criterion source, comparator, limit, floor source and status as JSON-compatible values. A metric is stored as integer numerator and denominator strings; absence is JSON null, distinct from the true-zero numerator. Sources are caller assertions and require separate verification; nonempty text alone does not authenticate a source.

from digitalmodel.infrastructure.analysis_criteria import Criterion, Quantity

# Synthetic hand calculation: |-2 - 0| = 2 > 1 kN.
criterion = Criterion(
    operator="absolute_residual", comparator="<=", response_unit="kN",
    limit=Quantity("1", "kN"), source="Synthetic hand calculation in this example",
)
result = criterion.evaluate(Quantity("-2", "kN"), Quantity("0", "kN"))
assert result.status == "FAIL"
record = result.to_record()

Tests and limitations

Tests include equal-magnitude positive and negative violations, signed comparators, strict and inclusive boundaries, positive and negative references, zero and near-zero references, dimensioned floors, malformed definitions, unit mismatches, missing evidence, JSON readback and repeating ratios under changed decimal contexts. Expected metrics are derived by hand in test docstrings. Cylinder parity tests compare every check in a synthetic complete case with the existing evaluator; that is interface regression coverage, not an independent physical reference or native validation. Sources, applicability and limit selection remain the analysis caller's responsibility.
