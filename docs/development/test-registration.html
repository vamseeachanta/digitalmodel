CI test registration

The registration audit detects test files that lack documented ownership, gate metadata, configured pytest arguments or touched-domain selection. Existing defects and collection exclusions remain visible as exact ledger entries. Passing the audit establishes enrollment consistency against that ledger; it does not establish that the tests passed or were collected.

Run the audit

uv run --no-project --with pyyaml==6.0.2 python scripts/ci/check_test_registration.py

The required ci-harness-tests job runs this command independently of the domain matrix, followed by the regression tests. No test module or conftest is imported by the audit. Configuration is read from the same .claude/quality-gates.yaml commands consumed by the domain workflow.

Method and sources

  1. Discover Python files beneath tests/ using the filename patterns in pytest.ini, including files suppressed by collection policy.
  2. Resolve the most specific matching ownership root from tests/DOMAINS.md, respecting the explicit overrides in scripts/ci/detect_touched_domains.py.
  3. Require an enabled, blocking gate whose metadata and positional pytest roots cover the file. Parse ignores separately from positional arguments; a path appearing as an ignore value is not an execution root.
  4. Account for norecursedirs, supported addopts, declarative collect_ignore and collect_ignore_glob. Read conftests with AST rather than executing them.
  5. Check that touched-domain selection includes the collecting domain. A detector exemption requires an explicit, unconditional invocation in the independent harness.
  6. Subtract only exact findings in config/ci/test-registration-exceptions.json. Reject new findings, empty reasons and stale entries.

The executable sources are scripts/ci/check_test_registration.py and scripts/ci/detect_touched_domains.py. Command consumption and independent execution are defined in .github/workflows/quality-gates-by-domain.yml. Expected regression results are derived from explicit fixture membership in tests/scripts/test_test_registration.py; no engineering equations or standards-derived constants are used.

Worked example: a new sibling is omitted

The input initially contains this registration:

Discovered file: tests/example/test_example.py
Documented domain root: example → tests/example/
Gate test_roots: [tests/example/]
Gate command: python -m pytest tests/example/test_example.py

A new file tests/example/test_sibling.py is added. Both files match the documented and metadata directory root. The literal command names only the original file. The independent set calculation is: 

Discovered = {test_example.py, test_sibling.py}
Commanded = {test_example.py}
Discovered minus Commanded = {test_sibling.py}

The answer is a failing audit with this finding:

missing-command|example|tests/example/test_sibling.py

Changing the command to python -m pytest tests/example/ covers both files. An existing exception for the original file cannot acknowledge the new sibling. The regression test_existing_directory_cannot_hide_new_undispatched_file implements this example without importing either fixture file.

Existing debt and intentional exclusions

Each ledger key has the form kind|domain|repository-relative-path. Its nonempty reason states the source of the existing boundary or gap and the unresolved work. Entries acknowledge defects; they do not suppress test execution, repair commands or establish test readiness. New files in an excluded directory require their own reviewed disposition. Removing a gap also requires removing the corresponding stale ledger entry.

Existing command and metadata omissions remain tracked under issue 2083. Existing collection-policy debt remains associated with issue 1923. The prior solver-smoke registration case from issue 2082 remains covered by its focused regression. The existing gate configuration and collection exclusions are preserved by this change.

Limits

The scope is file enrollment beneath tests/, not repository-wide test coverage. Test functions, markers, runtime skips, plugin behavior and tests outside that tree are not qualified. Static analysis supports the repository's literal Python or uv pytest commands and declarative exclusions; unsupported shell composition, selection expressions and dynamic collection policy fail the audit. Command ignores are treated conservatively as exclusions even where an explicit pytest argument could override them. Independent review and hosted execution remain separate acceptance steps.
