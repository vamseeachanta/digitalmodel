Coverage status claims

Summary

Installation report design-data status text is checked against the supplied summary counts before HTML is returned. Singular failure and cell nouns, case variants, and repeated spaces, tabs or newlines have the same validation as the canonical wording. Every occurrence is checked, including contradictory later claims. Accepted text is escaped and retained as supplied.

Inputs and method

The input is a summary containing a counts mapping and a report configuration containing a design_data row with a status string. The following checks use integer equality. The planned count is the sum of all values in the mapping; an absent named status has a zero count.

Recognized wordingRequired equality
V of P baseline cases verifiedV == counts.get('VERIFIED', 0) and P == sum(counts.values())
F numerical failure or F numerical failures F == counts.get('FAILED', 0)
M missing cell or M missing cells M == counts.get('MISSING', 0)

The regular expressions use \s+ between words, failures? and cells? for optional plural suffixes, re.IGNORECASE for case variants, and re.finditer to check every occurrence. No engineering coefficient or acceptance limit is introduced.

Worked example: input, calculation and answer

The synthetic example specified in issue #2349 has 61 verified, 1 failed and 1 missing case. Independent addition gives 61 + 1 + 1 = 63 planned cases. Therefore the status below renders; replacing 63 with 64 raises ValueError because 64 does not equal 63. The following example runs from a checkout with the renderer test dependencies.

from html import escape
from digitalmodel.workflows import vessel_capability_report as report
from tests.workflows.test_installation_report_layout import design_row, summary

# Synthetic counts: issue #2349's matching-singular example.
data = summary()
data['counts'] = {'VERIFIED': 61, 'FAILED': 1, 'MISSING': 1}
status = '61 of 63 baseline cases verified; 1 numerical failure and 1 missing cell'
config = {'design_data': [design_row(status=status)]}
assert escape(status) in report.render_html(data, config=config)

config['design_data'][0]['status'] = status.replace('of 63', 'of 64')
try:
    report.render_html(data, config=config)
except ValueError as error:
    assert '64 planned cases stated, source lists 63' in str(error)
else:
    raise AssertionError('Contradictory planned total was accepted')

For the original synthetic fixture, 61 verified + 0 failed + 95 missing = 156 planned. Claims of 60 verified, 160 planned, 1 numerical failure or 1 missing cell are each inconsistent. These hand calculations provide the expected outcomes of the parametrized regressions; no expected result is generated by the validator.

Limits and way forward

This is a bounded wording check, not a general natural-language parser or an independent audit of summary counts. Unrecognized prose makes no validated count claim. Synonyms, reordered wording, numbers written as words, and singular baseline case verified are outside the recognized grammar. Use baseline cases verified even for a single planned case. Broader wording requires a separate grammar change with renderer regressions.

Repository sources and executable examples

  • Case producer: _case emits FAILED when evidence checks fail.
  • Summary producer: generate_report counts case statuses with Counter.
  • Original renderer regressions: summary() defines the synthetic source counts.
  • Additional renderer regressions: all count types, later contradictory variants, matching variants, source immutability and the worked example.
