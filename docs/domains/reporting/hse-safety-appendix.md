# HSE and safety appendix

## Summary

Every engineering report carries an HSE and safety appendix. It gives the public
incident history of the equipment the report analyses, the recorded failure
modes and causes, and the lessons for the design in hand.
`digitalmodel.reporting.hse_section` adds the appendix to a report skeleton as
six required slots and fills them from the section generated by the
worldenergydata equipment failure table.

## Revision history

| Revision | Date | Change and reason |
|---|---|---|
| Initial | 2026-11-12 | Appendix added to the report skeleton so a report is not complete without its HSE and safety content. |

## Subsections

The headings are fixed. The letter follows the report's appendix order (F by default).

| Slot key | Heading | Content |
|---|---|---|
| `hse_data_used` | F.1 Data used | Each data set, with records read, records for this equipment, period and date read |
| `hse_incident_history` | F.2 Incident history | Count, period, counts by decade, most recent records as the source words them |
| `hse_failure_modes` | F.3 Failure modes and stated causes | Counts by failure mode; counts by cause only where the source states a cause |
| `hse_public_cases` | F.4 Illustrative public cases | Two or three investigated cases with what failed and the cause the investigation states, with page numbers |
| `hse_lessons` | F.5 Lessons for this design | Each finding or recommendation, with the report section that answers it |
| `hse_references` | F.6 References for this appendix | Every data set and report with link and date read |

## Rules

- The appendix is generated. This module adds no incident text of its own.
- A cause appears only where the source data codes it or the cited
  investigation states it. Nothing is inferred from an event type.
- Every number carries its source and the date the source was read.
- No operator, contractor, vessel or facility is named.
- A report is not ready while a lesson has no design response.
  `load_hse_appendix` refuses such a section unless `allow_open=True`, which is
  for drafts.

## Use

Generate the section for the report's equipment class (one of `riser`,
`mooring_line`, `pipeline`, `jack_up`, `lifting_rigging`, `wellhead_conductor`,
`fpso_topsides`):

```sh
python -m worldenergydata.safety_analysis.equipment section \
  --sources sources.json --equipment-class mooring_line \
  --design-links links.json --out mooring-hse-appendix.md
```

This writes `mooring-hse-appendix.md` and `mooring-hse-appendix.json`. Then:

```python
from digitalmodel.reporting import ReportSkeleton
from digitalmodel.reporting.hse_section import load_hse_appendix, with_hse_section

skeleton = with_hse_section(ReportSkeleton.from_yaml("mooring_skeleton.yml"))
content = {**analysis_content, **load_hse_appendix("mooring-hse-appendix.md")}
print(skeleton.completeness(content, provenance=provenance).summary())
skeleton.build_html(content, provenance=provenance, output_path="report.html")
```

`with_hse_section` appends the appendix once. `completeness` then reports the
six slots as missing until the generated section is loaded.

## Worked example

- Inputs: a one-section skeleton with one required slot, and a generated
  appendix with the six fixed headings (the synthetic fixture in
  `tests/reporting/test_hse_section.py`).
- Method: `with_hse_section` adds six required slots; `hse_content` splits the
  generated text at each `### F.n` heading and converts tables, bullets and
  bold text to HTML with all text escaped.
- Result: before loading, `completeness` reports 1 of 7 required slots filled.
  After loading, 7 of 7. A section with heading "F.2 History" in place of
  "F.2 Incident history" is refused.

## Checks made on the generated section

The checks are structural. They do not prove a count or a case statement; that
is done where the section is generated.

- `check_sidecar` returns a list of problems: no equipment class; no data
  source; a source without a public link or without a real calendar date read;
  no references; a lesson whose design response is blank, not text, or still
  the generator's placeholder; any open item reported by the generator. With
  `allow_open=True` the lesson and open-item checks are skipped.
- `check_consistency` returns a problem when the text does not print a source
  with its link and date read, or a reference, that the sidecar lists.
  Only the text of the six subsections counts, because only that text is
  placed in the report. Text before the first subsection is not placed.
- A subsection number that appears twice, or subsections with different
  appendix letters, are refused.
- Links are rendered only for plain `https` addresses made of URL characters.
  All other text is escaped, including quotation marks.
