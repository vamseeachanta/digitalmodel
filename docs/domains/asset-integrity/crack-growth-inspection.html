Crack growth and inspection planning analysis

Summary

Thresholded fatigue growth is integrated to a supplied assessment limit and converted to a capped inspection interval. The existing surface-flaw FAD envelope can supply that limit, and the resulting plan can feed qualitative RBI. Missing LBB evidence is reported as NOT_EVALUATED; through-wall geometry alone establishes no LBB acceptance.

Method and source basis

The MIT Fatigue notes (2001), Equation (2) give da/dN = C (DeltaK)^m. The AFGROW Damage Tolerant Design Handbook, Section 5.1.2, Equation (5.1.3) gives the stress-ratio correction introduced in 1970. With R = Kmin/Kmax, the implemented form is:

Keq = DeltaK / (1 - R)^(1 - gamma)
da/dN = 0                         when DeltaK <= DeltaK_th(R, environment)
da/dN = C * Keq^m                 otherwise
N = integral from a_initial to a_limit of da / (da/dN)

C is calibrated at R = 0. The threshold is the measured raw range at service R, before correction. All material parameters and their calibration basis are required. The supported domain is 0 <= R < 1 and 0 <= gamma <= 1. These are implementation limits, not universal material limits. Compression and load-sequence effects require a different qualified model. No BS 7910 or API 579 material coefficient is supplied.

Composite Simpson quadrature samples each panel's endpoints and midpoint. A sampled threshold arrest returns null remaining cycles and only reached history points. Step refinement is required for varying DeltaK. An arbitrary callable can contain an unsampled dip; this algorithm cannot establish the absence of one.

plan_crack_from_fad calls the existing critical_flaw_depth_mm. That routine can return its depth or geometry validity cap. The limit therefore denotes the end of the established assessment envelope, rather than a demonstrated fracture depth. Growth stops at the smaller of that depth and wall thickness. The FAD input length is held fixed; aspect-ratio evolution is not modeled. A compatible depth-dependent DeltaK solution is required. Surface depth is never substituted for through-wall length.

Inspection and RBI interfaces

years = remaining_cycles / cycles_per_year
half_life = years / 2
next_interval = min(years / life_divisor, supplied_max_interval)

The year, null-life and half-life semantics follow the existing inspection_planning.plan_inspection implementation. The divisor is required and cannot be less than that planner's divisor of 2. The maximum interval and policy basis are required; these inputs do not establish a crack-specific code interval. At or beyond the limit, remaining life and interval are zero and screening fails. Under threshold arrest, life and half-life are null and the supplied maximum interval governs only while the modeled loading and environment remain applicable.

screen_crack_plan uses the existing qualitative RBI life-ratio bands and consequence category, without inventing corrosion data. A supplied RBI policy can only tighten the crack plan's interval. Existing default bands remain practice parameters, not API RP 581 values.

The registered inspection router accepts inspection_planning.crack_growth instead of thickness inputs. Supply law, stress_range_mpa, geometry_factor, initial depth, integration steps, cycle rate, interval cap, divisor and policy basis. Supply either fad_inputs or explicit critical depth, wall thickness and depth basis. The router uses the existing constant-geometry SIF equation; the Python interface accepts a general compatible DeltaK callable. Results retain the ordinary result key and add crack_assessment.

Worked example: published growth problem

MIT Fatigue (2001), Table 1 and Problem 6, supplies steel C = 10-11, m = 3, an infinite-plate central crack from half-length 0.1 mm to 2.5 mm, and Delta sigma = 950 MPa. The problem's Delta sigma is treated as the range; it is not doubled. No threshold or R correction is specified, so zero threshold and gamma = 1 explicitly recover the published Paris equation. SI metres are used for half-length and MPa sqrt(m) for DeltaK.

DeltaK = 950 * sqrt(pi*a)
N = 2*(1/sqrt(0.0001) - 1/sqrt(0.0025)) / (1e-11*950^3*pi^(3/2))
  = 3351.4 cycles
Synthetic policy: 1000 cycles/year, divisor 2, maximum interval 2 years.
Remaining life = 3.4 years; next interval = 1.7 years (rounded).

The expected life is obtained by direct integration of Equation (2). The printed general expression in Problem 5 contains an extra factor m and is not used as the oracle. Synthetic policy values illustrate conversion only; they are not operating records or code limits.

Run the example from the repository root with the package dependencies installed:

PYTHONPATH=src python examples/workflows/crack-growth-inspection/run_example.py

JSON output includes the published case, a separate synthetic FAD-to-inspection example, input basis and the LBB evidence gaps. No output file is created by the script.

LBB evidence and remaining qualification

The LBB helper optionally checks the strict prerequisite length_margin * detectable_full_length < critical_full_length, with all lengths, margin and basis supplied. Equality fails the prerequisite. A geometric pass still returns NOT_EVALUATED overall. Leak-rate and detection qualification, through-wall stability under governing loads and transients, and the applicable LBB procedure and margins remain unestablished. API 579-1/ASME FFS-1 (2016), Part 9, LBB procedure is the intended qualification route; no procedure values are reproduced.

Threshold calibration, short-crack behavior, environment, residual stress effects on R, load spectrum, crack-shape evolution and inspection detection capability require case-specific evidence. The closed-form and published tests validate arithmetic and interface behavior; they do not qualify an operating component.
