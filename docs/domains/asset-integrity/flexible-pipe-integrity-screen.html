Unbonded flexible pipe integrity screen

Summary

The flexible-pipe-integrity-screen workflow records inspection evidence, groups it into five failure modes and returns ESCALATE pending qualified pipe-specific assessment. Remaining capacity and fatigue life are NOT_EVALUATED. Wire counts provide inventory statistics only.

Method and sources

The HSE inspection guidance (2008), Recommendations calls for failure-mode-based inspection and monitoring. Its Good practice guidance section lists API RP 17B, third edition (2002), Recommended Practice for Flexible Pipe. This workflow does not reproduce API acceptance limits or claim API compliance.

The public regulator report Un-bonded Flexible Risers – Recent Field Experience and Actions for Increased Robustness (2013), revision 5, by 4Subsea AS for PSA Norway, document 0389-26583-U-0032, provides the evidence grouping below. Section 5.5 requires damage and consequence assessment; section 5.4.1 identifies environment-specific fatigue data needs. These observations do not establish a generic count-to-capacity or flooded-life equation.

For every group, assessment status is NOT_EVALUATED and action is ESCALATE. This action is software evidence-gap policy. No automatic MONITOR, REPAIR or REPLACE criterion has been qualified.

Input contract

Evidence is supplied under flexible_pipe_assessment.evidence. Unknown keys, nonfinite numbers, boolean counts, negative counts and inconsistent counts are rejected. Counts are integers. Missing observations remain unknown; zero breaks and absence of indications do not establish fitness for service.

  • outer_sheath_breach_location: unknown, none, above_waterline or submerged.
  • annulus_test: unknown, dry, flooded, leak_indicated or inconclusive.
  • vent_status: unknown, clear or blocked.
  • total_armour_wires and broken_armour_wires: counts for the same assessed population and location.
  • end_fitting_age_years: nonnegative years; load_history_available: boolean or null.
  • carcass_collapse_indicated and pressure_sheath_damage_indicated: boolean or null.
  • allowable_broken_fraction: optional count criterion paired with allowable_fraction_reference (document and locator). It has no API default.
  • design_fatigue_life_years: positive years; optional flooded_life_factor paired with flooded_factor_reference. The factor is recorded but not applied.

Fraction bounds are mathematical definitions: a count fraction lies in [0, 1], and a supplied life reduction multiplier lies in (0, 1]. These bounds are not engineering acceptance limits. Citation strings record the supplied basis; their accuracy and applicability are not automatically verified.

An empty assessment block leaves observations unknown; a non-mapping block is rejected with an input error. Report percentages use one decimal place, with the exact broken-wire count ratio b / N shown alongside the inventory to distinguish small fractions that round to zero. Each generated report records its own issue date separately from the workflow version.

Worked example: inputs, method and answer

The following invented counts illustrate inventory arithmetic and are not measured engineering data. For total count N = 40 and broken count b = 2, the intact count is N − b = 38 and the broken fraction is b / N = 0.05 (5.0 %). These identities have no load-sharing assumption. No remaining-capacity fraction is calculated.

from digitalmodel.workflow_api import run_workflow

response = run_workflow("flexible-pipe-integrity-screen", params={
    "flexible_pipe_assessment": {
        "component_id": "FLEXIBLE-PIPE",
        "evidence": {
            "outer_sheath_breach_location": "above_waterline",
            "annulus_test": "flooded",
            "vent_status": "blocked",
            "total_armour_wires": 40,
            "broken_armour_wires": 2,
        },
    },
})
assert response.status == "ok", response.warnings
answer = response.result["value"]
assert answer["wire_inventory"]["intact_wire_count"] == 38
assert answer["wire_inventory"]["broken_fraction"] == 0.05
assert answer["decision"]["verdict"] == "ESCALATE"
assert answer["remaining_capacity"] is None
assert answer["remaining_fatigue_life_years"] is None

The response status ok means execution succeeded. The engineering action remains ESCALATE. The report is returned as report_html through FFSReport.generate_screening_html. An optional flexible_pipe_assessment.output_dir requests report persistence; a relative folder is resolved against the configuration root. Without it, the router writes no report.

Validation and remaining scope

Figure 3-7 of the public report records submerged sheath damage and a vacuum test indicating leakage. The test suite reproduces that evidence combination only; no published numerical capacity or life benchmark is established. A leak indication alone is not mapped to flooding, rupture capacity or repair/replacement criteria.

Further qualification requires representative corrosion sizing, per-layer geometry, loads, load sharing and stress concentration, environment-specific fatigue data, accumulated damage and documented disposition criteria. A supplied count limit or life factor alone does not close these gaps. The offering catalogue remains planned. External service routing is deferred; the registered offline workflow is available.
