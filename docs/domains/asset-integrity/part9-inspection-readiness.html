Part 9 inspection readiness

The api579-part9-crack-fad workflow checks declared inspection fields and reports outstanding method qualification. The worked example has complete intake fields and returns NOT_EVALUATED for fitness for service: no stress-intensity factor, reference stress, FAD point, remaining life or operating limit is calculated. Intake completeness is not engineering sufficiency or acceptance under API 579-1/ASME FFS-1.

Workflow and result contract

The engine basename is api579_part9_crack_fad. The registry entry is callable through digitalmodel.workflow_api.run_workflow, the same entry point used by Deckhand consumers. No separate Deckhand service is changed or deployed. Direct Python callers may use digitalmodel.asset_integrity.part9_inspection.assess_inspection without report dependencies.

from digitalmodel.workflow_api import run_workflow

envelope = run_workflow("api579-part9-crack-fad")
result = envelope.result["value"]
# result["measurement_sufficiency"]["status"] == "COMPLETE_FOR_REVIEW"
# result["verdict"] == "NOT_EVALUATED"
# result["acceptable"], result["kr"], result["lr"] are None

The workflow API envelope can have status="ok" when the workflow executed and the engineering result is NOT_EVALUATED. Consumers shall inspect the engineering result. acceptable=None means no acceptance decision was established; it is not a failed FAD check. No unresolved standard reference is emitted as a qualified citation sidecar.

With the example input, the optional part9_report.output_dir requests part9-report.html through the existing FFSReport.generate_screening_html renderer. The engine resolves relative output directories beneath its configuration root. The supplied part9_report.issue_date records the report revision date. Written paths and rendered HTML are kept in part9_report configuration metadata, outside the in-memory engineering result and its hash. Direct router callers can read part9_report.report_html. The shared report header uses the date of report generation.

Input schema

FIELD_SPECS in part9_inspection.py is the declarative schema. The root part9_inspection block shall be a mapping. Missing or invalid fields produce an ordered list of {field, kind, reason} issues. Booleans and numeric strings do not count as measured numbers; nonfinite values are invalid. No absent boolean is interpreted as false. All input values in the example are synthetic.

Inspection dates cannot be after the assessment date. Direct intake callers can supply as_of as a calendar date to reproduce a historical decision; the default is the current UTC date. The registered route uses this default, so a future-dated inspection can become eligible for intake when that date is reached. Rejections before that date do not echo the changing clock. Load and toughness temperatures cannot be below absolute zero, as defined by the Celsius scale in the SI Brochure, 9th edition, section 2.3.1, “The kelvin”, page 129 (BIPM source). These checks do not establish code applicability or material qualification.

Method and worked answer

The committed input is examples/workflows/api579-part9-crack-fad/input.yml. The invented cylinder has a 20 mm wall and a surface indication 5 mm deep and 30 mm long, with 1 mm depth-sizing uncertainty. The supplied stresses and toughness are synthetic demonstration inputs, not measurements or a material specification. They shall not be used as engineering data.

  1. The required fields and their types are checked.
  2. Geometric consistency is checked: depth plus its stated uncertainty is less than wall thickness. For the example, 5 + 1 = 6 mm, below 20 mm. This is a geometric identity, not an API acceptance limit.
  3. Strength ordering, flaw-zone toughness, temperature basis and conditional weld, hydrogen and growth fields are checked.
  4. Each unavailable numerical method is returned as a named blocker.

Answer: the example has zero intake issues and seven NOT_EVALUATED method checks. Its intake status is COMPLETE_FOR_REVIEW; its engineering verdict is NOT_EVALUATED; acceptance, Kr and Lr are null. The way forward is to qualify the source data, geometry-specific solutions and an independent published example before an engineering disposition is issued.

Sources and test basis

API 579 Part 9 Crack Like Flaws Assessment, Inspection for Industry, undated, accessed 2026-10-20 (HTTP 200), supplies the practitioner intake checklist. It supplies no numerical qualification used by this workflow. API 579-1/ASME FFS-1 (2016), Part 9 and (2007), Annexes C/D/E are required method references. All requested editions carry EDITION_CROSSWALK_UNQUALIFIED because the requirements mix 2007 annexes and 2016 Part 9. Lettered annex references do not establish an edition mapping. No licensed source tables or worked examples have been qualified for this route.
