Riser BOM trade-study costing

The digitalmodel.riser_bom package converts explicit installed quantities into a five-category cost breakdown with a separate citation sidecar. The method is public; real cost tables and results derived from them remain private. The worked example uses invented quantities and prime-number rates in fictional TEST currency.

Input schema and method

Configuration requires riser_length_m, joint_length_m, coated_length_m, buoyancy_module_count, ancillary_count, installation_days and a Citation identifying the complete quantity schedule. Lengths and duration accept decimal strings; counts shall be nonnegative integers. Installed and joint lengths shall be positive. Coating length shall not exceed installed length. Missing scope shall not be replaced by a zero: a supplied zero states that no quantity is included for that category.

Line cost = quantity × unit rate. Total cost = sum of the five line costs. The unit-rate method follows OpenStax, Prealgebra 2e (2020), section 5.6, Unit Rate and Unit Price. Addition is direct arithmetic. Upward joint rounding is a declared procurement convention: the least whole number of joints covering the installed length is purchased. Coating is charged on the supplied installed coating scope, not on any surplus joint length. Decimal arithmetic retains input digits; no monetary rounding or currency exchange is applied.

External cost-basis contract

load_cost_basis(configured_path) requires an explicit external JSON file. There is no default rate table, environment search or fallback. The resolved path shall be outside the current public repository, including when accessed through a symlink. The loader rejects unknown or duplicate fields, duplicate or missing components, unsupported schema versions, wrong units, negative rates and non-finite numbers.

The top-level fields are schema_version (integer 1), currency (a nonempty label), revision (a nonempty version), data_kind (synthetic or private) and rates (a list). Each rate requires component, unit, value and citation. Each component appears exactly once, with no implicit factors. The rates share the basis currency. See the synthetic JSON fixture for the complete structure.

Each citation uses the existing Citation schema: code identifier, publisher, revision, section, wiki path and source sibling, with optional note and source project. cost_bom resolves all quantity and rate citations at every calculation, including zero-quantity items. Missing pages or mismatched code identifier, publisher or revision raise an error. citation_root explicitly configures the citation store; omission uses the existing citation resolver. Synthetic tests provide a miniature citation store and need no private data. Citation section contents and the commercial validity or freshness of a supplied rate remain external review responsibilities.

Real rates, real price curves and scaled or indexed versions of them shall remain external. The primary result contains quantities and rates: a result derived from a private basis remains private, even if only totals or ratios are retained. data_kind is preserved in the result; it is metadata, not a publication access control. The engine does not load or reuse a project-level cost model.

Configuration integration and limits

configuration_from_lazy_wave(result, ...) consumes the analytical LazyWaveResults.total_arc_length interface and adds the supplied grounded length before costing. No solver is imported or executed by the adapter. Joint length, coating scope, discrete module count, ancillary count and installation duration remain required inputs. The unified design-input schema does not establish all these procurement quantities, so no automatic sizing factors or conversions from distributed buoyancy are assumed.

The public result includes currency, basis revision, data kind, breakdown, total, citation sidecar and limitations. Fatigue, structural adequacy, escalation, tax, contingency and currency conversion are NOT_EVALUATED. This is a trade-study support method, not an issued commercial estimate. Different currencies or revisions shall not be compared without a separately established basis. The future ranked-configuration interface can call this costing API after the installed quantity schedule is established.
