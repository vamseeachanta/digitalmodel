Wave-only operability analysis

Summary

OperabilityInput evaluates Hs and optional Tp limits using a wave scatter diagram. A supplied wind or current limit is rejected because the diagram contains no joint wind/current observations. In the synthetic example, the wave criteria give 40.0% operability; combined operability is NOT_EVALUATED. No combined percentage is returned.

The selected criteria are Hs ≤ 2.0 m and Tp ≤ 6.0 s. Accepted disjoint cells are summed: P = 0.1 + 0.3 = 0.4. Operability is 100P = 40.0%; non-operability is 100(1 − P) = 60.0%. The addition and complement rules are described in Introductory Statistics 2e (OpenStax, 2023), section 3.3. No assumption of independent wind, current and waves is made.

The example converts validation errors into NOT_EVALUATED entries for display. The API raises pydantic.ValidationError during construction or JSON validation, naming unsupported active fields. The calculation also raises ValueError if those fields are set through assignment, model_copy(update=...) or model_construct(...). This second check runs before the wave probability is evaluated. Pydantic documents the trusted-data bypasses in its model documentation.

Limits and way forward

Omitted or explicitly None wind/current limits request a wave-only assessment. Removing an actual operational requirement merely to obtain a percentage does not establish combined operability. A combined assessment requires a separate interface with synchronized wave, wind and current observations or their joint occurrence distribution, and explicit operating limits. That interface is outside this correction.

The default synthetic scatter remains demonstration data. This correction does not qualify site data, normalize supplied occurrence counts, calculate combined persistence, or establish compliance with marine-operation standards.
