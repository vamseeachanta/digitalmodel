OrcaFlex model catalogue

The generated catalogue presents source-local metadata and coordinate schematics. It reads YAML without initializing a solver. Missing values remain “not stated”; the page establishes neither loadability nor engineering acceptance.

Regeneration

From the repository root (PyYAML is the only generator dependency):

uv run --no-project --with pyyaml python src/digitalmodel/solvers/orcaflex/model_catalogue.py \
  --output docs/domains/orcaflex/library/model_catalogue.html

The inputs are library/model_library/, templates/ and library/templates/ beneath docs/domains/orcaflex/, plus the claim registry, pending inventory, tests and workflow references. Traversal and card ordering are sorted; no generation timestamp or absolute path is emitted. The dedicated freshness test compares two builds with the committed page.

Coverage and limitations

One card represents one YAML source variant. Includes and base files are counted without being opened to infer missing metadata. Unreadable YAML receives a failure card without echoing its contents. Model folders without YAML, including empty templates beneath populated categories, appear under “Files without cards”. Absent source roots are listed as “catalogue root not present”; they do not silently become empty inventories. The claim registry and inventory remain required inputs.

Project-derived groups are excluded before card generation. Vendor-derived cards carry selected metadata and schematics only. Unknown provenance remains “not stated” and carries a redistribution caution. References are text matches, not evidence that a test has passed or a workflow has run.

Free and Fixed connection coordinates are global. Anchored coordinates are relative to the seabed; parent-object connections use local axes or arc length. Only explicit global coordinates are drawn. Other objects remain unresolved; missing coordinates and water-surface elevations are not replaced with defaults.

Worked example: inputs, method and answer

All values below are selected synthetic inputs in a common file length unit. They are not measured data, design limits or coefficients from a publication.

Environment:
  WaterDepth: 20
  WaterSurfaceZ: 0
Lines:
  - EndAConnection: Fixed
    EndAPosition: [2, 3, 4]
    EndBConnection: Free
    EndBPosition: [5, 7, 11]

Method: count the entry in Lines; project each explicit global point onto X/Y for plan and X/Z for elevation. SVG coordinates retain the input values; a group transformation reverses the display's vertical axis. The seabed reference is the stated surface elevation minus the stated water depth. These are coordinate projections, not a catenary or an equilibrium calculation.

Replacing either line-end connection with Anchored leaves that line unresolved because its Z coordinate is then a height above the local seabed. The catalogue does not infer the required bathymetry or call a solver.

Sources and checks

The connection-frame interpretation follows Orcina's public Object connections, sections on connection coordinates and axes, and Line data: End connections, Position and Height above seabed (online help, consulted 2026-10-20; no numbered edition stated). The selected numbers require no external engineering reference.

tests/solvers/orcaflex/test_model_catalogue_coverage.py exercises a synthetic chord, a specification without geometry and an include-only model in a partial tree, as well as nested empty templates and structural-directory handling. The existing catalogue tests cover source-local environment fields, provenance, claim boundaries, coordinate projection and committed-page freshness.
