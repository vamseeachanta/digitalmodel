# Flexible riser configuration analysis

The offline workflow supports [the flexible riser comparison](https://github.com/vamseeachanta/digitalmodel/issues/2429): catenary, lazy wave, steep wave and pliant wave, each at near/far/cross offsets in two sea states. It builds a symbolic case table, checks supplied extrema against sourced project criteria and reports paired mesh changes. It never imports a licensed solver.

## Build the initial report

From the repository root, with an output directory that already exists:

```bash
PYTHONPATH=src python -m digitalmodel.subsea.flexible_pipes.configuration_comparison \
  --output comparison.html --revision 1 --date 2026-10-20
```

The generated report contains 24 symbolic cases with `NOT_EVALUATED` responses. The committed [initial analysis](flexible-riser-comparison.html) is generated by the same command. Source inventory entries identify eight existing specifications by repository-relative path and SHA-256; model content is not copied. The command verifies report readback. `inventory(root)` raises if any named source is missing.

The two reference libraries are `library/tier2_fast/a01_*_riser` and `library/model_library/a01_*_riser`. Generic generation precedents are in `templates/risers/`. The existing `tier2_fast/riser_validation_report.html` compares model representations; `riser_mesh_sensitivity.html` compares existing static mesh levels. Their pass labels are not evidence for this campaign. Existing generation tests and `src/digitalmodel/orcaflex/riser_config.py` cover preliminary geometry; this workflow does not use their default properties or treat a steel-pipe screen as an unbonded-flexible capacity calculation.

## Required engineering inputs

The common basis remains unresolved. Required sourced inputs are the pipe section and contents, buoyancy variants, one site and seabed/current basis, offset vectors, both sea states, and the extraction region and time window. Near/far/cross and sea_1/sea_2 are labels, not numeric values. Reference specimens shall not silently become an approved common pipe/site.

Supply scalar criteria in kN for maximum effective tension, 1/m for maximum curvature magnitude and m for minimum seabed clearance. Every measurement and criterion requires a source string. Capacity values, safety factors, clearance requirements and mesh tolerances have no defaults. Unknown criteria give `NOT_EVALUATED`. No API RP 2RD or DNV-OS-F201 compliance assessment is implemented; the issue names these documents but a qualified edition, governing clauses and applicable flexible-pipe criteria have not been established.

An `Evidence` record describes extrema over the full declared period and region, not isolated samples. The common basis digest shall cover pipe/site, case definitions, extraction scope and mesh-independent configuration definitions. Each run also records input/output digests, solver version, criteria revision, convergence and evidence kind (`synthetic` or `stored`). The report rejects duplicate cases, mixed versions, mixed basis digests, mixed criteria revisions and mixed evidence kinds. These checks validate supplied metadata; they do not authenticate native output bytes or private evidence. `stored` is not a qualification verdict.

Seabed contact can give negative clearance. Intended touchdown shall not be confused with sag-bend clearance: define a consistent suspended comparison region before supplying minima. Curvature is a nonnegative magnitude. Scalar maximum tension may be signed; compression, tension-dependent MBR and anisotropic curvature checks require additional assessments and are not established by a PASS here.

## Worked example: independent synthetic arithmetic

All values in this example are invented arithmetic fixtures, **not engineering inputs or acceptance limits**. No physical property or standards coefficient is assumed.

Inputs: maximum tension 80 kN against a synthetic upper limit of 100 kN; curvature 0.2 1/m against 0.25 1/m; clearance -0.1 m against a lower limit of zero. The method is direct inclusive inequality. Independently, 80 ≤ 100 and 0.2 ≤ 0.25 pass; -0.1 ≥ 0 is false, so clearance fails. A tension-only ratio would be 80/100 = 0.8, without a design-code interpretation.

For mesh arithmetic, coarse/fine tension is 105/100 kN: the absolute change is 5.0 kN and the relative change is |105 - 100| / |100| × 100 = 5.0 %. The factor 100 is the definition of percent. The deliberately invented segment targets halve from 2 m to 1 m. No tolerance is assigned, and a two-level change is not a convergence conclusion.

```python
from dataclasses import replace
from pathlib import Path
from digitalmodel.subsea.flexible_pipes.configuration_comparison import (
    Criterion, Evidence, Measurement, MeshPair, case_table, compare, render_report,
)

source = "Synthetic hand calculation in the worked example; not design data"
def scalar(value, unit):
    return Measurement(value, unit, source)

limits = {
    "tension": Criterion(100, "kN", source, "maximum"),
    "curvature": Criterion(0.25, "1/m", source, "maximum"),
    "clearance": Criterion(0, "m", source, "minimum"),
}
record = Evidence(
    case=case_table()[0], solver_version="synthetic-only",
    basis_digest="a" * 64, input_digest="b" * 64, output_digest="c" * 64,
    criteria_revision="synthetic-v1", kind="synthetic", converged=True,
    tension=scalar(80, "kN"), curvature=scalar(0.2, "1/m"),
    clearance=scalar(-0.1, "m"),
)
assert [row["status"] for row in compare(record, limits)] == ["PASS", "PASS", "FAIL"]
coarse = replace(record, tension=scalar(105, "kN"))
fine = replace(coarse, tension=scalar(100, "kN"), clearance=scalar(0, "m"),
               input_digest="d" * 64, output_digest="e" * 64)
pair = MeshPair(coarse, fine, (scalar(2, "m"),), (scalar(1, "m"),))
html = render_report([coarse], limits, revision="1", date="2026-10-20", meshes=[pair])
Path("synthetic-comparison.html").write_text(html, encoding="utf-8")
```

The example report displays one supplied synthetic case out of 24 and keeps engineering acceptance `NOT_EVALUATED`. Changing `kind` does not establish solver attestation. When fine reference clearance is zero, its relative mesh change is undefined; the absolute difference remains available.

`MeshPair` requires identical case/basis/version/criteria/kind, different run input/output digests, and positive corresponding section target lengths with at least one strict refinement and none coarsened. Actual mesh topology and unchanged section geometry require native evidence review. Missing or unconverged extrema do not produce mesh changes. Re-issues pass the entire prior `history` plus the new revision row to `render_report`; earlier rows shall be preserved by the caller.

## Sources and limits

- [Orcina online help, Line types: Limits data, Allowable tension and Minimum bend radii](https://www.orcina.com/webhelp/OrcaFlex/Content/html/Linetypes,Limitsdata.htm), unversioned online documentation, accessed 2026-10-20: meaning of supplied tension/curvature limits; no capacity values adopted.
- [Orcina online help, Line results: Contact, Seabed clearance](https://www.orcina.com/webhelp/OrcaFlex/Content/html/Lineresults,Contact.htm), unversioned online documentation, accessed 2026-10-20: signed clearance accounts for outer contact diameter; vertical clearance is a distinct result for three-dimensional seabeds.
- [Orcina online help, Line data: Structure, Target segment length and number of segments](https://www.orcina.com/webhelp/OrcaFlex/Content/html/Linedata,Structure.htm), unversioned online documentation, accessed 2026-10-20: target section segmentation. The relative-change formula above is explicitly defined arithmetic, not a vendor convergence threshold.

A published common-site numerical benchmark has not been selected. Tests use the independent hand calculations above rather than values returned by the implementation. Solver version/readback for all cases, approved common numeric inputs, code-specific criteria and convergence acceptance remain later work. Solver runs are outside this implementation. Vendor-derived model redistribution rights remain unverified; only results, method and source metadata are reported.
