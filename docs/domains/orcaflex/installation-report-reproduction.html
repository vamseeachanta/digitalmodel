Installation report reproduction

Reusable code and tests are owned by digitalmodel. Private solver evidence, source configurations, generated reports and dataset manifests are owned by digitalmodel-data. The owning dataset manifest identifies the code revision, source digests and intended-use status.

Inputs and environment

The full report consumes a verified demand-summary JSON file, an assessed envelope/monitoring payload JSON file, and a report-configuration JSON file. The payload pins the exact demand-summary bytes by SHA-256. Retain those original bytes; reserialising equivalent JSON changes its identity.

For source summaries containing legacy machine paths, configure dataset_root relative to the report directory and case_run_dirs as a complete mapping from string case index to dataset-relative run directory. Rendering relocates appendix links from that mapping without changing the pinned source summary. Retain the private dataset directory layout when moving the checkout.

Use the repository Python environment with src on PYTHONPATH. The retained report environment uses Python 3.12.13, reportlab 5.0.1 and pypdf 6.19.0; PyMuPDF 1.28.2 supports visual QA. Rendering requires no native solver licence. Re-running native simulations requires the matching solver version, licence, model and campaign inputs retained by the private dataset.

Generate HTML, sidecar and PDF

Set source paths to the files identified in the dataset manifest. Use a new output basename; the HTML generator rejects existing destinations. The PDF renderer accepts a path or byte stream, so the caller should reject an existing PDF before invocation.

from pathlib import Path
import json
from digitalmodel.workflows.installation_full_report import generate_report
from digitalmodel.workflows.installation_full_report_pdf import render_full_pdf

summary = Path('demand-summary.json')
payload = Path('report-payload.json')
config = Path('report-config.json')
output = Path('installation-report.html')
pdf = output.with_suffix('.pdf')
if pdf.exists():
    raise FileExistsError(pdf)
generate_report(summary, payload, output, config=config)
render_full_pdf(json.loads(summary.read_bytes()),
                json.loads(payload.read_bytes()), pdf,
                json.loads(config.read_bytes()),
                summary_bytes=summary.read_bytes())

Verification

python -m pytest tests/workflows/test_installation_full_report.py tests/workflows/test_installation_full_report_pdf.py tests/workflows/test_installation_envelope_dashboard.py tests/workflows/test_installation_envelope_pdf.py -q

The tests check source identity, case correspondence, rejected invalid dispositions, retained configuration, report sections and embedded monitoring. Verify all output hashes after generation, inspect PDF pages, and check HTML controls and links. Generated timestamps and PDF metadata can change file hashes; identical input results do not imply byte-identical regenerated documents.

Analysis and monitoring boundaries

The report composes existing installation_assumed_envelope, installation_monitoring_demo, installation_wave_assisted, installation_envelope_dashboard and installation_envelope_pdf workflows. Report generation does not rerun simulations or independently qualify source engineering.

Assumed-criteria screening is distinct from operational acceptance. A passing upper grid edge is censored unless a failure boundary has been established. Supplied future simulated waves constitute conditional load-preview input; they do not establish offshore wave-forecast skill. Keep unresolved qualification checks and the simulated designation in every issued derivative.
