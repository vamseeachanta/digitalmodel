Campaign fixture portability

Summary

The campaign compatibility tests resolve their tracked inputs from the repository containing the test module. A relocated checkout and an unrelated working directory therefore select that checkout's fixtures. The existing root calculation is preserved; the regression checks use independent expected paths and inspect the compatibility tests' missing-fixture skip conditions.

Inputs and method

The input is the resolved location of the campaign integration test module. Its repository-relative location is tests/solvers/orcaflex/modular_generator/integration/test_campaign_integration.py. Counting outward from the file gives the integration, modular_generator, orcaflex, solvers and tests directories, then the repository root. Consequently Path(__file__).resolve().parents[5] selects the root. The index follows from that tracked directory layout, not an engineering coefficient or acceptance limit.

Each fixture path is the root joined to its tracked relative path:

Worked example

Let checkout denote a temporary repository root. Place the test module under its relative location above and create an empty placeholder at checkout / docs/domains/orcaflex/pipeline/installation/floating/30in_pipeline/spec.yml. Import the module with an unrelated working directory. The expected FLOATING_SPEC is exactly that placeholder path, and the floating compatibility test's skipif condition is False. With the placeholder absent, the resolved path is unchanged and the condition is True. The S-lay case follows the other literal path in Table 2.

The relocation test creates placeholders only to check paths and collection conditions. The compatibility tests below use the actual tracked YAML inputs to generate a master file, includes and parameters, then retain their existing output assertions. No licensed solver is imported, queried or started.

From the repository root, with TMPDIR set to an external scratch directory, the compatibility check is:

uv run --no-project --with pytest --with pytest-asyncio --with pyyaml \
  --with 'pydantic>=2,<3' --with loguru --with 'numpy<2' --with scipy \
  python -m pytest \
  tests/solvers/orcaflex/modular_generator/integration/test_campaign_integration.py::TestBackwardCompatSingleRunFloating \
  tests/solvers/orcaflex/modular_generator/integration/test_campaign_integration.py::TestBackwardCompatSingleRunSlay \
  -q -rA -p no:cacheprovider --basetemp="$TMPDIR/campaign-example"

Expected answer: both compatibility cases pass, with zero missing-fixture skips when the tracked inputs are present. Use a fresh scratch subdirectory for each invocation because pytest manages its base temporary directory.

Scope and limits

The fixture presence and relocation checks cover both inputs. Literal expected paths prevent a wrong fixture declaration from defining its own test expectation. Skip-predicate checks distinguish an available input from a missing input. The complete module also checks campaign generation. These checks establish path selection and generated-file behavior; solver execution and engineering qualification remain outside their scope. Moving the test module to a different directory depth requires updating root resolution.

Sources

The acceptance criteria are recorded in issue 2517, titled test(orcaflex): resolve campaign fixtures relative to the repository. The linked test module and tracked fixture locations provide the path basis. No engineering equations, standards-derived constants or numerical acceptance limits are introduced.
