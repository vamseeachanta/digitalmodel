3. Delivery sequence

Private benchmark release will use a field-and-value allowlist, including numerical vectors and embedded plot data. Removing names alone will not authorize publication. Synthetic public counterparts will be labelled synthetic and will not claim to reproduce confidential designs. All packs will explicitly override default document history with review-only status and pending signoffs. Composite children will have row-level evidence anchors, not only a shared section link.

M1 will require owner-approved internal review document identities in a repo-owned register. Missing entries will block generation; no client/job identity or undocumented numbering convention will be invented to satisfy the renderer.

  1. M1 — Inventory and jacket pilot. The work will freeze source rights, benchmark mappings, coverage and negative tests, then migrate the jacket pack.
  2. M2 — Supported structures. The work will generate S01–S11 and all S09 children through the existing calculators and report builders.
  3. M3 — Benchmarks. The work will compare A–E on the private host, then bring permitted de-identified derivatives and comparison evidence into the repo.
  4. M4 — Review portfolio. The work will build the index from verified receipts, complete automated/adversarial checks, and submit a review-ready PR while retaining the owner's deferred visual review and all engineering acceptance gates.

4. Repo-owned deliverables

The review landing page will live at docs/domains/cathodic_protection/reports/index.html. Each case will include portable HTML, de-identified input, computed result JSON, citations, comment JSON, file digests, source revision and unresolved engineering limitations. Benchmark comparisons will live under the same report tree. A coverage manifest will record route/mode, standard edition, computed PASS/FAIL, use_status, automated verification, source-rights disposition and reviewer status independently.

The implementation will reuse the existing report engine. Portfolio-only presentation work will not change shared templates, numerical kernels, standards interpretations or global reporting conventions. A source-rights block or new solver requirement will return to the owner before the scope changes.

5. Completion criteria

  • Every required case and child will have its complete pack and resolvable index entry.
  • Numerical/citation fidelity, de-identification, portable assets, JSON binding, comment round trips and deterministic rebuild checks will pass.
  • Scoped tests, touched-file lint/type checks, legal/identifier/path scans and adversarial review will pass against the actual artifact set.
  • Outstanding human checks will be explicit; no elapsed time, AI recommendation, calculated PASS or generated report will imply acceptance.
  • The first-real-job benchmark condition will remain separate from portfolio completion.
