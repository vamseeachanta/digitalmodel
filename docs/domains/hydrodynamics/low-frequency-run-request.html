Low-frequency diffraction: solver run request

Native runs: NOT_EVALUATED. Numerical repair, root cause and physical qualification are not established. This package prepares a diagnostic campaign and screens exported amplitudes. It does not alter native RAOs or remove flags.

Scope: issue 1548. The separate frequency-screening draft retains and annotates native rows. This follow-up supplies the mesh/removal investigation and run request; it does not depend on that draft or duplicate its annotation code.

Plan and review basis

  1. The operator will provide a reviewed single-body unified specification, the original coarse mesh, and medium/fine refinements of the same geometry and wetted surface.
  2. The preparation will retain loading and environment fields, retain all original frequency and heading samples, and add samples inside the original lowest-frequency interval.
  3. Each solver will receive each mesh with removal disabled and interior-panel removal enabled. The manager will convert, inspect and execute the specifications using the existing native-deck workflow.
  4. The checker will compare complete exact sample grids and retain per-sample failures. Native completion and engineering qualification will remain separate manual evidence gates.

The plan review identified treatment mapping, input binding, incomplete grids and false convergence claims as material risks. The resulting design uses explicit solver/treatment pairs, input and generated-specification digests, complete grids, and numerical difference labels rather than a convergence or qualification verdict.

Required inputs and preparation

Copy examples/hydrodynamics/low-frequency-campaign.json into the controlled run package and replace every null with reviewed inputs. The template is deliberately non-runnable. No mesh, mass, inertia, damping, water depth, grid, runtime or comparison tolerance is invented here. The source strings will cite the specific approval or engineering basis; a nonempty string is a traceability field, not authenticated approval.

The base specification will use explicit angular frequencies in rad/s and explicit headings in degrees. The mesh paths in the request will be relative to the base specification directory, remain inside it, and have the same file format. Coarse will reference the original base mesh. The generator rejects identical mesh contents, but distinct hashes do not establish actual refinement. The mesh inspection will establish panel counts, geometry equivalence, waterline, normals and refinement quality. A class-quality replacement of a different geometry will require its own matched campaign; it cannot serve as a convergence level for the original hull.

The generator supports a single vessel and no auxiliary mesh references. Existing mass, inertia, reference point, depth, damping and other options are preserved. It does not validate the full engineering schema or generate native decks. The manager will validate generated specifications with the existing SpecConverter workflow before execution. Generated paths refer back to the supplied meshes: retain the entire input/preparation directory layout.

python scripts/benchmark/low_frequency_campaign.py prepare base.yml request.json prepared
python scripts/benchmark/low_frequency_campaign.py assess prepared/manifest.json results.csv screen.json

The first command creates a new output directory exclusively, records source and generated-specification SHA-256 digests, and verifies readback. The second command rebuilds and checks those bindings before reading results. No subprocess, solver API, licensed import or network operation is used. Existing outputs are never overwritten.

If a write or readback fails, the partial preparation is retained for diagnosis and is not runnable evidence. After resolving the cause, use a fresh destination; do not overwrite or treat a partial manifest as a completed preparation.

Export contract and numerical checks

run_id,frequency_rad_s,heading_deg,dof,amplitude,unit

Each run will contain every requested frequency/heading pair for sway and heave, with nonnegative magnitude and unit m/m. The manifest supplies run IDs. Headings use the canonical half-open revolution [0, 360) degrees; periodic duplicates are rejected, not normalized. Sample matching uses exact decimal numeric identity, without interpolation or nearest-neighbor tolerances. Exports will preserve the manifest sampling values when native serialization rounds labels; that mapping requires reviewed extraction evidence. Missing, additional, duplicate, malformed and non-finite samples are errors. Values that overflow or underflow the report's floating-point representation are also rejected.

numerical_screen reports PASS only when all applicable numerical checks pass, including diagnostic removal-off cases. A failed diagnostic case may coexist with a corrected candidate that passes every applicable check; the per-sample report is the evidence for that distinction. Exit status is nonzero for a failed numerical screen or invalid input. An exit status of zero is never engineering acceptance. qualification and native_execution remain NOT_EVALUATED even for numerically passing or synthetic exports.

Acceptance and remaining work

Closure will require the manager to identify the governing corrected candidate, reproduce the original anomaly, and demonstrate the applicable heave band, mesh agreement and independent solver comparison with native evidence. Hydrostatic equilibrium, mass/inertia consistency, geometry equivalence, normals, waterline, irregular-frequency treatment, nonnegative radiation damping and added-mass checks will also require review under the repository AQG gates. The observed finite-frequency peak may have a physical, loading or numerical cause; this preparation does not diagnose it. Additional frequency refinement and phase/excitation review may be needed to distinguish those causes.

The original raw results and low-frequency flags will remain retained until qualification. Dataset republication and downstream flag propagation are separate follow-ups; this tool neither publishes data nor automatically promotes flagged rows. Public commits will contain only generic code and instructions. Native geometry, run logs and results will remain in their authorized owning storage with a retained manifest and replica.
