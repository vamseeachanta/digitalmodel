Shear7 mode finder

The parser reads existing Shear7 text outputs and exports excited-mode lists and a cross-tabulation of power-in nodes. It ports the first-region behavior of ModesFind.m and the directory batch role of FindModes.m (2009). No solver is started or imported. Input counts and node identifiers are preserved.

The input directory is scanned non-recursively for the literal suffix (default .out). File names are sorted lexically. The command writes ExcitedModes and PowerInRegion files with the selected extension. It does not change the working directory. Existing exports are replaced; inputs cannot also be export destinations, including symbolic links and hard links. A failed parse returns exit status 2 before exports are opened. A missing directory or empty match set is an error.

Method and source

The format basis is ModesFind.m (2009), its above-cutoff sentinel, modal excitation-region table, lift-coefficient table and NodeList assignment/output loops. FindModes.m (2009) supplies the directory-processing role; the Python CLI uses explicit arguments rather than a separate FindModes.txt settings file. The restricted source and reference results are inspected read-only and are not distributed here. The maintained package location is digitalmodel.subsea.viv_tools.shear7_mode_finder; the obsolete hyphenated source location in the original issue is not recreated.

  1. Read the declared count after the number of modes above cutoff is: and then read that many integer mode rows after These modes are:. The potentially-excited modal-frequency table is not this list.
  2. Find Mode No. No. of Nodes Length Ratio, allowing variable whitespace and capitalization, and read the first summary row.
  3. Read the declared number of rows below node number Cl Fn/Fvo. Keep the node identifiers, checking that the coefficient columns contain finite numbers. A present mode number: label shall match the summary row.
  4. For each file column, place its first node in row one, its second node in row two, and continue. Shorter lists receive zero padding.

The zero padding is the MATLAB NodeList convention, not a physical zero or a node identifier. Node IDs shall be positive and unique. The row index denotes position in each list, not a common physical node across files. Only the first mode's region is represented, even when multiple excited modes are listed. JSON and YAML expose power_in_modes to make that selection explicit. The CSV matrix retains the legacy file-column arrangement. This is parsing and indexing; no physical equation, coefficient or acceptance limit is introduced.

Worked example

The committed inputs case_a.txt and case_b.txt are synthetic format demonstrations. Every count, identifier, length ratio and coefficient in them is invented; none is qualified engineering input.

Case A declares two modes, 3 and 7. Its first region belongs to mode 3 and lists nodes 4, 8 and 9. Mode 7 lists nodes 20 and 21, which are excluded by the legacy first-region rule. Case B declares mode 5 with one listed node, 2.

Independent hand calculation: align the two lists by ordinal position. Row one is [4, 2]. Row two is [8, 0] because B has no second entry. Row three is [9, 0] because B has no third entry. The excited-mode output is [[3, 7], [5]].

{

  "power_in_modes": [3, 5],
  "node_list": [[4, 2], [8, 0], [9, 0]]
}

The same example is asserted in test_worked_example. Additional tests cover export readback in CSV, JSON and YAML; missing and truncated sections; malformed and duplicate identifiers; Fortran D exponents; explicit zero modes; repeated calls; deterministic file ordering; and input protection.

Archive comparison and limitations

Read-only comparison against saved ExcitedModes.dat and PowerInRegion.dat outputs matches all 37 excited-mode lists and the full 1,182-row by 37-column NodeList matrix (43,734 entries). This establishes parity for that inspected archive set, not every Shear7 version. Restricted file names, raw files and case-specific results are excluded from this public artifact.

A declared zero-mode count gives an empty result. A first region with a zero node count gives no node rows. Missing markers and malformed or truncated counted rows raise errors; they do not silently become a zero-mode result. Only the declared number of rows is consumed, as in the original algorithm.

Other output dialects, non-UTF-8 encodings and all-mode regional extraction are not established by this port. YAML export requires PyYAML, already a package dependency. The original settings-file syntax and byte-for-byte DAT formatting are not supported; CSV, JSON and YAML preserve the parsed content. No fatigue, excitation or design acceptance conclusion follows from the exported IDs.
