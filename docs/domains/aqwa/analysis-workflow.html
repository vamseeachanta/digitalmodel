AQWA analysis workflow

Revision 1 · 13 September 2026 · Operational definition · AQWA diffraction/radiation baseline

Review coverage is recorded with the published workflow revision. This document defines a workflow; it does not approve a physical basis, implementation or licensed execution. Missing evidence will prevent the affected stage from passing.

This mapping implements common workflow Revision 1 and analysis criteria Revision 1. Use the common engineering workflow and analysis, parametric and lookup criteria. The issue owner will record scope approval and reciprocal provider review separately from solver status.

Stage and entryActions and retained outputExit criterion
Basis
Issue, intended use, source geometry and physical inputs.		Reconcile units, wetted geometry, normals, symmetry, draft, mass, COG, inertia, reference point, water density/depth, frequency units and heading conventions. Calculate displacement and restoring assumptions. Save a versioned basis, unresolved assumptions and source digests.Inputs describe one physically consistent case. Comparators, applicability and tolerances are fixed before results. Unresolved equilibrium or coordinate contradictions block analysis acceptance.
Offline preflight
Accepted basis and bounded preparation authority.		Validate the canonical specification and mesh. Generate into a fresh directory; inspect actual DAT triangle/quad cards, normals, ordering and serialization. Save specification, mesh, DAT and a generation receipt with source revision and hashes.Written bytes pass independent geometry/card checks and relevant offline regressions. Preparation output is not native evidence.
Parametric definition
Frozen baseline and question.		Prespecify physical parameter changes separately from mesh/frequency refinement, dependencies, case IDs, stopping rules and run budget. Preserve mass/draft consistency. Save the matrix and each case's basis relationship.Every case has defined inputs and acceptance rules. Case generation may precede execution; accepted engineering trends require an accepted baseline and verified case results.
Gated native execution
Explicit scope approval, reviewed artifacts and passing preflight.		Verify the designated host, executable/version, license availability and exclusive execution controls. Freeze invocation, timeout, attempt ledger and source-bound inputs; use a fresh output directory. Retain native logs and result files, including failed attempts.Actual native completion, process exit and license release are evidenced. Timeout, missing executable, dry-run fallback or skipped validation cannot count as a successful analysis.
Verification
Complete native bundle and frozen criteria.		Extract coefficients/RAOs; compare source listings with parsed values. Check units, phase, reference transformations, frequency/heading/DOF coverage, hydrostatics, symmetry, reciprocity and applicable energy/asymptotic checks. Assess refinement separately from solver-to-solver agreement.Each required criterion has evidence and a disposition. Missing values differ from physical zeros; a refused comparison remains refused. Extractor success alone cannot establish engineering acceptance.
Saved results
Verified or explicitly failed case.		Retain exact raw inputs/outputs, extraction revision, conventions, profile, criteria, review and SHA-256 manifest with the engineering owner. Read back saved artifacts; distinguish private originals, sanitized derivatives and backup status.Source-to-result relationships and intended-use readiness are traceable. Synthetic fixtures and failed cases remain labelled; existing evidence is not overwritten.
Lookup and report
Indexed, source-bound accepted cases.		Reuse existing catalogs; key lookup by geometry, loading state, environment, conventions, solver/profile and grid. Report governing checks, coverage and limitations. Interpolation requires its own declared domain and verification.No extrapolated, stale, synthetic or unmatched case silently becomes accepted input. Reporting and publication authority remain separate.
Table 1. Stage entry, evidence output and exit requirements. Workflow requirements are not a claim that all controls are automated.

Common-stage correspondence: AQWA Basis implements common stage 1; Parametric definition implements stage 2; Offline preflight implements stage 3; Gated native execution implements stage 4; Verification implements stage 5; Saved results implements stage 6; Lookup and report implements stage 7. A baseline-only preflight may precede study design; each generated study case must repeat the applicable preflight before execution. For common stage 8, the engineering owner reviews source/criteria/findings changes, determines consumer impact and withdraws affected responses until requalification.

Verified repository interfaces

Inspection baseline: commit ec54195ba74900806f684011d43e4fe1de589b32, 13 September 2026. Native execution uses explicit configuration and preparation followed by execution, but execute itself can also return dry-run if the executable is absent. Require an explicit non-dry-run receipt with actual executable, exit status and retained native evidence; method selection alone does not remove the fallback.

DiffractionSpec in input_schemas.py supplies the model. AQWABackend.generate_single(spec, output_dir, spec_dir=None) writes DAT input. AQWARunner.prepare / execute / run separate preparation from execution; run invokes both and may fall back to dry-run. AQWAResultExtractor.extract(run_result) returns extraction status. These interfaces do not themselves authenticate approval, guarantee exclusive license control or establish the full acceptance contract.

First-case hold point

Unit-box benchmark is the candidate, not a qualified baseline. Its historical results are synthetic. Its issue basis uses a body mass of 500 kg and water depth of 50 m; the canonical example uses a body mass of 1025 kg and water depth of 100 m. The 1025 kg value is the vessel.inertia.mass field in examples/hydrodynamics/diffraction/unit_box_rao/spec.yml; that file separately declares environment.water_density as 1025 kg/m³. The 500 kg value is the body-mass parameter in issue 141. These masses are not water densities; mesh coordinates and COG/symmetry also require reconciliation. The first action is an offline basis assessment. No physical inputs are selected here. The preserved AQWA-to-structural workflow is a separate scope.
