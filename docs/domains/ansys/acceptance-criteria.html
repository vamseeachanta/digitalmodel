ANSYS response acceptance criteria

The offline evidence adapter evaluates equilibrium, convergence and strength separately from native execution and independent reference agreement. Engineering lookup requires explicit intended-use requirements in the digest-bound verification register. Existing diagnostic packages remain diagnostic; import alone establishes no engineering qualification.

Method and evidence contract

Source: ENG-ANALYSIS-CRITERIA, Revision 1 (2026), AC-01, AC-07 and AC-08; ANSYS analysis workflow, Revision 1 (2026), Extract and verify. No engineering constants or default acceptance limits are supplied. The only numerical operations are exact decimal ordering: observed ≤ limit (le) or observed ≥ limit (ge), with equality passing. Values and limits share the declared unit; no conversion or interpolation is performed.

Each verification entry adds acceptance_criteria, a mapping with optional equilibrium, convergence and strength records. Each supplied record requires criterion_id, quantity, unit, observed, limit, comparator, source and nonempty evidence. Source text identifies the document, edition and clause/table or independently recorded derivation; evidence references use the existing logical ID and SHA-256 resolver protocol. Their bytes are checked on every evaluation. The independent checker remains responsible for applicability and derivation of the observed quantity, limit and units; a digest is not evidence of competence or authority.

acceptance_requirements maps each permitted intended use to a nonempty list of required criteria. Equilibrium and convergence are always required. A strength decision additionally lists strength. A demand-only use may omit strength explicitly, retaining NOT_EVALUATED for capacity readiness. This policy is frozen with the verification register; an ordinary query cannot supply or override it. Strength observations, when supplied, must equal the queried response value, definition and unit. A strength criterion shall therefore use the same quantity as that response, rather than an unrelated utilization.

A missing record, observed value or limit yields NOT_EVALUATED; a valid comparison yields PASS or FAIL. Malformed records, unknown criterion names, nonfinite values, unsupported comparators and unavailable or changed evidence raise ValueError. Any required check other than PASS blocks engineering lookup. Independent comparison, rights, retained-native evidence, current publication authority, review findings and withdrawal checks remain required.

Worked offline example: comparison protocol

Inputs below are invented software-test values, not engineering data or design limits. Independent hand calculation: 12.5 is less than 13, so the supplied strength comparison passes; 12.5 exceeds 12, so changing the limit to 12 fails. Equilibrium and convergence are absent and remain NOT_EVALUATED. The result does not qualify any case. The source file is created only in a temporary directory configured through the launch environment.

from pathlib import Path
from tempfile import TemporaryDirectory
from digitalmodel.ansys.analysis_criteria import evaluate_criteria
from digitalmodel.ansys.analysis_records import digest_bytes

with TemporaryDirectory() as directory:
    basis = Path(directory) / "basis.txt"
    basis.write_text("Synthetic comparison example, revision 1: 12.5 < 13; 12.5 > 12.")
    strength = {
        "criterion_id": "synthetic-comparison", "quantity": "test scalar",
        "unit": "MPa", "observed": "12.5", "limit": "13", "comparator": "le",
        "source": "Synthetic comparison example, revision 1, independent ordering",
        "evidence": [{"id": "basis", "sha256": digest_bytes(basis.read_bytes())}],
    }
    result = evaluate_criteria({"strength": strength}, {"basis": basis})
    assert result == {"equilibrium": "NOT_EVALUATED",
                      "convergence": "NOT_EVALUATED", "strength": "PASS"}
    strength["limit"] = "12"
    assert evaluate_criteria({"strength": strength}, {"basis": basis})["strength"] == "FAIL"
    print(result)

Lookup and migration

lookup(...) returns acceptance_results only after the existing qualification gates and the required checks pass. This key preserves all three statuses, including unresolved capacity for a demand-only use. Diagnostic retrieval continues to return unqualified responses without requiring a register. Historical registers lacking the new requirements cannot qualify an engineering response; a new register digest and package revision bound to current authority are required. Merely adding passing labels is insufficient.

Tests cover exact boundaries, high-precision ordering, null versus zero, missing requirements, malformed sources, changed evidence, response binding and diagnostic preservation. Existing retained results are neither rewritten nor newly qualified. Native execution, new campaigns, physical validation, source authentication and automated determination of criterion applicability are outside this offline implementation.
