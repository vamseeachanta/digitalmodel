Abscissa policy numeric domains

Summary

AbscissaConfig validates each numeric field at construction, before checking custom justification. Invalid values raise a field-specific ValueError. Boolean thresholds are rejected even though Python treats booleans as integers. Existing numeric defaults remain unchanged.

Domains and their basis

The domain definitions follow the interval operations in benchmark_abscissa.py: _validated_abscissa, build_evaluation_grid, _check_source_gap and assess_sampling.

FieldDomainDerivation
min_samplesInteger at least 2 Two endpoints are required to define an interval; fractional counts and floating-point counts are excluded.
min_coverageNone or finite real in (0, 1]Coverage = shared span / smaller source span. Positive overlap cannot exceed the smaller span. None requires one complete source domain within the other.
max_relative_gapFinite real greater than 0 Relative gap = positive frequency difference / positive lower frequency. No finite upper cap is imposed by this domain.

Table 2. Numeric domains; booleans are excluded from every field.

The Python 3 Library Reference, Built-in Types, Boolean Type documents boolean inheritance from integers. Explicit rejection prevents a configuration flag from silently becoming a numeric threshold. Supported NumPy real and integer scalar values retain their types; strings and arrays are not coerced.

Worked example: inputs, method and answer

The example is synthetic. The coarse frequencies are [1, 1.25, 1.5, 1.75, 2] rad/s; the dense frequencies are 1 + k/8 rad/s for integer k from 0 through 8. The declared policy is min_samples=2, min_coverage=1.0, max_relative_gap=0.25, with custom justification recording these illustrative inputs.

Hand calculation: coverage = (2 − 1)/(2 − 1) = 1. The largest coarse relative gap is (1.25 − 1)/1 = 0.25; the largest dense gap is (1.125 − 1)/1 = 0.125. Both are at or below the declared 0.25 bound. The method selects the coarser grid in the shared interval. The answer is [1, 1.25, 1.5, 1.75, 2] rad/s.

Run the example script from the repository root:

PYTHONPATH=src python examples/hydrodynamics/diffraction/abscissa_policy.py

The script also demonstrates rejection of True for each real-valued threshold. Integer 1 remains a valid threshold. Domain rejection occurs before matrix alignment can consume a malformed policy.

Checks and limits

Regression tests exercise boolean rejection with and without custom justification, nonfinite and unsupported values, supported numeric scalars, caller rejection and the independently calculated example. These checks establish configuration validation. They do not establish physical adequacy of a sampling policy; no solver execution or tolerance change is involved. Other nested policy classes remain outside this change.
