Diffraction G4 evidence record

The offline evidence API separates a mesh packaging screen from the complete G4 record. A packaging PASS or WARNING supplies no G4 row automatically. The record contains every required row, including missing evidence and unknown applicability. Engineering acceptance is not established by this implementation.

Source and qualification

The source is pinned by SHA-256: 0b997e73ea95ecdc41457535561687396693615680bdeb5b61e5eda48d655671. The original AQG document and the licensed panel-size clause are not qualified. The internal transcription is not a citation to a checked licensed clause. Source absence or a digest mismatch raises an error at calculation time. Source qualification cannot be enabled by a caller flag.

Inputs, method and answer

The runnable example is examples/aqg/diffraction_g4.py. Its quantities are synthetic arithmetic examples, with SI units declared explicitly. They are not an engineering design basis or solver results.

The legacy equilibrium screen normalizes against displaced mass and therefore rejects this example at the same supplied tolerance: 1/99 exceeds 1.0 %. Its documented behavior is preserved. The new API makes the G4 input-mass normalization explicit. The legacy aspect and uniformity defaults, mean-normal screen, packaging warning policy and comparison tiers are also preserved.

Evidence and status contract

digitalmodel.aqg.diffraction.assess consumes criterion-specific Check records. The fixed inventory rejects duplicate and unknown IDs; generic mesh dictionaries are rejected. Each row includes applicability, fixed criterion, units, observations, evidence references and digests, and a reason. Input quantities are finite and domain checked; no unit conversion is performed. Inclusive comparisons use exact rational arithmetic on the canonical decimal representations of validated float inputs, without an added engineering tolerance. Serialized observations remain floats; pass/fail decisions use the unrounded rational values. Each caller shall reconcile input units, coordinate frames, load case and input/result identity.

status is FAIL when a row fails and otherwise NOT_RUN while source qualification is missing. record_status describes documentary completeness only: FAIL takes precedence, then NOT_RUN, then PASS. PASS in record_status is not engineering acceptance. An artifact digest proves byte identity, not correctness, source rights or review authority. The serialized source sidecar records the source revision, section, digest and qualification limitation.

reviewed_check records an external criterion-specific review with supporting artifacts, a reviewer role and a basis. Computed rows are reserved for their calculator APIs and cannot be replaced by generic reviews; assessment construction derives status from the complete fixed inventory. It does not authenticate that review or replace independent calculations. A manual exclusion is supported only for G4.1b with explicit equilibrium_mode="free_floating" and its supporting evidence. G4.7b is excluded only by a computed below-trigger comparison. Other uncertain applicability remains NOT_RUN. Native and independent hydrostatics, CoB/CoG/GM, waterline/draft, outward orientation, views and response checks require these external reviews; their absence remains visible.

Implemented numeric comparisons

check_mass uses input mass as the denominator. check_panels evaluates every supplied longest-edge/shortest-edge ratio; the caller supplies the complete panel inventory and waterline classification. The waterline exception requires second-order work and a nonempty quality note. Wavelength is a required independently derived input; uniform element size does not establish it. check_resources requires a program/version-specific panel limit and source, plus a native memory estimate and the available-memory snapshot at the time of measurement. No universal panel or memory limit is assumed.

Irregular-frequency evidence

check_irregular_frequencies requires the first irregular frequency in rad/s and its independent calculation artifact. No frequency estimate is guessed. A complete BodySurface inventory declares each body's treatment. At the lid trigger every body needs an InteriorLid with distinct panel IDs, artifact and reviewer role. Every body declaring the control-surface method also requires resolvable control-surface evidence, including below the lid trigger. Unknown body coverage or missing applicable surfaces remains NOT_RUN. Below the first irregular frequency, paired removal is NOT_APPLICABLE; at or above it the compared canonical program pair and native proofs are required. Only the canonical identifiers aqwa and orcawave are currently supported, so alternative aliases cannot count as distinct programs.

NativeRemoval contains exact native input bytes, program version, an active setting line, its externally reviewed enabled/disabled/unknown interpretation, a reviewer role, and native-result readback linking the result to the input digest. The complete setting line must occur in the input and cannot be a comment. Unknown interpretation, missing pair, missing result or missing linkage remains NOT_RUN; disabled removal fails; an input/result digest mismatch is rejected. The emitted record retains setting-line locators and digests. This is an evidence receipt, not a general native syntax parser. Active sections, includes, override semantics and successful removal remain matters for native readback and review. Response spikes are checked separately under G4.8e.

Verification and limitations

The regression tests exercise boundary arithmetic, invalid inputs, exclusions, missing evidence, native-result linkage, aggregation, source-digest failure, JSON readback and the runnable example. A fresh Python subprocess checks that the offline API loads neither the hydrodynamics package nor a licensed interface. No solver is imported or executed. A complete receipt set still emits NOT_RUN as engineering status because original-source qualification is absent.

The new API is deliberately separate from the eager legacy diffraction initializer. It does not change legacy callers or wire acceptance into packaging. Automatic native parsers, original-source qualification, solver execution and end-to-end report integration remain follow-up work. The inventory is not proof that the external checks were performed.
