Reproducible capability dataset exports

The exporter projects committed explorer sidecars into grouped Hugging Face configs. Seven further configs cover 251 observations across casing design, analytical sloshing and synthetic dynacard troubleshooting. Export fidelity is checked independently of engineering qualification, which remains NOT_EVALUATED. No dataset is uploaded and no explorer is switched to an unverified remote endpoint.

Method and source basis

scripts/hf/build_capability_datasets.py renames leaf fields and retains every facet as a column. Values are copied without recalculation or additional rounding. The bundle command reads each distinct source once, shares that snapshot across its configs, and normalizes CRLF line endings to LF: the retained JSON, recorded source digest, and projected rows share that snapshot. Generator, projection, and packager digests also use LF-normalized text, so text checkout conversion does not change their identities. SHA-256 digests identify the retained source and output bytes. The manifest records the build system and architecture; full byte verification includes that platform metadata.

For mixed analytical/CFD sloshing sidecars, only meta and shapes are selected before checking or projecting. Unselected CFD, forced-response, SDOF and research sections are never staged. The manifest's source_sha256 identifies the complete original LF-normalized input; retained_source_sha256 identifies the retained bytes, and retained_source_sections declares the selection (null means the complete source is retained). Selecting sections does not alter any observation value.

The bundle contains a dataset card, manifest.json, <config>/train.jsonl, and sources/<config>.json. Config names and column names form the website registry contract. Source metadata is retained, null cells remain null, and missing columns are padded with null across rows. Empty tables, nested cells, non-finite observations, and private filesystem/contact locators are rejected before a destination is created. Existing destinations are preserved.

The layout follows the public Hugging Face manual configuration guide (configs, config_name, data_files, split, path) and JSON loading guide (one observation per line). JSON front matter uses the compatibility described by YAML 1.2.2 (2021), section 1.2, YAML History. The website's docs/capabilities-registry.md defines downstream config and highlight-column validation. No new engineering equation, coefficient, or acceptance limit is introduced by this export.

Table 3. Units follow the generators' input DTOs and output fields. The suffix knots denotes speed in knots; kn denotes force in kN. MUSD denotes millions of USD; bopd denotes oil barrels per day; ppg denotes pounds per gallon (US). Froude number, reduced velocity, and safety factor are dimensionless.

Casing load_unit applies to both rating and max_load: tension uses lbf, burst/collapse/triaxial use psi. These units follow the four check functions in src/digitalmodel/well/tubulars/casing_design.py. Design factors are dimensionless. Unequal profile lengths and unknown check units fail before bundle creation; failed source checks remain false.

The sloshing master curve always uses depth divided by characteristic length: length for rectangles, diameter for cylinders and width for ovals. The dimensional lookup instead uses depth/height for ovals. This distinction follows build_sloshing_explorer.py::_norm_curve and _lookup_table; the source oval curve label alone does not describe its coordinate. Each lookup row carries its depth-ratio definition and span basis. CFD and damping are excluded. Dynacard loads use lbf and areas use inch·lbf; confidence and probability are dimensionless source outputs. Candidate rank is the one-based source-list position, so ranking survives table sorting. No probability is recalibrated.

Worked example: IPR export

Input: the committed IPR sidecar. Its generator declares three reservoir pressures, ten productivity indices, and eleven flowing-pressure points. Hand count: 3 × 10 × 11 = 330 observations. The first source point has reservoir pressure 2000 psi, productivity index 0.5 bopd/psi, flowing pressure 2000 psi, flow rate 0 bopd, and maximum flow 555.6 bopd. These are demonstration-source values, not a published validation example.

The example uses the repository's MIT license as an explicit input. A publication operator will confirm the license for the selected payload. Set OUTPUT_DIR to a new external scratch directory before running:

python -m scripts.hf.capability_bundle \
  --dataset digitalmodel-artificial-lift --license mit --out "$OUTPUT_DIR"
python -m scripts.hf.capability_bundle \
  --dataset digitalmodel-artificial-lift --license mit --out "$OUTPUT_DIR" --verify

Answer: ipr/train.jsonl contains 330 rows. The first row retains those five source values. The dataset card declares config ipr, split train, and path ipr/train.jsonl. Verification reconstructs the expected bundle and compares every file and byte; changed source, changed rows, missing files, and extra files cause failure without modifying the bundle.

Worked example: casing export

Input: the committed casing sidecar. Method: transpose the pressure arrays by depth, copy each product's geometry and ratings, and unpivot each product's checks with an explicit load unit. No pressure, rating or design factor is recalculated. Source basis: build_casing_design_explorer.py::build_profiles and build_study.

Independent hand counts from those generator declarations: 61 depths + 8 products + (8 products × 4 check modes) = 101 rows across the three new configs. The existing pore-pressure config remains present in the group. The first profile row copies depth 0 ft, tubing-leak internal pressure 7300 psi, frac internal pressure 9000 psi, and external pressure 0 psi from the source arrays. The corresponding net pressures retain 7300 psi and 9000 psi.

python -m scripts.hf.capability_bundle \
  --dataset digitalmodel-well --license mit --out "$OUTPUT_DIR"
python -m scripts.hf.capability_bundle \
  --dataset digitalmodel-well --license mit --out "$OUTPUT_DIR" --verify

Answer: casing_profiles/train.jsonl has 61 rows, casing_products/train.jsonl has 8, and casing_checks/train.jsonl has 32. Their configs retain the existing train split convention. Use a distinct new output directory for each group. The same commands with digitalmodel-hydro produce 90 analytical curve rows and 28 lookup rows alongside the existing hydro configs. With digitalmodel-artificial-lift they produce 8 synthetic-case rows and 24 differential rows alongside IPR. Tests document independent hand projections using arbitrary inputs; these are transport checks, not engineering validation.

Limits and remaining work

All new configs contain synthetic screening observations. Original source rounding and statuses are retained; model assumptions are not independently requalified. The field-economics sidecar summary and generator reservoir input differ, so that config carries an explicit source-consistency limitation. Missing engineering evidence does not become valid input merely because export succeeds.

Casing ratings are a selected study, not a complete product catalog. Sloshing curves use linear theory and equivalent-rectangle approximations where the source generator declares them; no CFD accuracy or design-load claim is made. Dynacard exports cover only the synthetic case summaries and candidates in the sidecar, not the field-card library, controller settings, intervention advice or card coordinates. Classifier confidence does not establish field diagnostic accuracy.

The integrity dataset requires its full generated tension/moment input and fails before output if it is unavailable. No existing config is silently dropped. Riser release publication remains separately owned. Remaining capabilities require explicit projections or generators; generic nested-JSON discovery is not used.

Under the capability dataset issue, the remaining steps are public publication with a confirmed license and suppressed deploy hooks, readback of live configs and revisions, website registry validation, and conversion of explorer generators to fetch those verified revisions. The capability landing page and API stubs are not converted here. Independent review remains pending before merge.
