Reproducible capability dataset exports

The exporter projects committed explorer sidecars into grouped Hugging Face configs. Six additional configs cover 658 observations. Export fidelity is checked independently of engineering qualification, which remains NOT_EVALUATED. No dataset is uploaded and no explorer is switched to an unverified remote endpoint.

Method and source basis

scripts/hf/build_capability_datasets.py renames leaf fields and retains every facet as a column. Values are copied without recalculation or additional rounding. The bundle command reads each source once and normalizes CRLF line endings to LF: the retained JSON, recorded source digest, and projected rows share that snapshot. Generator, projection, and packager digests also use LF-normalized text, so text checkout conversion does not change their identities. SHA-256 digests identify the retained source and output bytes. The manifest records the build system and architecture; full byte verification includes that platform metadata.

The bundle contains a dataset card, manifest.json, <config>/train.jsonl, and sources/<config>.json. Config names and column names form the website registry contract. Source metadata is retained, null cells remain null, and missing columns are padded with null across rows. Empty tables, nested cells, non-finite observations, and private filesystem/contact locators are rejected before a destination is created. Existing destinations are preserved.

The layout follows the public Hugging Face manual configuration guide (configs, config_name, data_files, split, path) and JSON loading guide (one observation per line). JSON front matter uses the compatibility described by YAML 1.2.2 (2021), section 1.2, YAML History. The website's docs/capabilities-registry.md defines downstream config and highlight-column validation. No new engineering equation, coefficient, or acceptance limit is introduced by this export.

Worked example: IPR export

Input: the committed IPR sidecar. Its generator declares three reservoir pressures, ten productivity indices, and eleven flowing-pressure points. Hand count: 3 × 10 × 11 = 330 observations. The first source point has reservoir pressure 2000 psi, productivity index 0.5 bopd/psi, flowing pressure 2000 psi, flow rate 0 bopd, and maximum flow 555.6 bopd. These are demonstration-source values, not a published validation example.

The example uses the repository's MIT license as an explicit input. A publication operator will confirm the license for the selected payload. Set OUTPUT_DIR to a new external scratch directory before running:

python -m scripts.hf.capability_bundle \
  --dataset digitalmodel-artificial-lift --license mit --out "$OUTPUT_DIR"
python -m scripts.hf.capability_bundle \
  --dataset digitalmodel-artificial-lift --license mit --out "$OUTPUT_DIR" --verify

Answer: ipr/train.jsonl contains 330 rows. The first row retains those five source values. The dataset card declares config ipr, split train, and path ipr/train.jsonl. Verification reconstructs the expected bundle and compares every file and byte; changed source, changed rows, missing files, and extra files cause failure without modifying the bundle.

Limits and remaining work

All new configs contain synthetic screening observations. Original source rounding and statuses are retained; model assumptions are not independently requalified. The field-economics sidecar summary and generator reservoir input differ, so that config carries an explicit source-consistency limitation. Missing engineering evidence does not become valid input merely because export succeeds.

The integrity dataset requires its full generated tension/moment input and fails before output if it is unavailable. No existing config is silently dropped. Riser release publication remains separately owned. Remaining capabilities require explicit projections or generators; generic nested-JSON discovery is not used.

Under the capability dataset issue, the remaining steps are public publication with a confirmed license and suppressed deploy hooks, readback of live configs and revisions, website registry validation, and conversion of explorer generators to fetch those verified revisions. The capability landing page and API stubs are not converted here. Independent review remains pending before merge.
