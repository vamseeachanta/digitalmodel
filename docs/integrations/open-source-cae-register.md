# Open-source CAE register

Register of open-source simulation tools for use in offshore engineering, and the status of each in digitalmodel as of 5 Nov 2026. Started 5 Nov 2026 from a public LinkedIn post listing open alternatives to commercial closed-source simulation software, and from the tools named in its comments.

Source: [LinkedIn post, "Looking for alternatives to commercial closed-source simulation software"](https://www.linkedin.com/feed/update/urn:li:share:7523714627994681344/)

Licences were each checked on 5 Nov 2026 against the project's own repository or site (source linked in each row); check the project again before redistributing. Test counts are `def test_` function definitions under the named test directories or files on `main` at 5 Nov 2026. "none" means no module, test or documented workflow is present in digitalmodel.

## Adoption of open-source solvers

An open solver is adopted only when it reproduces a trusted number, not because it is free. The post that started this register makes the same point: AI can help with scripting and post-processing, but verification, validation and engineering judgement stay with the engineer. In practice:

- **Benchmark first.** Where a commercial or analytical reference is available, an open tool is compared against it before use for engineering work. The structural comparison framework is tracked in #1703 and epic #1846 (adopt only when the open solver lands on the same number as the licensed one).
- **Pinned, repeatable runs.** `src/digitalmodel/solvers/benchmark` (88 tests in `tests/solvers/benchmark`) is a timing and fingerprint baseline pack for the solver stack (#2300). It shows a machine runs a fixed workload the same way; it is not itself a validation against commercial results.
- **Reference cases in the repo.** `docs/benchmarks/` holds fixtures such as the closed-form catenary hand calculation (`catenary_closed_form`, 5 % tension band, no program results included), the diffraction `unit_box` reports, `near-wall-acceptance` and the sloshing analytical fixture. A result is stated only where a case file backs it.
- **Fail closed.** Solver wrappers check input compatibility (for example the CalculiX writer work in #2080) and record solver evidence rather than assuming success.
- **Engineer signs off.** Scripts and post-processing may be automated; the assumptions, validity range and conclusion are reviewed by a person.
