Section properties API

digitalmodel.sections.compute_section_properties(section_type, dimensions) returns the existing SectionProperties dataclass. Five selectors dispatch to the existing wrappers; direct wrapper calls and serialization keys remain supported.

Inputs

dimensions is a mapping copied before dispatch. Lengths are finite plain numbers in mm; mesh_size is target element area in mm². Point counts n/n_r, mesh defaults and optional string label match the direct wrappers. Unit-bearing values are rejected without conversion.

Unsupported selectors raise ValueError. Non-mappings, missing or extra keys, invalid value types and non-finite numbers raise TypeError before meshing. Physical geometry constraints and analysis errors remain with sectionproperties.

Outputs and independent check

area is in mm²; ixx, iyy and j in mm⁴; cw in mm⁶; rx/ry in mm. All four moduli are in mm³. Plastic zx/zy map to get_s()[0]/get_s()[1] (AISC Z). Elastic sx/sy map to get_z()[0]/get_z()[2] (AISC S): these are positive-fibre values, not necessarily the minimum-fibre values for asymmetric axes. Inertias and moduli use centroidal x/y axes, not principal axes.

For a synthetic rectangle of width b = 20 mm and height h = 40 mm, area integrals give Sx = b h² / 6 = 5333.3 mm³ and Sy = h b² / 6 = 2666.7 mm³; first moments of the yielded halves give Zx = b h² / 4 = 8000.0 mm³ and Zy = h b² / 4 = 4000.0 mm³. The regression analyzes this rectangle through the internal helper with the integration suite's 1.0 % numerical allowance; the rectangle is not a public dispatch selector. This allowance is not a design acceptance limit.

Remaining scope

Pint conversion, tee/custom polygon dispatch and a production AISC catalog bridge remain later work under issue 1695. The corrected Z/S values and populated sy change numerical output; consumers relying on the earlier labels require review. The API computes properties without structural capacity checks.
