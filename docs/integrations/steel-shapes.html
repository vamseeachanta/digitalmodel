AISC nominal section lookup

The packaged lookup returns a sectionproperties Geometry for a limited, cited sample. Full W-shape coverage depends on the user obtaining and importing the publisher workbook. Issue 1694 remains subject to review and original-manual validation.

from digitalmodel.steel_shapes import get_section, get_section_data, list_sections

geometry = get_section("W14x90")       # mm; equivalent alias: W360x134
inches = get_section("W360x134", unit="imperial")
reference = get_section_data("W14x90") # inches and square inches, with source cells
available = list_sections("W")

Names ignore case and whitespace and accept the multiplication sign in place of x. Both EDI and manual labels are stored explicitly. Other fraction, decimal, punctuation or schedule spellings are accepted only when present as aliases; the lookup does not infer metric names by arithmetic. Unknown names raise a KeyError; invalid names, units and catalogue values raise clear errors.

Some full-catalogue Pipe labels collide across naming systems: the same text can denote an imperial nominal diameter or a metric nominal diameter. Ambiguous names raise a KeyError. Select name_system="imperial" or name_system="metric" explicitly; this selects the name interpretation, while unit still controls the output coordinates.

Output coordinates default to mm independently of the designation language. Raw metadata retains source inch dimensions and square-inch areas. Metric geometry uses the inch conversion already present in the existing integration utility; rounded metric dimension columns are not substituted for imperial source figures.

The model does not infer material or capacity. Agreement with catalogue area within a corner-envelope and discretisation allowance does not establish the exact rolled outline. Source-byte equivalence with the publisher and comparison against original Manual pages are unestablished: the research sample was checked against a publicly accessible electronic workbook copy. Engineering use requires obtaining the governing source and verifying these assumptions for the selected section.

Local full catalogue

Review the publisher terms and obtain the current XLSX link from the AISC download page. No bulk redistribution permission is asserted. From the repository root, either fetch the publisher URL or import an already obtained workbook:

PYTHONPATH=src python scripts/integrations/fetch_steel_shapes.py --url PUBLISHER_XLSX_URL
# Alternative when the publisher download requires browser interaction:
PYTHONPATH=src python scripts/integrations/fetch_steel_shapes.py --workbook source.xlsx

# Explicit selection prevents a missing full catalogue from silently using samples:
geometry = get_section("W14x90", catalog_path="data/steel_shapes_local/catalog.json")

The fetch utility is never called by tests. It accepts publisher HTTPS URLs, stops on access failures, refuses existing destinations, retains the raw workbook, records its SHA-256 digest and source cells, and verifies saved files by readback. Both files remain under the git-ignored data/steel_shapes_local/ directory. If validation fails, the downloaded raw workbook is preserved and no usable full catalogue is reported. The original file is retained for diagnosis; an existing destination is never overwritten. File import records the publisher page as its source locator, so source authenticity remains a user verification obligation.

The converter accepts the named v16 worksheet, separates duplicate imperial and metric name headings, and includes W, S, HP, C, L, rectangular/round HSS and Pipe. Other families are excluded. Missing dimensions, impossible geometry and ambiguous aliases reject the import. Counts are reported from the actual imported rows; import success alone does not establish that a user workbook is complete.

Dependency and catalogue choice

sectionproperties and openpyxl are already declared project dependencies. Geometry construction imports sectionproperties lazily; metadata lookup remains available when that dependency is absent. No runtime dependency is added.

steelpy supplies imperial family CSV files and a convenient attribute-based lookup. Its Apache software licence metadata does not establish redistribution rights for the upstream AISC compilation. A thin in-repo JSON loader is used to retain source-cell provenance, explicit metric aliases and geometry assumptions without another dependency. The existing script-level W lookup and its catalogue remain separate compatibility surfaces.
