Steel section lookup and local catalogue import

The repository ships a synthetic sample for tests only. For real section properties, obtain the shapes database from the publisher yourself, under the publisher's terms, then run the importer on your local copy; nothing imported is committed. The publisher's site is the source for the database.

The eight hand-written profiles cover each supported geometry family. Every sample name and alias begins with SYN-, including the made-up metric aliases. Every sample row and the catalogue carry synthetic: true. Area is computed from the module's own geometry model, not a publisher table. The sample cannot supply real section properties. The all-shapes acceptance item in issue 1694 depends on the user's own full import.

from digitalmodel.steel_shapes import (
    clear_catalog_cache, get_section, get_section_data, list_sections,
)

geometry = get_section("SYN-W")                  # test geometry in mm; warns synthetic
inches = get_section("SYN-METRIC-W", unit="imperial")
reference = get_section_data("SYN-W")            # synthetic=True; inch dimensions
available = list_sections("W")
clear_catalog_cache()                            # next lookup will validate again

Names ignore case and whitespace and accept the multiplication sign in place of x. EDI and manual labels in imported catalogues are stored explicitly. Other fraction, decimal, punctuation or schedule spellings are accepted only when present as aliases; the lookup does not infer metric names by arithmetic. Unknown names raise KeyError; invalid names, units and catalogue values raise errors.

Some full-catalogue labels can collide across naming systems. Ambiguous names raise KeyError. Select name_system="imperial" or name_system="metric" explicitly; unit controls coordinates.

Coordinates default to mm. Raw metadata retains inch dimensions and square-inch areas. Metric geometry uses exactly 25.4 mm per inch; rounded metric dimension columns are not substituted for imperial source figures.

The model does not infer material or capacity. Synthetic area agreement verifies model self-consistency only. Original rolled-profile validation remains required for real sections, including the tapered-flange approximation.

Local full catalogue

Obtain the publisher's workbook yourself under its terms. From the repository root, import your local copy or supply a current publisher XLSX URL:

PYTHONPATH=src python scripts/integrations/fetch_steel_shapes.py --workbook source.xlsx
PYTHONPATH=src python scripts/integrations/fetch_steel_shapes.py --url PUBLISHER_XLSX_URL
# Restore all-or-nothing validation:
PYTHONPATH=src python scripts/integrations/fetch_steel_shapes.py --workbook source.xlsx --strict

# Use a designation from your imported catalogue:
geometry = get_section(user_designation, catalog_path="data/steel_shapes_local/catalog.json")

A local file import requires no network access. Fetch accepts publisher HTTPS URLs, stops on access failures, refuses an existing destination, retains the raw workbook and records its digest and source cells. Files are verified by readback. The utility refuses to write unless data/steel_shapes_local/ is ignored by Git. The workbook and derived catalogue remain there; nothing imported is committed.

The converter accepts the named v16 worksheet and separates duplicate imperial and metric headings. Each supported row is validated independently. Valid rows are imported; each rejection is reported to standard error with its worksheet row number, designation when readable and reason. The returned catalogue's import_report and CLI output report imported and rejected counts. Unsupported families are excluded and counted as skipped. Duplicate designations and alias collisions reject the affected row. The command succeeds when any supported row imports; --strict rejects the complete import if any supported row is invalid. Zero valid rows also fail. On failure the raw workbook is retained and no catalogue is emitted. An existing destination is never overwritten.

Imported catalogues are cached by resolved path, modification time in nanoseconds and size; a changed file is reloaded and validated. The packaged sample validates once until clear_catalog_cache() is called. Metadata returned to callers is an independent deep copy. Clear the cache explicitly after edits preserving both file metadata attributes.

Dependencies and limits

sectionproperties and openpyxl are existing dependencies. Geometry construction imports sectionproperties lazily; metadata lookup remains available when it is absent. No dependency is added. The importer has only been run on synthetic workbooks, never on the publisher's real file. Import success alone does not establish completeness or engineering qualification.
